## Worktrees — two, not five

An audit of the original 5-tree scheme measured ~1.2x parallelism at 5x cost. Two trees:

| Tree | Branch | Scope |
|---|---|---|
| **T1** `mens-hub` | `claude/qwen38-27b-hub-*` | Everything in this plan. Sequential. One PR stack. |
| **T2** `axis-leftovers` | `fix/axis-chat-honesty-leftovers` at `/Users/brbrainerd/dev/vox-main-merge` | Already exists, already has uncommitted work. Owns the Axis prerequisites in Phase 3. |

No integrator tree. Reasons the 5-tree scheme was dropped:

- Every fresh worktree must run `vox run scripts/gui-build.vox` **and** `pnpm install && pnpm build` in `crates/vox-gui/ui` before `vox ci pre-push --complete` passes (sidecar + `ui/dist` trap, AGENTS.md §Perennial Bug Patterns; three agents lost a day to this on 2026-09-05).
- The build broker caps machine-wide cargo at ~1/3 cores clamped to `[2,8]`. Five trees queue; they do not parallelize.
- W0 and W1 as originally scoped edited the **same files** (`vram_autodetect.rs`, `preset_schema.rs`, `spoke_base_resolver.rs`) and the **same yaml row table** (`gpu-specs.yaml` `train_bases`) — exactly the "move+reformat = silent duplicate definition" and "one-side-wins on a row table" merge classes AGENTS.md warns about.

**Integrator checklist before any merge:**

- [ ] `vox run scripts/fmt.vox -- --all` (the dirty-only default misses files another tree formatted).
- [ ] Verify each moved item is defined **exactly once**: `grep -c 'fn <name>' <file>` per moved symbol.
- [ ] Check **every** yaml row against the **merged** tree, not either side's intent.

## Global constraints

- Secrets: `vox_secrets::resolve_secret(SecretId::HuggingFaceToken)` for the HF download. Never `env.get`.
- Eval calls go through `vox_actor_runtime::llm`. The `llm_provider_call` detector is **Error** severity.
- Format per-crate (`cargo fmt -p <crate>`), never `cargo fmt --all`.
- Test-first: every task below names the failing test to write **before** the fix.
- Mutation-verify security/correctness guards: break, confirm red, restore — guarding with a presence check, since a concurrent `fmt` can revert your edit.

## Phase 1 — family routing (not a new predicate)

**Do not add `is_qwen38`.** Qwen3.8-27B **is** the Qwen3.5 architecture (`model_type: "qwen3_5"`). The bug is `is_qwen3()` over-matching the `"qwen3"` substring (`memory_budget.rs:296-299`), routing to the dense planner whose ladder is only 0.6/8/14/32 — so a 27B request silently **retreats** to Qwen3-14B. **A concurrent agent is fixing that routing; coordinate, do not duplicate.** This plan owns the downstream work.

- [ ] **P1.1 (FIRST) — Refit `RESIDENT_GIB_PER_B_PARAMS`.** `memory_budget.rs:27-45` is linear, fitted at 4B, and predicts **88.0 GiB** for a 27B QLoRA that physically needs ~24.4 GiB. Split into fixed + per-B terms and refit **before** adding any rung — otherwise every new threshold is calibrated on a broken curve.
  - Test: `qlora_27b_resident_estimate_within_10pct_of_measured` in `memory_budget.rs`.
- [ ] **P1.2 — `QwenSizeClass::Other` has an empty ladder-policy arm** at `preset_schema.rs:163`, so a 27B gets **no** rank/seq/batch clamps.
  - Test: `size_class_other_still_clamps_rank_seq_batch` in `preset_schema.rs`.
- [ ] **P1.3 — Layout dims fixture.** Replace the proposed `is_qwen38_not_classified_as_dense_qwen3` (deleted — `classify_hf_architecture` maps every qwen string to one variant by design, so that test is tautological or aimed at the wrong target) with a dims assertion against a real 3.8 `config.json` fixture.
  - Test: `qwen38_27b_config_yields_expected_layout_dims` in `crates/vox-hf-layout/src/lib.rs`.
- [ ] **P1.4 — `hub_base_parity` must be CROSS-ARTIFACT to fail first.** Reconcile `contracts/mens/training-presets.v1.yaml::default_base_model`, the rung `spoke_base_resolver` picks at measured memory, and a real 40-hex SHA.   - Test: `hub_base_parity` in `crates/vox-populi/src/mens/spoke_base_resolver.rs`.
  - Verify by **mutation**: break the pin, confirm red, restore — guard with a presence check (a concurrent `fmt` can revert your edit).
- [ ] **P1.5 — Add the 27B rung to `mens/config/gpu-specs.yaml` `train_bases`.** A rung is needed **only** to make 27B the auto-resolved choice on big boxes — `VOX_MENS_DEFAULT_MODEL` already selects any base end-to-end (`mens/mod.rs:78-83`, honored at `run_train.rs:101-133`, given precedence at `spoke_base_resolver.rs:183-190`).
