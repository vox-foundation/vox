## Batch procedure (referenced by 90-02..90-05)

Inputs: batch number `N`, its stems (MANIFEST fixture names without `.mmd`) and docs. Work dir
`/Users/brbrainerd/dev/vox-voxdiagram/target/vd-migration/bN/` (create it). Paths below are from the repo root.

- **P1 Import.** For each stem: `timeout 120 target/debug/vox diagram import
  crates/vox-diagram/tests/fixtures/corpus/<stem>.mmd -o target/vd-migration/bN/<stem>.vdg`. Exit 0 and no
  `unsupported:` line (else rule 6). Record any `dropped:` lines. `diff -q` the output against
  `crates/vox-diagram/tests/fixtures/corpus-roundtrip/<stem>.vdg`: identical (the importer is the one
  `corpus_roundtrip` pins). Optional id renames go into the scratch `.vdg`; then `timeout 120 target/debug/vox
  diagram check target/vd-migration/bN/<stem>.vdg` exits 0.
- **P2 Replace.** In the doc, replace the whole Mermaid fence (opening line, body, closing line) with a fence whose
  info string is exactly `vox-diagram` and whose body is the scratch `.vdg`, unindented, closing with three
  backticks. Use the Edit tool with the full old fence as the match. In a file with several fences, work from the
  last fence upwards so the recorded line numbers stay valid. Nothing else in the doc changes.
- **P3 Fidelity.** `FIDELITY_OUT=/Users/brbrainerd/dev/vox-voxdiagram/target/vd-migration/bN/fidelity.md timeout
  2400 cargo nextest run -p vox-diagram --retries 0 --run-ignored only -E 'binary(migration_fidelity)'`. Passes;
  every batch stem's row says `migrated`; the summary line matches the batch's expected counts. Copy the batch rows
  into the SUMMARY.
- **P4 Baseline and lint.** `timeout 1200 cargo run -q -p vox-doc-pipeline -- --tighten-mermaid-baseline` prints
  the expected `tightened:` line. Then the scoped lint over the batch's docs passes.
- **P5 Build and browser specs.** Stop any preview on port 4321. `timeout 1800 pnpm --dir docs-astro build >
  target/vd-migration/bN/build.log 2>&1`, then `timeout 1800 pnpm --dir docs-astro exec playwright test
  tests/vox-diagram.spec.ts tests/build-output/diagrams.spec.ts --reporter=line --output=test-results/vd-run`: all
  pass. A failing fit, contrast, id or title-strike check on a migrated page is a renderer defect (P7).
- **P6 Contact sheet and review.** `CONTACT_SHEET_STEMS=<stem,stem,..>
  CONTACT_SHEET_OUT=/Users/brbrainerd/dev/vox-voxdiagram/target/vd-migration/bN timeout 900 pnpm --dir docs-astro
  exec playwright test tests/migration-contact-sheet.spec.ts --reporter=line`. Open every `<stem>.png` and
  `<stem>-column.png` with the Read tool. For each fence record in the SUMMARY review table: what Mermaid showed,
  what VoxDiagram shows, and every concrete defect with where it is (which node, label, title or edge). Defects
  (P7 fixes them): two boxes or labels overlapping; text clipped or outside its box; an edge through a node or a
  container title band; a word split inside a title or label; a staircase (one rank drifting diagonally so edges
  cannot be followed where Mermaid is aligned); labels or edges crowded so that the column PNG cannot be read; an
  element missing compared with Mermaid. Observations (recorded, not fixed): a different but readable layout, a
  different size, Mermaid colours or classDef styling not carried, a dropped subgraph direction. A problem already
  visible in the Mermaid render is a source-diagram property: an observation.
- **P7 Defect procedure** (only when P5 or P6 found a defect). (a) Write a failing test in `crates/vox-diagram`
  first, using the corpus `.vdg` as input where possible and the existing helpers in `src/layout/tests/` and
  `tests/support/svgcheck.rs`; observe it fail. (b) Fix in `crates/vox-diagram/src`. (c) Re-bless only goldens the
  fix changes (`UPDATE_GOLDEN=1` on the owning binary, e.g. `binary(svg_corpus)`), read each golden diff, then
  `INSTA_UPDATE=no timeout 3600 cargo nextest run -p vox-diagram --retries 0` and `timeout 3600 cargo clippy -p
  vox-diagram --all-targets -- -D warnings` pass. (d) Mutation proof: revert the fix in a copy, confirm the new test
  fails, restore and confirm the restore with a grep presence check. (e) Commit `fix(90): <defect>` on its own.
  (f) Re-run P3, P5 and P6 for this batch, regenerate contact sheets for every stem migrated in earlier batches into
  `target/vd-migration/bN-recheck/`, `diff -q` each against its earlier PNG and Read every one that changed. If the
  fix would need a layout redesign rather than a bounded change, stop and report it as a checkpoint.
- **P8 Commit.** Stage only the batch's docs and the baseline YAML; `docs(90): migrate batch N Mermaid fences to
  vox-diagram` (background, timeout; lefthook runs).
