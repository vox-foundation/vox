<decisions>
## Implementation Decisions

### Scope and allowlist
- Corpus at committed HEAD: 33 fences in 21 files (the baseline YAML lists them). The home page (`docs/src/index.mdx`) has no Mermaid fence on this branch, so "home-page fence first" in ROADMAP SC1 does not apply; start with the smallest single-fence files instead.
- Allowlist = the Gantt only (user decision 2026-10-16). Each allowlist entry carries a reason.
- The one non-Gantt block the importer rejects (`docs/src/how-to/how-to-rust-crate-imports.md`, a flowchart whose labels are Mermaid markdown strings using backticks only for code formatting) is converted by hand, dropping the backticks, rather than allowlisted — no new allowlist entry, so no further user sign-off is needed. Any other block that turns out unconvertible: stop and report; do not allowlist it.
- If `main` gained Mermaid fences after 2026-10-16, they are out of scope here: the user re-seeds the baseline when this branch next merges `main` (Phase 87 decision).

### Conversion method and fidelity
- Use `vox diagram import` (the Phase 84 strict importer, via the CLI or `vox_doc_pipeline::diagram::mermaid::import`) — never hand-transcribe a convertible block. Hand edits after import are limited to readability (ids, label wrapping) and must keep node/edge-set equality.
- Fidelity check per fence: import → Mermaid export → node/edge-set equality against the original (the Phase 84 round-trip oracle); recorded in a per-batch fidelity report. The hand-converted backtick block is checked the same way against its backtick-stripped original.
- Every migrated fence passes `vox diagram check` and the doc lint (`cargo run -p vox-doc-pipeline -- --lint-only --paths <file>`).

### Batches and review
- Small batches (about 4–6 fences, grouped by file; the 7-fence and 4-fence files may be their own batches), one commit per batch.
- Each batch gets a before/after contact sheet: Mermaid rendered by the pinned Node oracle (mermaid@11.17.2 + jsdom, Phase 84) or the shipped site, beside the VoxDiagram SVG from the built site / `vox diagram render`. The executor opens the PNGs with Read and records concrete layout defects (overlaps, clipped text, edges through titles, staircases, unreadable density). A defect in the renderer is fixed in `crates/vox-diagram` with a red-first test, not worked around in the doc.
- After the last batch: tighten the baseline with `--tighten-mermaid-baseline` (never hand-edit the generated YAML), confirm the Gantt is the only remaining fence and its reason is recorded, and confirm `git diff` over `docs/src/archive/` is empty.
- Closing gate: `pnpm diagrams && pnpm build` in docs-astro, then the diagram Playwright specs (`tests/vox-diagram.spec.ts`, `tests/build-output/diagrams.spec.ts`) over the full migrated corpus (figure pages are discovered from `dist/`).

### Carried forward
- Fixes from the Phase 89 review: compact containers, sideways titles laid in their content's ranks, no edge through a title band, words never split in titles, Arimo webfont with metric-identical fallbacks.
- Determinism, no new crate edges or dependencies, files < 400 lines, tests first for any Rust change.
- Generated artifacts are regenerated by their generators, never hand-edited.

### Claude's Discretion
- Batch grouping, contact-sheet layout and file location (scratch or the docs-astro review bundle; not committed unless small), fidelity-report format (a markdown table in the plan SUMMARY is enough).

</decisions>
