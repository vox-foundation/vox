<objective>
Make every diagram label fit a font about 20% wider than the static width table, without touching the table: a
minimum horizontal padding floor in the Rust layout (D-09), applied everywhere a text box is padded, with the
affected goldens re-blessed deliberately and every oracle still green. This is the Rust half of DOCS-04's "labels
fit their boxes under two font stacks"; plan 89-04 proves it in a real browser.

- Task 1 (tracer): the floor function, applied to sequence message labels (the worst measured overflow, 4 px pad)
  through render to the re-blessed sequence goldens.
- Task 2: the remaining call sites (nodes and actors via `node_size`, edge labels, notes, container title struts),
  the graph goldens, the full suite, clippy, and the decision record.

Output: `pad_x` in `layout/text.rs`, its call sites, re-blessed goldens, updated font policy.
</objective>

Sizing (D-09, numbers from 89-RESEARCH.md Open Question 1): `measure` already includes the 8% slack, so a font whose
advances are R times the table needs a box of `R / 1.08` times the measured width. Verdana measured R up to 1.186;
DejaVu is expected similar (A5). With a per-side floor of 6% of the measured width (`WIDE_FONT_PCT = 12` percent in
total) a box is at least 1.12 x measured = 1.21 x the table, which covers the measured worst case with about one
percent to spare. All labels are drawn centred (`shapes::label`, `text-anchor: middle`), so the overflow splits
evenly across the two sides. Node labels already have 14 px per side and only grow for text wider than about 233 px;
edge and message labels (4 px per side) grow for text wider than about 67 px.

Scope note (discretion, recorded): D-09 names message, edge and node labels. The same floor also goes on sequence
notes (14 px per side, up to 60 cells wide) and container title struts (10 px per side), because the browser check in
89-04 requires every `<text>` inside its box (D-07, ROADMAP SC2) and the same arithmetic overflows those boxes
under a wide font. Sequence actor boxes get it through `node_size`.
