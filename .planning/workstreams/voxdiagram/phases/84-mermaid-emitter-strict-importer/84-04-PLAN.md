Added here:
- `text.rs`: free-text decoding for state transition text, sequence aliases, messages and notes: the 84-03
  pipeline (br forms, single-pass Mermaid entities, trim, `html-label`, `html-entity`, `entity`,
  `forbidden-char`, `label-too-long`) WITHOUT the unquoted-label character ban (Mermaid state and sequence
  text is free text to end of line; corpus 32 has `lease expiry (swept)`); a raw `;` is `semicolon` and
  `%%` is `comment`. Sequence text additionally rejects a raw trimmed text starting `wrap:`, `nowrap:`,
  `:wrap:` or `:nowrap:` as `wrap` (Mermaid strips the prefix; RESEARCH "Sequence export"). As in 84-03,
  every rejection check runs on the RAW text; the decoded text is only checked for emptiness, length and
  forbidden characters, so the exporter's encoded forms (`#59;`, `#119;rap:`, `#96;`) import back as text.
  Empty message and note text is allowed (`text: ""`); a blank participant alias is `empty-label`.
- `import/mod.rs`: header arms `stateDiagram-v2` and `sequenceDiagram` (`stateDiagram` without `-v2`
  stays `header:stateDiagram`).
- stateDiagram-v2 subset (RESEARCH "Importer Rules", state row): `A --> B`, `A --> B : text` /
  `A --> B: text`, `[*] --> A`, `A --> [*]`, `[*] --> [*]`. State ids follow the DSL id rule; `start` and
  `end` as state ids are `id-clash` (reserved for the terminals, whatever the block contains). Nodes in
  first-mention order, states rect with label = id; the terminals are created at their first mention.
  Direction down. Output via `flow::Graph` + `to_dsl` + `fmt`. Unsupported: `state "x" as y`
  (`state:alias`), `A : description` (`state:description`), `state X {` / a lone `}` (`state:composite`),
  `<<fork>>` `<<join>>` `<<choice>>` (`state:pseudo`), `note …` / `end note` (`state:note`), a `--` line
  (`state:concurrency`), `direction X` (`direction`), styling heads and `:::` (`styling:*`, droppable),
  anything else `statement`.
- sequenceDiagram subset (RESEARCH "Importer Rules", sequence row): `participant X`,
  `participant X as Label`; `X->>Y: text` (solid), `X-->>Y: text` (dashed), spaces around the arrow
  allowed, text after the first `:` (may be empty; a missing `:` is `message-syntax`); `Note over X: text`,
  `Note over X,Y: text` (`note` in any case). Participant ids follow the DSL id rule. A participant first
  used implicitly becomes `Actor { id, label: id }` at its first mention; `participant` after an implicit
  use is `participant-after-use`; a second `participant` line for the same id is
  `redeclared-participant`. Every `Actor`/`SeqEvent` `span` is a `Location` from `span::LineIndex` over
  the statement's trimmed byte range in the block. Caps: more than `MAX_NODES` participants `limit-nodes`,
  more than `MAX_EDGES` events `limit-edges`. Unsupported: `actor` (`actor`), `create` / `destroy`
  (`lifecycle`), `activate` / `deactivate` and `+`/`-` arrow suffixes (`activation`), other arrows `->`
  `-->` `-x` `--x` `-)` `--)` `<<->>` `<<-->>` (`arrow:<token>`), `loop alt else opt par and critical
  option break rect end` (`block:<keyword>`), `autonumber`, `title`, `box`, `link` / `links` / `properties`
  / `details` (`links`), `Note left of` / `Note right of` (`note-placement`), `Note over` with more than
  two ids (`note-actors`), `accTitle` / `accDescr` (`styling:accTitle` / `styling:accDescr`, droppable),
  `%%` (`comment`), `%%{` (`directive`), anything else `statement`.
- Report: state blocks set `source`; sequence blocks set `sequence` and leave `source` None.
