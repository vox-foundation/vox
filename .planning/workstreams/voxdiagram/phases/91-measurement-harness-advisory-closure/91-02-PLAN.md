## Task authoring rules (binding for Tasks 1-3)

- One compact JSON object per line (no space after `:` or `,`, as `serde_json::to_string` writes it), keys in this
  order: `id`, `kind`, `prompt`, `reference`. Ids `g001`..`g184` (graph) then
  `s001`..`s016` (sequence); the file is sorted by id.
- The prompt describes the diagram in plain prose, identically usable by both arms: every label, edge label, container
  title, actor name, message and note text appears verbatim in double quotes; a graph prompt always states its
  direction as one of `top to bottom`, `left to right`, `bottom to top`, `right to left`; nesting is described as
  groups or regions ("inside a group titled ..."), shapes in words ("drawn as a cylinder", "a diamond decision",
  "a rounded box", "a start circle", "an end double circle"), sequence order explicitly ("first", "then", "replies",
  "a note over ...", "sends ... to itself"). Outside quoted labels a prompt never uses arrow tokens or the words
  subgraph, container, flowchart, mermaid, vox, node, actor, participant (the gate checks this case-insensitively).
- The reference is a VoxDiagram source that checks valid and draws exactly what the prompt says. Labels have no line
  breaks. Prefer references of at most 25 nodes. A reference may be adapted from the corpus or fixture files above
  (the docs corpus is public, which can only favour the Mermaid arm: record it for the report's limitations) or
  written fresh.
- Never derive a prompt or reference from a model's output; tasks are hand-authored data.
