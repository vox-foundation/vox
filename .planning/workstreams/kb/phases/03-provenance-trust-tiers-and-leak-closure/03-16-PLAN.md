## Decisions applied

- **D-08 (binding, user decision 2026-10-08):** "tracked by git and has no working-tree modifications" is read against HEAD: the file is in `git ls-tree HEAD` and absent from `git diff HEAD` (staged or unstaged). A staged but uncommitted new file is therefore Untrusted. That is the stricter, fail-closed reading, and it matches TRUST-01's "merged to git".
- **Fail-closed git:** any GitExec error (git missing, not a checkout, no HEAD) gives an empty clean set, so every file is Untrusted. When `repo_root` is not the git top-level, the paths do not match and the result is again Untrusted.
- **Ceiling semantics:** `IndexDeps::trust_tier` stays the corpus ceiling (`tier_for_curated(false)` = Trusted in production) and is still recorded in `kb_index_state`. Per-file tier = ceiling if clean, else Untrusted.
- Removing the corpus-wide re-stamp reverses the 03-05 "rows always agree with kb_index_state" invariant. It is replaced by "every walked file has its tier re-evaluated every run", which is strictly stronger for safety.

## Flagged assumptions

- `kb_eval/library.rs` (a non-test source file) passes an always-clean classifier. It indexes a synthetic corpus into a throwaway in-memory database for retrieval-quality evaluation and never touches a user database, so tier gating is out of its scope.
- The 03-03 version-gated backfill still copies `kb_index_state.trust_tier` onto Library rows when a v95 database upgrades. Only dev databases on this branch are v95 (`main` is at 94, and Phase 2 is unshipped), and the next reindex re-tiers every walked file, so this is not changed here.
