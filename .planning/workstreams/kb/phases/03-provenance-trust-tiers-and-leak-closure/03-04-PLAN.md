<objective>
Build the single capture chokepoint that turns web text into pending Untrusted findings, and reroute the two live web-leg sinks (R1 in `execute_search_plan`, the Tavily CRAG mirror) into it.

Purpose: TRUST-02 (web hits never enter the searchable corpus), TRUST-04 (provenance plus a gitignored snapshot), TRUST-05 at the ingest boundary. vox-search has no vox-crypto edge, so hashing, redaction and snapshots run in vox-orchestrator-mcp and reach vox-search through an injected trait, mirroring the existing `LexicalMemoryFallback` injection.
Output: `vox_search::capture::{WebFindingCapture, CapturedWebHit}`, `SearchRuntimeContext::web_capture`, `vox_orchestrator_mcp::kb_tools::findings` capture pipeline, and the deletion of the corpus mirror helper.
</objective>

## Assumptions pending discussion

- **`persist_web_hits` stays default-on (Open Question 3)** and now means "capture into the inbox, deduped". Alternative: default it off until the Phase 9 review tools exist.
- **Taint rule (Open Question 1):** every captured web finding is Untrusted. Advisory is reserved for agent output derived only from curated inputs, which no Phase 3 path produces.
- **Snapshot location (Open Question 6):** content-addressed under the repo root's `.vox/cache/kb-findings/`, `snapshot_relpath` relative to the repo root, even when the DB is the user-global one. Alternative: next to the DB in the user data dir.
- **Quote caps:** at most 3 quotes of at most 300 chars, summary capped at 1000 chars, snapshot capped at 2 MiB (copyright posture is a Phase 9 decision).
- **Surfaces with no sink capture nothing:** the GUI's in-process `vox_search_query` and CLI research paths build a context without a sink, so their web hits are no longer persisted anywhere. Alternative: inject a sink there too.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| web providers (SearXNG, DDG, Tavily) → vox-search | attacker-controlled page text and titles |
| vox-search → capture sink → kb_findings | the only path web text may take into storage |
| capture → local filesystem | snapshot writes under the repo root |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-07 | Tampering | `execute_search_plan` web leg, CRAG branch | high | mitigate | Hits go only to `WebFindingCapture`; no sink means no write; mirror helper deleted; mutation-proven row-count test |
| T-03-08 | Information disclosure | `capture_finding` summary/quotes | medium | mitigate | `vox_redact::redact_owned` before storage; redaction test mutation-proven |
| T-03-09 | Tampering | snapshot writer | medium | mitigate | Filename is the content hash only (no URL-derived path, no traversal); `atomic_write_secure`; 2 MiB cap |
| T-03-10 | Denial of service | inbox flood from preamble re-searches | medium | mitigate | `dedupe_key` UNIQUE with ON CONFLICT DO NOTHING; one capture point per path |
| T-03-23 | Tampering | stored prompt injection in captured text | high | mitigate | `SanitizedText` at ingest; red-team set asserted on stored summary and quotes; rows stay pending and are never auto-injected |
| T-03-24 | Repudiation | swallowed capture errors | low | mitigate | `tracing::warn!` on every capture failure; no `let _ =` in findings.rs |
