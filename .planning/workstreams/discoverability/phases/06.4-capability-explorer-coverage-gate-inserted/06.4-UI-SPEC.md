### Domain rail

- First item "All domains", then `CAPABILITY_DOMAINS` in generated order. Omit a domain with zero indexed rows (before filters).
- Each item (h-10, px-2, rounded-lg): label (13px, text-secondary; selected = `--color-accent-default`), right-aligned count (11px mono, text-muted), and under the label a 4px-high status-mix bar made of four segments in the four badge colors (proportional to counts; `aria-hidden`). A visually-hidden sentence carries the same data: "Mesh / Populi, 1,284 capabilities: 612 Generic form, 480 Dedicated surface, 150 CLI-only, 42 MCP-only / orphan".
- Selected: `aria-current="true"`, 2px left marker + `bg-brass/8 border border-brass/20` (same selected treatment as Omnibar rows). Counts reflect the current search + show-exempt setting (not the status filter), so hits in other domains stay visible while typing. A domain with 0 matches stays selectable, count "0", `text-text-muted`.
- Keyboard: one tab stop (roving tabindex); Up/Down/Home/End move focus; Enter/Space selects. Selection is not changed by focus movement.

### Tree row model (what the generator must provide, names are the planner's)

Tree = domain scope -> group rows (level 1) -> verb rows (level 2). With "All domains" selected, a domain header row is level 1, groups level 2, verbs level 3. Each domain scope ends with a pseudo-group "MCP-only tools" holding MCP tools with no CLI/GUI path.

| Row | Needs |
|-----|-------|
| Group | name (`vox mesh`), status (dedicated / generic_form / cli_only), `viewKey?` (dedicated surface), crate + layer, verb count, short summary, docs path, exemption `{owner, reason, reviewBy}` or null, Explain target index row id |
| Verb | CLI path array, own status (inherits the group's badge unless not compiled into the build, then CLI-only; D-16.4), summary, side-effect class, `catalogForm`, Explain target row id |
| MCP-only tool | tool name, summary, status `mcp_only` (graph-flagged orphans use the same badge), docs path, Explain target row id |

"Capability" in every count in this UI = one leaf row (a verb or an MCP-only tool). Groups are containers; a group appears when any leaf under it matches the filters.

### Row anatomy (treegrid row, columns: Capability | Status | Actions)

| Row | Height | Capability cell | Status cell (176px) | Actions cell (304px) |
|-----|--------|-----------------|---------------------|----------------------|
| Domain header | 40px | chevron + domain label (font-display 13 uppercase tracking-[0.14em]) + count | rollup bar only (no badge) | none |
| Group | 48px | chevron; line 1: `vox mesh` (13px mono text-primary); line 2 (11px text-muted, truncate): `{crate-button} · L{n} · {k} verbs · {summary}` | group badge | Open surface / Open form, Explain capability, Open docs |
| Verb | 36px | 24px indent spacer; `vox mesh status` (13px mono text-secondary, truncate) | own badge | Open form, Explain capability, Open docs |

## Interaction

### Roles and semantics (decision: treegrid, not tree)

Rows carry several actionable cells, which a plain `tree` cannot express. Use the WAI-ARIA `treegrid` pattern.

| Element | Semantics |
|---------|-----------|
| Container | `role="treegrid"`, `aria-label="Capabilities"`, `aria-rowcount` = visible row count + 1 header, `aria-colcount="3"`, `aria-multiselectable` absent |
| Header row | `role="row"` with three `role="columnheader"` cells (Capability, Status, Actions); sticky, `aria-rowindex="1"` |
| Row | `role="row"`, `aria-level`, `aria-setsize`, `aria-posinset`, `aria-rowindex` (computed from the full filtered list, not the rendered window), `aria-expanded` on rows with children only, `tabindex` roving (`0` on the active row, `-1` elsewhere) |
| Cells | `role="gridcell"`; Actions cell contains real `<button>` elements |
| Domain rail | `nav` + buttons with `aria-current` (not a listbox) |
| Filter chips | `div role="group" aria-label="Filter by status"` of `<button aria-pressed>` |
| Search | `<input type="search">` with a visible-to-AT label "Search capabilities", `aria-controls` = treegrid id |
| Result count | one `role="status"` `aria-live="polite"` node: "{n} capabilities in {domain label}" (visible, 11px muted, right of the filter bar) |

### Keyboard (tree/treegrid APG, row-then-cell)

| Key | On a row | On an action button |
|-----|----------|---------------------|
| Tab | Enters the grid at the active row; next Tab leaves the grid. Shift+Tab returns to the show-exempt checkbox | (not used inside the row) |
| Down / Up | Next / previous visible row | Same row's button stays; Down/Up moves to the same action on the next row |
| Home / End | First / last row | n/a |
| PageDown / PageUp | +/- 10 rows | n/a |
| Right | Collapsed parent -> expand. Expanded parent or leaf -> focus first action button | Next action button (stops at last) |
| Left | Expanded parent -> collapse. Collapsed parent or leaf -> focus the parent row (level 1: no-op) | Previous action; from the first action -> back to the row |
| Enter / Space | Parent: toggle expand. Leaf: run the primary action (Open surface/form) | Activate the button |
| Escape | no-op | Back to the row |
| Escape in search | Clears the query (if empty, no-op) | n/a |

- Virtualization must never unmount the focused row: use the virtualizer's `rangeExtractor` to always include the active index; arrow moves call `scrollToIndex` then focus after render.
- Focus ring: the global `*:focus-visible` 3px accent outline (7.37:1 dark, 5.15:1 light). Do not remove or restyle it.
- Mouse: click a parent row body toggles it; click on a leaf row selects it only. Buttons inside a row stop propagation.
- Expanded state is component state (not persisted). Search or a status filter auto-expands the ancestors of matches (derived, not stored); clearing returns to the user's own expansion.
- Auto-expand cap: if matches would expand more than 200 rows, expand only the first 20 groups and show "Showing the first 20 matching groups, narrow the search to see the rest." in the result-count line. (Prevents a 1-letter query from expanding the whole tree.)

### Actions (D-10a)

| Action | Label | Behavior |
|--------|-------|----------|
| Open surface | "Open surface" | Group with `viewKey`: `onNavigate(viewKey)` (hash-synced via `navigateTo`) |
| Open form | "Open form" | Group without dedicated surface, or verb: prefilled Catalog form via the same App handler as the palette (`setCatalogPrefill` + `navigateTo('catalog')`). For a group the path is the group name. `decideCliActivation` result `explain` -> button stays rendered, `aria-disabled="true"`, `aria-describedby` points to a visually-hidden reason ("Not compiled into this build" or "Not in this build's command catalog"); activation is a no-op. `run` is mapped to `form`: the Explorer never executes anything and has no destructive actions |
| Explain | "Explain capability" (`aria-label="Explain capability {name}"`) | `onExplain(targetRowId)`; opens the existing `ExplainDrawer`. Group target = the index row for the bare group CLI path, else its surface row; if neither exists the button is `aria-disabled` |
| Docs | "Open docs" (icon `book` + text; icon-only below 1024px with `aria-label="Open docs for {name}"`) | `onOpenDoc(docKey(path))` (same as the drawer). Absent docs -> button omitted |
| Crate / layer | `{crate} · L{n}` in the row's second line, styled as a link (underline on hover/focus, `text-text-secondary`) | Opens Explain for the crate's index row (kind `crate`). Becomes an Atlas link in 06.5. If no crate row is found, render as plain text |
| Exemption | none; inline | Exempt groups show an `Exempt` tag in the second line and, when expanded, an exemption strip (below) |

Action buttons: `Button variant="outline" size="sm"` (28px high, 11px text); only "Open surface/form" uses `text-text-primary`, the others `text-text-secondary`. All always visible (not hover-revealed), so keyboard, touch and screenshots show them.

### Exemption display (D-14)

- Collapsed exempt group row: second line starts with an `Exempt` tag (11px uppercase, neutral outline) followed by "review by {YYYY-MM-DD}". Badge in the Status cell is **CLI-only** (D-03: exempted = CLI-only).
- Expanded: first child is the strip, a `dl` on `bg-overlay-subtle rounded-lg p-4` with three rows in a 7rem/1fr grid (same recipe as `ExplainDrawer` `Group`): **Owner**, **Reason** (full text, wraps, no truncation), **Review by**.
- Past due (`reviewBy` < today in the client's local date): the `Exempt` tag gains a second tag `Review overdue` (`--color-status-fail`, glyph `!`), the strip's "Review by" value reads "{date}, overdue", and the chip/rail counts are unaffected. (CI fails on past-due, so this only shows when a build is older than its own review date; it must still be visible.)
- Hidden by default (see show-exempt). The tag/strip are text, never color-only.

### Filters

| Control | Behavior |
|---------|----------|
| Search | Case-insensitive substring match over id, title, CLI path, MCP name and summary; `useDeferredValue` (no debounce timer); 1,500 rows is trivially cheap. Esc clears. |
| Status chips | Four toggle buttons, multi-select, OR semantics, none pressed = all. Label = badge name + count (e.g. "Generic form 590"). Pressed chips add a leading `✓` glyph and `ring-(--color-accent-default)` so the state is not color-only. Counts respect domain scope, search and show-exempt, but not the status filter itself. |
| Show exempt groups | Native `<input type="checkbox">` + label "Show exempt groups ({n})", **default off**. Off hides every exempt group (and so its verbs) from rows and counts; the count in the label is always shown so the hidden amount is never a surprise. `accent-color: var(--color-accent-default)`. |
| Clear filters | Appears in the no-results state only. Resets search, chips and show-exempt, keeps the domain. |

## States (D-11)

All states render inside the surface frame; the title and (when known) snapshot note always show.

| State | Trigger | Render |
|-------|---------|--------|

## Virtualization (decision: required)

Worst case rendered rows is about 1,500 (about 1,000 verbs + 342 MCP tools + about 88 groups + domain headers) when a broad search or "expand all"-like filter opens everything; `extras-ludus` alone expands to about 200 rows. Without a window this is 1,500 rows x ~10 elements and measurable jank on open. Therefore:

- Always virtualize the tree body with `useVirtualList` (`overscan: 8`), including the collapsed default (cheap, one code path).
- Rendered DOM must stay under 150 `role="row"` elements regardless of expansion (assert in Playwright) while `aria-rowcount` reports the full count.
- The degraded fallback list (<= 112 rows) is not virtualized.
- Unit tests target `explorerModel.ts`; the component test sets `initialRect` so the virtualizer renders a window under jsdom.

## Color

All colors are existing semantic tokens; both themes resolve through the same variable names. Contrast values were computed (WCAG relative luminance) against `--color-bg-surface` / `--color-bg-base` for the real hex values in `tokens.generated.css` / `tokens.travertine.generated.css`.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-bg-base` (#0c0e10 / #ece5d6) | surface background behind rail and tree |
| Secondary (30%) | `--color-bg-surface` / `--color-overlay-solid` via `Glass`; hover `--color-overlay-hover`; strip `--color-overlay-subtle` | rail, tree container, row hover, exemption strip, input fill |
| Accent (10%) | `--color-accent-default` (#c9a24a / #7d5f20) | see list below |
| Destructive | n/a | the Explorer has no destructive action. `--color-status-fail` is used only for the "Review overdue" tag |

Accent reserved for (and nothing else): (1) the selected domain label and its left marker, (2) the global focus ring, (3) pressed state ring on a status chip, (4) the show-exempt checkbox, (5) the "Browse all … in the Explorer" link in the palette hint. **Small accent text must use `--color-accent-default`, not `text-brass`**: `rgb(var(--brass))` in travertine is #8a6a26 = 4.36:1 on surface and 4.02:1 on base, below AA for 11-13px text; `--color-accent-default` is 5.15:1 (light) and 7.37:1 (dark).

**Focal anchor:** the Status-column badges are the primary focal point (the only saturated color in each row, aligned in one 176px column so the eye scans down them), with the selected rail domain (accent marker + accent label) as the secondary anchor. Row text, buttons and counts stay neutral (`text-primary`/`secondary`/`muted`, outline buttons) so nothing competes with the badges.

### Badge palette (D-03: exactly four, label text always visible, glyph always shown, never color-only)

| Badge (visible text) | Glyph | Color token (text + ring/30) | Contrast on surface dark / light |

| Generic form | `≡` | `--color-status-info` | 12.44 / 7.26 |
| CLI-only | `>_` | `--color-text-secondary` | 10.87 / 8.34 |
| MCP-only / orphan | `◇` | `--color-status-warn` | 6.61 / 5.04 |
| Exempt tag | none | `--color-text-secondary`, outline only | 10.87 / 8.34 |

## Decided by researcher (override any of these)

CONTEXT left these visual/interaction choices open; each was decided from the existing design system.

1. **Placement**: pinned in the sidebar System block replacing the Coverage item (not a main-list top-level view), icon `branch`, la label "Facultates". Alternative: add to `TOP_LEVEL_VIEWS` next to Commands for higher visibility.
2. **Treegrid, not tree**, because rows have several actions; row-then-cell keyboard model.
3. **Capability count unit** = leaf rows (verbs + MCP-only tools); groups are containers whose badge is a rollup.
4. **Default scope** = "All domains" with domain header rows; selecting a domain drops the header level.
5. **Show-exempt default off**, with the hidden count always displayed. Alternative: default on (shows about 400 extra CLI-only verbs).
6. **Status chips are multi-select toggles** (not `Segment`), doubling as the legend.
7. **Crate/layer link** opens the crate's Explain card until 06.5 provides the Atlas.
8. **Degraded error state** shows a static-registry flat list (data already in the bundle) rather than a blank page, mirroring the palette.
9. **Own badge component** instead of `StatusPill`, because two `StatusPill` tones are not theme-safe; the old `CoverageView` chip colors fail contrast in travertine and are dropped.
10. **Exemption detail inline** (strip), not a popover (`Popover` is dark-only and bottom-anchored).
11. **Palette link seeds the Explorer search** with the palette query (small extra beyond the bare link in D-12; drop it if it costs more than a state field).
12. **Weights 400 + 500** (matches existing `StatusPill`/`Button`), sizes 11/13/18.
13. **Past-due is computed from the client's local date** at render time.
