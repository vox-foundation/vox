   - `pub fn resolve<'a>(index: &'a CapabilityIndex, query: &str) -> anyhow::Result<Resolution<'a>>`:
     - trims and lowercases the query
     - rejects an empty query or one over MAX_QUERY_CHARS chars (count chars, not bytes)
     - builds each row's alias list with a priority number: 0 id; 1 cli forms; 2 mcp name and name minus `vox_`; 3 surface view_key; 4 crate name and name minus `vox-`; 5 skill id minus `skill.`
     - on an exact hit, picks the primary by (priority, kind order, id); `also` is the rest, sorted the same way and capped at MAX_RESULTS - 1
     - otherwise scores each row as the max of token containment (query tokens found in tokens of id, title, cli path, mcp name, view_key) and `strsim::jaro_winkler` against each alias; keeps rows at or above the threshold, sorts by score desc then id asc, and truncates to SHORTLIST_LIMIT
     - returns NoMatch when nothing qualifies
   - The query is treated purely as data: no regex built from it, and no path operations.
   - `pub fn explain_rows<'a>(r: &Resolution<'a>) -> Vec<&'a IndexRow>`.

   - Header: title, kind and id, then the summary line.
   - **Equivalents**:
     - `CLI:` the row's own `cli.invocation`, otherwise the invocations of `equivalents` / `refs` rows of kind cli

     - `GUI:` `nav_label (view <view_key>)` from the row's `gui`, otherwise from a linked surface row. The view key is the value the GUI's `vox://navigate-surface` event takes (RESEARCH Join Keys).
