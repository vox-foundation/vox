## Deviations from Plan

**1. [Rule 1 - Bug] Dead-code warning on `Domains.schema_version`.**
- **Found during:** Task 1 verification build (pre-existing from 06.2-02, surfaced in every build).
- **Issue:** the field is deserialised only so `deny_unknown_fields` accepts the yaml key; `clippy -D warnings` in hosted CI would reject the warning.
- **Fix:** `#[allow(dead_code)]` with a reason comment. **File:** inputs.rs. **Commit:** d17a90daf.

**2. [Note] Function signatures differ slightly from the plan text.** `apply_surface_join(rows, surfaces)` drops the `ops` parameter (the mcp op-id namespace is already on `row.op_id`); `non_operation_rows(rows, inputs)` takes the rows mutably so it can write the `skills` back-references; `Inputs` holds one `skills: Vec<SkillInput>` instead of separate plugin and bundle lists. `owner::owner_ref` and `join::single_line` became `pub(super)` so nodes.rs reuses them (all inside the plan's files).

**3. [Note] `--refresh-coverage` without `--write`.** It writes the snapshot, then runs check mode, which reports the index stale once the snapshot changed. The documented flow is `--refresh-coverage --write`, after `vox graph rebuild --corpus vox-gui-surface`.

**4. [Note] Snapshot provenance.** The committed snapshot's `git_sha` (75465d426) is the commit at refresh time, a test(06.2-05) RED commit, not the final HEAD. That is by design (D-08 shows the age, nothing gates on it).

**Total deviations:** 1 auto-fixed (Rule 1), 3 notes. Impact: none on scope.
