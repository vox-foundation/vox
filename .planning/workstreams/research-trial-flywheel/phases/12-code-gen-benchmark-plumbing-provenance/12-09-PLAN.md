<objective>
Make every benchmark run a Phase 7 campaign run with a signed, offline-verifiable evidence bundle and atomic Tier A persistence (BENCH-06; completes BENCH-04's integrity group; D-01, D-07, D-09, D-10).

Purpose: results today live only in unsigned JSON files; nothing ties a run to a signed preregistration or makes a tampered result detectable. This plan consumes exactly five Phase 7 interface items and owns everything else (bundle shape, signing call, offline verification, compare-side verification). It is the only Phase 12 plan that depends on Phase 7, which has no plans yet, so its task preconditions halt execution until Phase 7 has shipped those items.
Output: `crates/vox-cli/src/commands/model/eval_bundle.rs`; campaign-aware eval-corpus; bundle-verifying eval-compare.
</objective>

## Phase 7 interface this plan consumes (assumed names, RESEARCH A7)

Phase 7 is unplanned, so the names below are the contract shape, not final identifiers. The executor maps each item to Phase 7's actual symbol (from the Phase 7 SUMMARY files) and halts if any item is missing or shaped differently.

| # | Item | Shape Phase 12 needs |
|---|---|---|
| 1 | Run identity | open a run under a signed campaign → `campaign_id`, `run_id`, `replicate_id`, `attempt_index`, `retry_of_run_id` (strings/ints; mapped into `vox_eval::provenance::RunIdentity`) |
| 2 | Preregistration id and signer | the campaign's `preregistration_id`, its allowlisted `signer_key_id`, and a signing handle for that key resolved the way Phase 7 resolves the campaign signer (D-10: no new Clavis `SecretId`) |
| 3 | Canonicalizer | `canonical_json_bytes<T: Serialize>(&T) -> Result<Vec<u8>, _>`: keys sorted at every depth, non-finite numbers rejected (TRIAL-05) |
| 4 | Allowlist check | `verify_signer_allowlisted(pubkey_hex) -> Result<(), _>` |
| 5 | Atomic persist | one-transaction persist of the run row (with the canonical §5 record as `provenance_json` plus indexed scalars `syntax_fingerprint`, `model_id`, `condition`, `problem_set_hash`, `run_complete`) and its sample batch, with a test failpoint for STORE-02; `model_benchmark_results` defined in the Phase 7 baseline as a projection over these tables (D-09) |

Schema ask for the STORE-01 human gate (raised again in the planning return): add `provenance_json TEXT NOT NULL` plus the five indexed scalar columns above to the Tier A run row instead of one column per §5 field, so Phase 13 can add provenance fields without a migration; and fold the branch's uncommitted `model_benchmark_results` into the Phase 7 baseline as that projection (D-09). Phase 7 must not reuse baseline 95, which this branch's uncommitted work already claims.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bundle file → any offline verifier / eval-compare / replay | the bundle travels as an artifact and may be modified in transit |
| harness → Tier A database | run, provenance and samples are written to the shared DB |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-09-01 | Spoofing | bundle self-signed by an arbitrary key | high | mitigate | Phase 7 allowlist check runs before signature verification; `foreign_signer_is_not_allowlisted` and `swapped_embedded_key_fails` (D-10) |
| T-12-09-02 | Tampering | edited record, sample code or seed | high | mitigate | ed25519 over Phase 7 canonical bytes; four tamper tests; mutation proof 5 |
