## Fixed Issues

### WR-01: "Related" group is crowded out by unrelated same-owner rows

**Files modified:** `crates/vox-capability-registry/src/card.rs`, `crates/vox-capability-registry/src/index.rs`, `crates/vox-capability-registry/src/lib.rs`, `crates/vox-cli/src/commands/ci/capability_index/owner.rs`
**Commit:** 10d2058f6
**Applied fix:** Related now sorts same-domain rows first, then same-crate rows, with the id as tie-break. Surface crates no longer count as a shared owner. The `SURFACE_CRATES` list is exported once from `vox-capability-registry` and `owner.rs` uses it, so there is no second copy. The new test uses a fixture of five alphabetically earlier `vox-cli` rows in another domain; on the old code the same-domain sibling was cut by the limit.

### WR-02: Index "skills" input comes from the compiled-in plugin catalog

**Files modified:** `crates/vox-cli/src/commands/ci/capability_index/inputs.rs`
**Commit:** 64241cb98
**Applied fix:** `load_skills(repo_root)` parses `crates/vox-plugin-catalog/catalog.toml` from disk. It uses the catalog crate's public schema types (`PluginCatalogEntry`, `SkillBundleEntry`) through a small private struct. This adds no workspace crate edge: `vox-cli` already depends on `vox-plugin-catalog`. A test writes a temp-dir catalog and asserts the rows follow the file and that a missing file is an error.

### WR-03: Malformed or unreadable docs frontmatter silently drops claims

**Files modified:** `crates/vox-cli/src/commands/ci/capability_index/docs_claims.rs`, `crates/vox-cli/src/commands/ci/capability_index/inputs.rs`, `crates/vox-doc-pipeline/src/pipeline/lint.rs`, `docs/src/contributors/documentation-governance.md`
**Commit:** 4f0953f5c
**Applied fix:** `parse_meta(path, content)` now returns `Result`. A page whose `capabilities:` key cannot be parsed, or whose frontmatter has no closing `---` while it declares `capabilities:`, fails the generator with the page path. A BOM before the frontmatter is tolerated. Read errors in the docs walk now propagate with the path. Malformed frontmatter that makes no claim is still skipped. The two lint tests that passed on the unmodified lint were removed, and the governance doc now says the generator is the check and the lint does not parse YAML. Tests: unreadable scalar/flow/unterminated claims, a BOM, and a skip case without a claim.

### WR-04: `single_line` / `safe_line` strip only Cc controls

**Files modified:** `crates/vox-cli/src/commands/ci/capability_index/join.rs`, `crates/vox-cli/src/commands/ci/capability_index/emit.rs`
**Commit:** 9f9dbe443
**Applied fix:** `single_line` (which `safe_line` calls) also drops U+200B-200F, U+202A-202E, U+2060-2064, U+2066-2069, U+FEFF, U+E0000-E007F, plus U+061C and the soft hyphen. Test: `sanitizer_strips_bidi_zero_width_and_tag_characters` covers `safe_line` and the emitted `llms_full` title.

### WR-05: Advertised input bounds are not enforced

**Files modified:** `crates/vox-capability-registry/src/explain.rs`, `crates/vox-capability-registry/src/lib.rs`, `crates/vox-orchestrator-mcp/src/capability_tools.rs`
**Commit:** 9067c54ab
**Applied fix:** `resolve` checks the character count of the trimmed original input (scanning at most 257 characters) before lowercasing. 200 x U+0130 is now accepted and a 5 MB query is rejected without being copied. `rows_in_domain` enforces the new `MAX_DOMAIN_CHARS = 64` and echoes only the bounded trimmed value. Tests cover both in the registry and the MCP twin.

### WR-06: Hard-coded domain ids and duplicate vocabulary entries are never validated

**Files modified:** `crates/vox-capability-registry/src/index.rs`, `crates/vox-capability-registry/src/lib.rs`, `crates/vox-cli/src/commands/ci/capability_index/owner.rs`, `crates/vox-cli/src/commands/ci/capability_index/nodes.rs`, `crates/vox-cli/src/commands/ci/capability_index/join.rs`
**Commit:** 59f2748cf
**Applied fix:** `FALLBACK_DOMAIN`, `GUI_DOMAIN`, `SKILLS_DOMAIN`, `DOCS_DOMAIN` and `REQUIRED_DOMAINS` now live once in `vox-capability-registry`, replacing the two private `FALLBACK_DOMAIN` copies and three string literals. `validate_domains` requires all four ids and rejects duplicate ids. The check keeps the existing "skip when the vocabulary is empty" behaviour, which synthetic test fixtures rely on. The non-empty fixtures were extended with the three new ids. Tests: one per missing required id, and a duplicate-id test.

### WR-07: `vox features --domain skills|docs` prints nothing while `--json` lists the rows

**Files modified:** `crates/vox-capability-registry/src/card.rs`
**Commit:** 9ff87fea4
**Applied fix:** `render_features` gets `Skills` and `Docs` sections. The `—` placeholder now prints only when a domain has no rows at all. It no longer prints beside other rows. The per-domain counts line still has only cli/mcp/gui columns, because adding columns would change the `--json` shape. Test: `features_lists_skill_and_doc_rows`.
