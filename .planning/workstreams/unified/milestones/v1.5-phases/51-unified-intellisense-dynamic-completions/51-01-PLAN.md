# Plan 51-01: Context-Aware `vox-lsp::CompletionEngine`, `vox completions nushell`, and `nucleo` Multi-Source `discovery_suggest`

<objective>
Upgrade the three Rust completion backbones so every surface (LSP editors, Nushell CLI sessions, and the Axis GUI Terminal/Chat omniboxes) shares context-aware, fuzzy-ranked completions:
1. **`vox-lsp::CompletionEngine` (`crates/vox-lsp/src/completions.rs` & `server.rs`)**: Make `CompletionEngine::completions` context-aware using document text, cursor position, trigger character (`@` -> decorators only with docstrings; `:` -> `SURFACE_TYPE_NAMES`; general -> keywords + builtins + current-document AST symbols from `crate::symbols::extract_symbols`), and prefix filtering.
2. **Nushell CLI Completion Generator (`vox completions nushell`)**: Extend `vox completions <shell>` and `crates/vox-cli/src/command_catalog.rs` (`render_nushell_completions`) to emit valid Nushell `extern "vox" [...]` subcommand & flag definitions, and update `vox doctor` (`checks_standard/completions.rs`) to inspect `~/.config/nushell/config.nu` (and Windows `%APPDATA%\nushell\config.nu`).
3. **`nucleo`-Powered Multi-Source `discovery_suggest` (`crates/vox-gui/src/commands/discovery.rs`)**: Upgrade `match_catalog` and `discovery_suggest` to rank both subcommand groups and runnable leaves, `--long`/`-s` flags, terminal `/slash` commands (`vox_terminal_core::commands::CommandRegistry`), Nushell structured builtins (`!nu`), and `.vox` language surface symbols using `vox_cli::fuzzy::FuzzyMatcher` (`nucleo`), returning rich `Suggestion` records (`kind`, `category`, `signature`, `flags`).
</objective>

## Tasks

### Task 1: Upgrade `vox-lsp::CompletionEngine` with Cursor, Prefix, Trigger, and AST Symbol Context `[MODEL: ARGON-4]` `[SEQUENTIAL]`

<files>
- crates/vox-lsp/src/completions.rs
- crates/vox-lsp/src/server.rs
</files>

<action>
1. In `crates/vox-lsp/src/completions.rs`:
   - Add `pub fn completions_for_document(params: &CompletionParams, source: Option<&str>) -> CompletionList`:
     - Inspect `params.context.as_ref().and_then(|c| c.trigger_character.as_deref())` and the line prefix up to `params.text_document_position.position`:
       - If triggered by `@` or the token before the cursor starts with `@`: emit only `add_decorators` (with `Documentation::String` and `InsertTextFormat::SNIPPET`) filtered by any typed prefix after `@`.
       - If the line prefix before the identifier ends with `: ` or `-> `: prioritize `add_types` (`SURFACE_TYPE_NAMES`) + user-defined type/table/struct symbols extracted from `source`.
       - Otherwise: emit `add_keywords`, `add_builtins`, `add_types`, `add_decorators`, AND current-document AST symbols (`fn`, `component`, `actor`, `workflow`, `activity`, `table`, `type`) extracted by parsing `source` with `vox_compiler::lexer::lex` + `vox_compiler::parser::parse` + `crate::symbols::extract_symbols` (gracefully ignoring parse errors on incomplete buffers), filtered by the identifier prefix under the cursor.
   - Keep `CompletionEngine::completions(params: CompletionParams)` delegating to `completions_for_document(&params, None)` for backward compatibility, and update `crates/vox-lsp/src/server.rs` (`completion` handler) to pass the open document text from `self.documents` into `CompletionEngine::completions_for_document(&params, doc_text.as_deref())`.
2. Add unit tests in `crates/vox-lsp/src/completions.rs` proving:
   - `@` trigger returns decorator completions with documentation and excludes bare statement keywords,
   - `: ` type position prioritizes `SURFACE_TYPE_NAMES`,
   - Document containing `fn calculate_tax() -> int { 0 }` includes `calculate_tax` in completions.
</action>

<files>
- crates/vox-gui/src/commands/discovery.rs

<action>
1. In `crates/vox-gui/src/commands/discovery.rs`:
   - Extend `Suggestion` with `#[serde(default)]` fields (`kind: String`, `category: String`, `signature: String`, `score: u32`) while preserving `action_id`, `completion`, and `about` for full backward compatibility.
   - Upgrade `match_catalog` and `discovery_suggest` to use `vox_cli::fuzzy::FuzzyMatcher`:
     - When `typed` starts with `/`: rank `vox_terminal_core::commands::CommandRegistry::default().entries()` with `FuzzyMatcher`.

     - Otherwise: fuzzy-match across all `CommandCatalogEntry` paths, aliases, and `about` descriptions using `FuzzyMatcher`, boosting exact prefix matches above substring/fuzzy matches and returning both subcommand groups and runnable leaves with their argument signature preview.
2. Add unit tests in `crates/vox-gui/src/commands/discovery.rs` covering prefix match, `nucleo` fuzzy match (`"scntia rev"` -> `"scientia review"`), `--flag` completion, `/slash` completion, and `!nu` pipeline completion.
</action>
