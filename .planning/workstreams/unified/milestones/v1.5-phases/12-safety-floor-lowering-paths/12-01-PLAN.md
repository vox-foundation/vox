<objective>
Build the typed, level-independent safety floor (FLOOR-01, FLOOR-02) and enforce it at the single tool-call chokepoint.

Purpose: Every MCP client, the chat agent loop, and the autonomous runtime converge on `dispatch_tool_call`. Today the dangerous-tool gate keys only on the canonical tool name and four of six gated names are phantom; the real mutators are ungated. This plan adds `vox_orchestrator::oversight::floor` (pure classifier over the action only) and a small `floor_gate` hook so floored calls always park, bypassing `mode_auto_approves` and the allowlist.

Output: new `oversight` module, new `floor_gate.rs`, a ~6-line change to the gate block in `dispatch.rs`, a one-line registry-probe skip, two integration tests updated to approve their now-parked installs, and a where-things-live row.
</objective>

## Floor tables (authoritative for this phase — every executor uses these exact lists)

| Category (`id()`) | Name-floored tools (registered) | Arg rules |
|---|---|---|
| `HistoryRewrite` (`history_rewrite`) | `vox_snapshot_restore`, `vox_undo`, `vox_workspace_merge` (P12-D1) | `shell_command_history_rewrite`: `command` arg of `vox_skill_run` and reserved `vox_run_shell` |
| `PolicyGrant` (`policy_grant`) | `vox_add_approval_allowlist_entry`, `vox_config_set` (P12-D7, every call), `vox_trust_override` | `policy_file_write`: write-tool path resolving to a `Vox.toml` file, under `.vox/agents/`, or `contracts/orchestration/permission-modes.*` (Claude's discretion — these files feed oversight config) |
| `ExternalEffect` (`external_effect`) | `vox_deploy` (reserved, unregistered), `vox_scientia_publication_publish`, `vox_scientia_publication_submit_local`, `vox_plugin_install`, `vox_skill_install`, `vox_skill_add`, `vox_mesh_dispatch`, `vox_openclaw_gateway_call`, `vox_agent_gateway_call` (P12-D2) | none |
| `SecretsWrite` (`secrets_write`) | none (no secrets-write MCP tool exists — documented, P12-D3) | `secrets_path_write`: write-tool path whose resolved form matches `.env`, `.env.*`, `*.pem`, `*.key`, `id_rsa*`, `id_ed25519*`, a `.ssh` component, `.aws/credentials`, `.secrets`, `.netrc`, `.npmrc`; `secrets_config_key`: any `vox_config_set` object key (recursive) containing `token`, `secret`, `password`, `api_key`, `apikey`, `credential`, `private_key` (case-insensitive) |

Write tools for path rules: `FILE_WRITE_TOOLS = ["vox_apply_structured_edit", "vox_generate_code"]`, path arg keys checked in order `path`, `file_path`, `target_file`, `output_path` (mirrors `scope_guard::WRITE_TOOLS` / `PATH_ARG_KEYS`; parity test lands in 12-04).

Classification precedence (first match wins): SecretsWrite → PolicyGrant → HistoryRewrite → ExternalEffect. So `vox_config_set {"openai_api_key": …}` is SecretsWrite, `vox_config_set {"max_agents": 4}` is PolicyGrant.

Deliberately NOT floored (record rationale in the module doc comment): `vox_redo` (re-applies an op the human already allowed), `vox_news_approve` (records one maker-checker vote in VoxDb; live syndication requires two humans), `vox_publish_message` (in-process agent bulletin board), `vox_agy_delegate*` (returns a diff for human review), `vox_attention_reset` (P12-D5, level-governed), `vox_resolve_approval` (not floored, since floored parks must stay resolvable by humans; 12-07 instead refuses approve/modify of a floored park from in-process agent dispatchers, and the authenticated channel is FLOOR-04 / Phase 14 — see threat T-12-08), plain shell and delete (D3, level-governed).

Shell history-rewrite rule (`command_rewrites_history`, best-effort escalator, not a boundary): split on whitespace and `; & |`, skip leading `-c k=v` / `-C dir` pairs after `git` (as `git_exec::is_banned` does), then match: `git push` with any of `-f`, `--force`, `--force-with-lease[=…]`, `--force-if-includes`, `--mirror`, `--delete`, `-d`, a short-flag cluster containing `f` (e.g. `-uf`), a `+refspec`, or a `:ref` delete refspec; `git filter-branch`; `git filter-repo`; `git reset --hard`; `git rebase` unless the next token is `--abort|--continue|--skip|--quit`; `git commit --amend`; `git update-ref -d`; `git reflog expire`; `jj git push --deleted`; `jj abandon`; `jj op restore`; `jj op undo`; `jj undo`. Limits (aliases, `sh -c "$(…)"`, scripts, `GIT_*` env, `+` refspecs in git config, encodings) are documented in the module doc.
