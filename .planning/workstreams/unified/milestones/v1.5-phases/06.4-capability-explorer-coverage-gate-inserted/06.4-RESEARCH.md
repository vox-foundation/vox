### Locked Decisions
- **D-01:** The gate unit is the top-level CLI group (88 groups today; 82 are tier `none` in `contracts/gui/surface-registry.v1.yaml`). Per-op gating is rejected: it would need ~1000 exemptions.
- **D-02:** The `generic_form` tier is derived, not declared. A group is `generic_form` automatically when its verbs are compiled into the GUI build and reachable through the Catalog form (the index row's `catalog_form`). A group whose verbs are feature-gated and not compiled in stays `none`. No hand-set `generic_form` values in the YAML (the `RepresentationTier::GenericForm` enum arm already exists in `gui_surface_registry.rs`). Reversibility: costly.
- **D-03:** The Explorer badges are exactly four: Dedicated surface (`live_backend` or `curated_decorator`), Generic form, CLI-only (not reachable in the GUI: not compiled in, or exempted), MCP-only / orphan (a backend capability with no CLI or GUI path).
- **D-04:** Exclude the `surface` node kind from the orphan metric, with the reason recorded in the generator and docs. A `surface:` node has no callers by design, so `orphan_backend` there is a classifier artifact (all 32 surface nodes flagged only for that reason). Disposition applies to backend kinds only (`cmd`, `tool`, `cli-command`). Do not change `vox-graph-reader`'s classification semantics for this; apply the exclusion where the snapshot is consumed or generated.
- **D-05:** Scope is the nodes the graph flags, in the kinds it covers. Today that is 2 MCP tool nodes: `tool:vox_mesh_nodes` (`dead_end`) and `tool:vox_populi::inference_PROFILE` (`orphan_backend`, a templated placeholder-looking name). Do not widen the graph ingest to all ~342 MCP tools in this phase.
- **D-06:** No exemptions for orphans or dead-ends: fix or delete. Every flagged backend node must be surfaced or deleted. Stale artifact of the graph ingest (bad edge, placeholder): repair the ingest/source so it is not emitted; real dead code: delete it; real tool with no GUI path and cheap to wire: surface it. ## Summary

The phase is mostly a join-and-projection problem on top of 06.2/06.3 machinery. Everything the gate and the Explorer need already exists as data: the registry YAML, the operations catalog (via `capability_index::inputs`), the `catalog_form` rule in `nodes.rs`, the committed coverage snapshot, the chunked TS emitter and the `RatchetSpec` pattern. New code is (a) one pure derivation function plus a gate module (Rust), (b) a group-rollup emitter, (c) an ingest repair in `vox-graph-reader`, (d) the Explorer view with a pure model file, and (e) wiring/tests. No new packages and no new workspace crate edges are needed.

Five findings change or sharpen CONTEXT and need the planner's (and in two cases the user's) attention; they are listed first in "Findings That Affect CONTEXT Decisions". The most consequential: the "88 groups" figure is the index's count, the registry/gate universe is **90** (two `dei`-gated groups, `attention` and `safety`, have no catalog rows); `catalog_form` as written mis-reads the two `script-execution` rows (a *default* vox-cli feature) as uncompiled; and the registry's legacy `ludus`/`oratio` rows keep the Gamify and Voice surfaces from being credited to the real CLI groups `gamify`/`speech`.

**Primary recommendation:** Add one pure `in_gui_build(status, feature_gate)` predicate (default-feature aware, pinned to `crates/vox-cli/Cargo.toml` by a test), derive the tier once at registry resolution so TS registry, index rows and the gate all see it, put the gate in a new sibling module (the registry file would pass the 500-line God-Object error), and fix the two graph nodes by repairing the ingest (registry-backed tool nodes) rather than touching the GUI source or the snapshot.

### Pattern 1: One shared "compiled into the GUI build" predicate
**What:** a pure fn in the gate module, `in_gui_build(status: &str, feature_gate: Option<&str>) -> bool`: `status == "active"` and every token of the gate (split on `|`, `+`, `,`; AND, conservative) is in a `GUI_BUILD_FEATURES` const equal to vox-cli's `default` features. `nodes.rs:78` and the gate both call it.
**Why:** today's inline rule is correct only because no other default-feature gate exists in the data; and the claim "compiled into the GUI build" is otherwise unfalsifiable.
**Pin it:** a test reads `crates/vox-cli/Cargo.toml` (`CARGO_MANIFEST_DIR`, as `repo_root()` does in the existing tests) and asserts `GUI_BUILD_FEATURES` equals its `default = [...]` array; a second test (default features only) asserts every catalog row with `in_gui_build == true` appears in `command_catalog::build_catalog()` entries. That ties "derived" to ground truth instead of to the YAML.
**Data check (computed this session):** gates present in the index: `ars, cloud, coderabbit, codex|stub-check, dei, extras-ludus, gpu, gpu+mens-dei, gui, live, ludus-hud, mcp-server, mens-base, mens-base|gpu, mens-dei, oratio, populi, script-execution, stub-check`. Only `script-execution` is a default feature.

### Pattern 2: Resolve the effective tier once, upstream of every consumer
`load_registry` returns the raw YAML (hand tiers). Add `resolve_effective(reg, ops) -> SurfaceRegistry` and call it (a) in `gui_surface_registry::run` for the TS and report, and (b) in `inputs::load` so `nodes::gui_ref` (`nodes.rs:34-41`) writes the effective tier into index rows. **Never** pass the resolved registry to `serde_yaml::to_string` in the `--write` path (`gui_surface_registry.rs:219`) - that would bake derived tiers into the YAML and violate D-02. Reject a hand-set `generic_form` in the YAML (drop it from the schema enum at `surface-registry.v1.schema.json` - zero rows use it today - or fail in `load_registry`); keep the Rust enum arm (it is what the derived value is expressed in).

### Pattern 3: Gate = pure functions with injected "today"
```rust
// Names are the planner's; shape is the contract. Tests first (tdd-guard needs same-file tests).
pub(crate) struct Exemption { pub group: String, pub owner: String, pub reason: String, pub review_by: String }

pub(crate) fn gate_violations(
    top_level: &BTreeSet<String>,
    effective: &BTreeMap<String, RepresentationTier>, // group -> effective tier
    exemptions: &[Exemption],
    today: chrono::NaiveDate,
) -> Vec<String>;
// FAIL: group effective==None and not exempt            ("unrepresented ... add a surface or an exemption")
//       exemption.group not in top_level                (unknown group)
//       exemption.group effective != None               (stale: now represented)
//       review_by < today                               (past review_by)
//       duplicate exemption group / unparsable date / empty owner or reason
// WARN (::warning, not fail): review_by within 30 days
```
`today` comes from `chrono::Utc::now().date_naive()` in `run`, overridable with `--today` for reproduction; unit tests pass a literal date. `ssot-drift` already uses the wall clock for a doc-staleness warning (`docs.rs:194,220`), so this is not a new class of nondeterminism, but an expiring entry is the only thing in the gate that can turn red without a code change - that is its purpose; the 30-day warning is the mitigation. Do not use the HEAD commit date: on PR merge refs it is "now" anyway and it adds a git dependency to `ssot-drift`.

### Pattern 4: Ratchets - reuse `RatchetSpec`, add a direction
`ratchet.rs` is set-based: `check(live, baseline, spec)` fails on ids not in the baseline or `live.len() > max_unresolved`; `tighten` is removal-only and bootstraps from `live` when the file is absent. Reuse as is for:
- **exemption ratchet**: ids = exempt group names (adding an exemption also requires editing the baseline: a visible, user-authorized edit - this is what stops the YAML alone being a rubber stamp);
- **orphan ratchet**: ids = snapshot entries with `status` in `orphan_backend|dead_end` and kind not in `EXCLUDED_KINDS`; baseline `{ "max_unresolved": 0, "unresolved": [] }`.

`RatchetSpec.ids` is `fn(&CapabilityIndex)` today (`ratchet.rs:17`); the orphan ids need the snapshot (the index only carries snapshot *meta*, and the false-positive node has no index row), so change it to take a small ctx struct `{index, snapshot}`; four existing call sites (`mod.rs:73-78,129-140`, tests) adapt mechanically.
- **dedicated floor**: opposite direction. `check_floor(live, baseline)` fails when any baseline member is missing from `live` (names the lost groups); `tighten_floor` may only *add* members (raising the floor is the safe direction). Use a set, not a bare count, so swapping one dedicated group for another cannot hide a loss and the error names the group. Definition: groups in `top_level` whose registry tier is `curated_decorator|live_backend` - 10 today: `commands, config, memory, mens, model, populi, repo, research, scientia, skill`.

Flags: `gui-surface-registry --tighten` (new, `conflicts_with = "write"`) tightens the two group baselines; `capability-index --tighten` (existing) gains the orphan spec. Bootstrap order: check mode errors on a missing baseline (`mod.rs:51-64`), so the first plan task must create all three files via `--tighten` from a state that is already green.

### Anti-Patterns to Avoid
- **Writing derived tiers back to the YAML** (see Pattern 2).
- **A second definition of "compiled in"**: the gate, `nodes.rs` and the Explorer must call the same predicate / read the same emitted field.
- **Treating `tool:` / `cmd:` ingest output as ground truth for MCP reachability**: it only sees GUI-wired calls.
- **`onClick={() => {}}` for the `aria-disabled` Open form button**: `surfaceHonesty.guard.test.ts` scans `src/components/surfaces/**` for exactly that regex (`honestyScan.ts:14-15`) and for "not implemented/available/wired" prose (`:11-12`); omit the handler when disabled. - **New literal `invoke('invoke_mcp_tool', { tool: '...' })` or `callTool('vox_...')` in Explorer code**: each creates a `tool:`/`cmd:` edge the next snapshot refresh must resolve.

## Common Pitfalls

### Pitfall 1: Stale `vox` binary refuses `vox ci`
**What goes wrong:** `vox ci` hard-fails with "installed vox is stale: built at commit ..." after any commit (`freshness.rs:217,247`). `target/debug/vox` in this worktree is dated Oct 10 23:48; HEAD is `eb42e59b2` (2026-10-12).
**How to avoid:** background `cargo build -p vox-cli` after the last commit before running any `target/debug/vox ci ...` (06.3-12 hit this). Do not use an override flag. Never foreground a cargo build (memory: feedback-never-block-foreground-on-cargo).

### Pitfall 2: Derived tier leaks into the YAML or is computed twice
See Pattern 2. Test: run `gui-surface-registry --write` twice and `git diff` the YAML -> unchanged apart from the hand edits; a unit test asserts the serialized registry contains no `generic_form`.

### Pitfall 3: `gui_surface_registry.rs` and `emit.rs` size
The registry file is 367 lines; the governance God-Object limit is Error at 500 non-blank lines (`docs/agents/governance.md:70`). Put the gate in `gui_coverage_gate.rs`. `emit.rs` is already 708 lines (with tests); add the group emitter in `groups.rs`.

### Pitfall 4: New clap flags are in a different crate and two dispatch sites
`GuiSurfaceRegistry { write }` is defined in `crates/vox-cli-ci/src/cmd_enums.rs:103-107` and matched in `ci/run_body.rs:117` and `ci/providers.rs:115`. Flags are not mirrored into the operations catalog or `command-registry.yaml` (the existing `capability-index --tighten` is absent from both), but they are documented by hand in `docs/src/reference/cli.md`. D-13's "no new catalog op" is satisfied. Avoid a new env var (see Alternatives).

### Pitfall 5: ssot-drift ordering and the autoregen bot
`run_ssot_drift` runs `gui_surface_registry` before `capability_index` (`docs.rs:624-634`); keep that order so the effective tier is computed from the same committed YAML. The bot re-runs generators with `--write` (AGENTS.md); ratchet baselines are written only by `--tighten` (docs/cli.md:216), so the bot cannot raise them. A new exemption therefore needs the YAML entry, the baseline edit and user sign-off - by design.

### Pitfall 6: TS2590 and artifact size
Keep the `ROWS_n` chunking, keep row objects uniformly shaped (no optional fields on one chunk only), and run `pnpm --dir crates/vox-gui/ui typecheck` after the emitter change (06.3 gate 2 passed with `tsc --noEmit`). The lazy chunk was 707 KB raw / 62 KB gzip in 06.3; the three new row fields add roughly 100 KB raw [ASSUMED]. The artifact must stay out of the entry chunk: the only runtime importer is `capabilityIndexLoader.ts`, and a static-import guard test exists (06.3-03). Do not import `CAPABILITY_GROUPS` statically in `ExplorerView`.

### Pitfall 7: vox-gui is excluded from PR CI; only the `ui` lane covers TS
Rust changes here are in vox-cli / vox-cli-ci / vox-graph-reader (covered by `linux`/`tests`). The `ui` lane (typecheck + vitest + Playwright) is required on PRs touching `crates/vox-gui/**`, and CI runs the whole Playwright suite with `workers: 1`, `retries: 2` and a 12-minute cap (`ci.yml:245-263`), so the new spec must stay light (about 19 screenshots, one axe pass per theme, no long waits).

### Pitfall 8: Playwright specifics
`reuseExistingServer: !process.env.CI` on port 1420 - check `lsof -i :1420` before running; a stray dev server serves stale code. The lazy index is `import('../generated/capabilityIndex.generated')`, so under the vite dev server the request path contains `capabilityIndex.generated` - `page.route('**/capabilityIndex.generated*', ...)` can delay (loading shot) or `route.abort()` (degraded shot); the loader resets `pending` on failure so Retry works (`capabilityIndexLoader.ts`). No existing spec uses `page.route` or `page.clock`; `page.clock.setFixedTime` (Playwright >= 1.45) for the overdue state [ASSUMED: API availability in ^1.62]. `review-bundle/` is gitignored; screenshots are evidence, not committed. Scope axe with `.include(...)`; the only existing AxeBuilder use is the opt-in review capture (`VOX_REVIEW_CAPTURE=1`).

### Pitfall 9: Guard tests that new UI/nav code trips
`lexicon.test.ts` (lexicon entry + label agree with registry), `navigation.test.ts`, `Sidebar.test.tsx:16`, `englishVocabulary.test.ts` (NAV_LABELS keys; code-name regex applies to LEXICON English values), `statusColorTokens.test.ts` (no `text-(amber|rose|red|emerald|cyan)-NNN` classes or raw hex in scanned files - the old `CoverageView` used `text-cyan-300`/`text-emerald-300`; the new badges must use `--color-status-*`), `travertineContrast.test.ts`, `surfaceHonesty.guard.test.ts`. ### Known Threat Patterns
| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Injection into generated TS via exemption `reason` / group names | Tampering | `ts_str` (JSON string escaping); never `format!("'{x}'")` (the registry's `opt()` is not sufficient for free text) |
| Hidden-text / markup in `reason` reaching LLM-facing files | Tampering | Do not emit exemption text into `llms*.txt` / `vox-docs.json`; if ever shown there use `safe_line` (`emit.rs:50-57`) |
| XSS in the Explorer from exemption/summary text | Tampering | Render as React text nodes only; no `dangerouslySetInnerHTML` |
| Gate bypass by editing only the YAML | Elevation | Baseline ratchets + user-authorized seed; floor set is by name |
| Poisoned graph snapshot hiding an orphan | Tampering | Snapshot is a committed, reviewed file; M6; document that the check reads the committed snapshot only |
| Explorer executing a verb | Elevation | UI-SPEC: read-only, `run` outcome mapped to `form`; no `executeCommand` import in Explorer files (assert in a test) |
