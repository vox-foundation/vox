<objective>
Close the single Phase 2 verification gap, CR-01 (SC1 / IDX-01). Today a reindex treats an incomplete or empty corpus walk as the whole tree and prunes the Library while reporting success. After this plan:
- the walker reports its errors,
- the indexer refuses to prune on an incomplete walk or on an empty walk while rows are stored,
- the call fails outright when `docs/src` is missing.

Each guard is proven by a regression test and by a mutation run.

Purpose: SC1 says a delete or rename prunes its rows "and only those". A partial walk must never be read as "everything else was deleted".

Output:
- fallible `walk_corpus`
- guarded `index_library`
- three integration tests and two walker unit tests
- a mutation-proof record in the SUMMARY

Gap-text reconciliation (deliberate; this is not a scope cut): the verifier's `missing` list also says to skip orphan-embedding cleanup and the Tantivy rebuild on an incomplete walk. This plan gates only the prune. The other two steps are left alone, for these reasons:
- Once prune is skipped, neither step can remove live data:
  - `prune_orphan_kb_chunk_embeddings` deletes only vectors whose chunk no longer exists. Its existing test `prune_orphan_kb_chunk_embeddings_keeps_live_and_foreign_vectors` proves this.
  - The rebuild is built from the un-pruned DB rows.
- Gating them would create new defects:
  - Skipping the orphan cleanup would leave orphaned vectors from this run's chunk replacements. That breaks SC1's "after any reindex no `embeddings.source_id` is orphaned".
  - Skipping the rebuild would leave docs edited in the same run unsearchable, with no later self-heal (the WR-04 failure mode).
- Task 1's test asserts both directions:
  - protected vectors survive;
  - an edited doc stays searchable.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| file system ↔ indexer | The corpus walk reads a working tree whose completeness the indexer cannot assume (permissions, vanished dirs, wrong root) |
| indexer ↔ vox-db Library rows | Prune is the only destructive write. It must act only on a walk known to be complete |
| errors_json ↔ vox_kb_status callers | Walk-error text is persisted and served by the status tool |
