# Plan 53-01: Classified Candidate Handoff & 1-Click Candidate/Session → `publication_manifests` Promotion

<objective>
Close Gap 2 from [`scientia-publication-and-deep-research-claims-vs-reality-audit-2026.md`](../../../../docs/src/architecture/scientia-publication-and-deep-research-claims-vs-reality-audit-2026.md):
1. **Rich Candidate Classification in `discovery_bridge.rs` (`crates/vox-research-shim/src/research/discovery_bridge.rs`)**: Replace the hardcoded `EventCandidateClass::Other`, `title_hint: None`, and `novelty_evidence_bundle_id: None` in `finding_candidate_from_research_result` with deterministic classification (`BenchmarkDelta`, `ArchitectureDecision`, `ReproducibilityAudit`, `CorpusFinding`, `VerificationProof`, `Other`) and a clean `title_hint` extracted from the research report H1 or query.
2. **1-Click / 1-Command Candidate & Research Session Promotion (`promote_candidate_to_publication`)**: Implement `promote_candidate_to_publication` in `crates/vox-orchestrator-mcp/src/gui_ops/scientia.rs` (`POST /api/v2/scientia/candidates/:id/promote`), Tauri command `scientia_promote_candidate` in `crates/vox-gui/src/commands/scientia.rs`, and CLI `vox scientia candidate-promote --id <candidate_or_session_id> [--venue <venue>]`. Promotion creates a canonical `publication_manifests` row (`pub-<slug>-<short_id>`), updates `scientia_discovery_inbox.publication_id` and `scientia_finding_candidates.status = "promoted"`, and seeds `scientia_claims` from the research session's verified claims so `DiscoveryReview.tsx` and `ArchivePanel.tsx` never fail with `"not_found"`.
</objective>

<files>

- crates/vox-cli/src/commands/scientia_cli.rs

<action>
1. In `crates/vox-orchestrator-mcp/src/gui_ops/scientia.rs`:
   - Add `POST /api/v2/scientia/candidates/:id/promote` (`promote_candidate_to_publication`):
     - Accept `:id` as either a `candidate_id` (`"finding-..."`), a `research_session` ID (`"res-..."` / UUID), or an inbox item ID.
     - Load the candidate (`state.db.get_scientia_finding_candidate`) and/or research session (`state.db.get_research_session`).
     - Construct a canonical `publication_id` (`pub-<slug>-<short_hash>`), abstract text, body markdown, and `metadata_json` containing `scientia_evidence` (`epistemic`, `novelty`, `signal_to_noise`, `source_session_id`, `candidate_id`).
     - Persist the manifest via `state.db.upsert_publication_manifest`, seed extracted claims via `state.db.insert_scientia_claim` for each verified claim in the research session, and update any matching `scientia_discovery_inbox` row so its `publication_id` points to the new `publication_manifests` row.
     - Return `{ "ok": true, "publication_id": publication_id, "claims_seeded": count, "stage": "draft" }`.
2. In `crates/vox-gui/src/commands/scientia.rs`:
   - Add `#[tauri::command] pub async fn scientia_promote_candidate(state: State<'_, AppState>, candidate_id: String, venue: Option<String>) -> Result<Value, String>`.
3. In `crates/vox-cli/src/commands/scientia_phase_handlers.rs` & `scientia_cli.rs`:
   - Add `vox scientia candidate-promote --id <id> [--venue <venue>]`.
4. Add unit/integration tests in `crates/vox-orchestrator-mcp/src/gui_ops/scientia.rs` verifying that promoting a finding candidate creates a `publication_manifests` row that `get_publication_worthy` and `DiscoveryReview` can immediately load.
</action>
