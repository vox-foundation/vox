# Phase 06.3 Plan 07: Find UX Summary

**Cmd/Ctrl+K now finds every capability kind from the index: a Best match row (moved, not copied) on top, a capped Tools & crates facet for MCP tools and crates, deduplicated surfaces/commands/docs/skills, kind icons with CLI/GUI/MCP and domain chips, honest 'N of M' counts, and an accessible dialog structure.**

## Accomplishments

- D-05: index surface and cli rows replace the federated surface and command rows; docs and skills from the index only fill gaps (dedupe by `docKey` and by installed skill name); settings, policies, installed skills, agents, on-screen, graph and backend hits keep their own sources; backend command hits equal to an index cli path are dropped.
- D-08/D-08a: Best match facet, `FACET_CAP = 6` per facet with `total`; Tools & crates facet; when capped it shows "N of M" next to the heading and one muted line "Keep typing to narrow, or use > (commands) / # (crates)".
- D-09/D-10: icons, chips, `#`/`#L3`. In the real browser `#L3` shows 52 layer-3 crates as "Best match + Tools & crates 6 of 52".
- Omnibar a11y: `role="dialog"` `aria-modal` `aria-label="Command palette"`, input `aria-label="Search Vox"`, `aria-current` on the keyboard row, one polite `role="status"` region, focus restored to the previously focused element on close (captured during render, before the autofocused input takes focus).
- `useFederatedSearchIndex` drops the `getCatalog` + `getActionManifest` effect (two IPC calls per palette mount); `buildFederatedIndex` keeps its optional inputs and tests.
- `contracts/gui/omnisearch-index.v1.yaml` updated per kind (`capability_index` x7, new `mcp_tool` and `crate` kinds).
