## User Constraints (from CONTEXT.md)

### Locked Decisions
- **D-01:** Selecting a CLI verb **opens the Catalog form, prefilled, with an explicit Run button, by default**. It runs directly from the palette only when the op is declared read-only (`side_effect_class: read_only`) AND has no required arguments. *Reversibility: costly — users learn the Enter behavior.*
- **D-02:** **Backfill `side_effect_class: read_only`** in `contracts/operations/catalog.v1.yaml` for verbs we can verify are read-only (status, list, show, explain, features, doctor, and similar). Apply each by checking the handler, never by name alone. Anything unclassified (null) is **treated as side-effecting**. Add the classification to the 06.2 capability index row. Ratchet it: the count of null side-effect classes on CLI ops may only fall, following the 06.2 owner-ratchet pattern.
- **D-03:** **The backend enforces a confirmation token for destructive ops.** `execute_command` (`crates/vox-gui/src/commands/execute.rs`) must refuse an op whose catalog `side_effect_class` is destructive or irreversible unless the call carries an explicit `confirmed: true`. The UI sets that flag only after a confirm dialog. Unknown or unclassified ops are not blocked by the backend. The UI default from D-01 covers them. The backend reads classification from the bundled capability index (`vox-capability-registry`, already a dependency path), not from the UI. *Reversibility: costly — changes an IPC contract other callers use.*
- **D-04:** **Run output** is a short toast with the exit status, plus the full output in the existing Console surface. This mirrors the `/audit` pattern in `App.tsx` (~line 1500). Do not stream output inside the palette.
- **D-05:** **The capability index replaces the overlapping federated sources.** The `surface`, `command`, `skill` and `doc` rows come from `capabilityIndex.generated.ts`. `setting`, `policy`, `action`, agents, on-screen hits, graph and backend hits stay as their own sources. Update `contracts/gui/omnisearch-index.v1.yaml` to record the new source per kind. No row may appear twice from two sources.
- **D-06:** **Load the index lazily on the first ⌘K**, via dynamic `import()`, cached in memory afterwards. The startup bundle must not grow by the 514 KB artifact. Show a brief loading state on the first open. *Reversibility: reversible.*
- **D-07:** **Rows with no direct GUI action** (MCP tools, crates, and capabilities without a surface) open an **explain card in a drawer**. The card shows the same groups as `vox explain`: equivalents, location, status, related, docs. It offers "Open form" for CLI ops, "Copy MCP name" for MCP tools, and "Open docs" when a docs link exists. Render it from the index data in TS. Do not shell out to `vox explain`.
- **D-08:** **Keep the existing capped facet groups** (Surfaces, Commands, Docs, On screen, Graph; `FACET_CAP`), fed from the index per D-05. Add one **top "Best match" row**: the single best hit across all facets.
- **D-09:** **Each result row shows a kind icon plus chips** for the interfaces it's reachable through (CLI · GUI · MCP), the domain, and its keybind chord if it has one.
- **D-10:** **Add a `#` prefix mode** for crate and layer rows, alongside the existing `>` commands, `@` agents and `/` skills (`parsePaletteQuery` in `components/layout/paletteSources.ts`).
- **D-11:** A bare **`?` opens the shortcut sheet only when focus is not in** an input, textarea or contenteditable. It is also available as a palette action and through a new registry binding (`Mod+/`).
- **D-12:** The sheet lists **all keybinds from the registry** (`lib/keybinds.ts`, `ACTION_REGISTRY` + `DEFAULT_BINDINGS`), showing the user's current rebinds as they're set. It is generated from the registry, not hand-written.
- **D-13:** **Every registry action is a palette row** labelled with its current chord (for example "Toggle sidebar ⌘B"). Selecting the row runs the action. Use the existing `action` federated kind. A new registry entry appears automatically.

## Summary

The palette work is mostly a **TS wiring job on top of a generated artifact that is thinner and more broken than CONTEXT assumes**. Four premises in CONTEXT do not hold and change the plan shape (see §Corrections). The most urgent is that `pnpm typecheck` already **fails** on the 06.2 artifact (TS2590, "union type too complex", reproduced this session) and the hosted `ui` lane runs `pnpm typecheck` on any PR touching `crates/vox-gui/`. The generator must emit the 1544 rows in chunks of <=~250; this is a one-function change in `emit.rs::generate_ts` and is the first task of the phase.

The second structural fact: the TS projection carries only 12 fields. It has no `equivalents`, `tier`, `status`, `side_effect_class`, `catalog_form`, `source_path` or `product_lane`, so D-07 (explain card with equivalents/location/status/related), D-09 (chips) and D-01 (read-only run) cannot be built from it. The Rust `IndexRow` already has every field; the work is extending `generate_ts` (and its test), not adding data. `side_effect_class` is populated for only 13 of 998 CLI rows (4 `read_only`, 4 `none`, 4 `writes_files`, 1 `destructive`), so D-01's direct-run path is dead until D-02's backfill lands, and D-03's backend gate currently covers exactly one CLI verb (`vox plugin remove`).

The D-03 gate can be built with **no new crate edge**: `vox-gui` already depends on `vox-cli`, which already depends on `vox-capability-registry` and embeds the index at compile time (`bundled_index()`). Put the decision function in `vox-capability-registry` (fast hosted tests), expose a thin wrapper in `vox-cli::command_catalog`, call it from `execute.rs`. Note that hosted PR CI **excludes `vox-gui` from `cargo check`/test** (`ci.yml:87-95`), so every line of gate logic that can live outside `execute.rs` must, so the gate is tested on PRs. The gate must look past `path` into `__argv` subcommand tokens or it is trivially bypassed.

**Primary recommendation:** Sequence as (1) generator fixes + ratchet + backfill, (2) Rust gate + `execute_command` contract, (3) pure-TS loader/ranker/facet engine with tests-first, (4) Omnibar UI (rows, chips, Best match, `#`, explain drawer, prefill, confirm dialog), (5) shared keybind store + `?` sheet + action rows, (6) Playwright spec + screenshots + docs/contract updates. Local verification is fully workable: `pnpm install --frozen-lockfile --offline` took 1.5 s, vitest runs in ~3 s, Playwright chromium runs locally.

### Pattern 1: Lazy index module with a single importer
**What:** one memoized loader; everything else takes rows as props/params so tests inject a small fixture.
**When to use:** always — a second static importer (even `import { CAPABILITY_DOMAINS }`) drags the 470 KB into the main chunk. `import type {...}` is erased and safe.
```ts
// Source: vite dynamic-import code splitting, verified by build in this session
type Mod = typeof import('../generated/capabilityIndex.generated');
let p: Promise<Mod> | null = null;
let loaded: Mod | null = null;
export function loadCapabilityIndex(): Promise<Mod> {
  return (p ??= import('../generated/capabilityIndex.generated').then((m) => (loaded = m)));
}
export const getLoadedCapabilityIndex = () => loaded;
```
**Verified:** a scratch `vite build` of `document.onclick = () => import('./gen')` emitted `gen-*.js 470.29 kB │ gzip: 52.82 kB` as a separate chunk plus a 1.97 kB entry. No code in `src/` imports the artifact today (grep: zero importers), so there is no static-import regression yet.

### Pattern 2: Tests inject the loader
`Omnibar.test.tsx` mocks `useFederatedSearchIndex` and `useContentManifest` with `vi.mock` (`Omnibar.test.tsx:16-65`). Do the same for the new hook with a ~10-row fixture; never import the 514 KB module in unit tests.

### Anti-Patterns to Avoid
- **Static import of the generated module anywhere** (defeats D-06).
- **Scoring with Jaro-Winkler alone on partial queries.** Measured on the real index: query `vox fabrica fmt` gives 755 rows >= 0.75 because every `vox ...` invocation shares the prefix; `fmt` gives only 2. JW is a typo fallback, not the primary matcher (F-9).
- **Reading classification from the UI.** The gate decides in Rust from the embedded index; the UI flag only records consent.
- **Hand-editing `capabilityIndex.generated.ts`** or `capability-index.v1.json`.

## Findings by question (with evidence)

### F-1 Typecheck blocker and the fix (Q2)
Reproduced: `pnpm typecheck` → `TS2590` at `capabilityIndex.generated.ts(37,57)` (the `= [` of `CAPABILITY_INDEX`). Experiments on scratch copies: single array fails (also fails with `as CapabilityIndexEntry[]`); **chunked arrays pass at 250, 400 and 800 rows per chunk**: `const C0: CapabilityIndexEntry[] = [...]; ... export const CAPABILITY_INDEX: CapabilityIndexEntry[] = [...C0, ...C1, ...];`. Adding fields (F-2) makes each literal bigger, so use 200-250 per chunk for margin and add a typecheck-based guard (a vitest cannot catch TS2590; the CI `ui` job's `pnpm typecheck` is the guard, so run it locally after regenerating). Root cause is TS inferring a union over 1544 object-literal types; vite/esbuild and vitest do not typecheck, which is why 06.2's vitest/vite checks passed [VERIFIED: vite build of the same file succeeded].

### F-2 Fields to add to `generate_ts` (Q8, Q4, chips)
Current emitter: `crates/vox-cli/src/commands/ci/capability_index/emit.rs:227-290`; test `generate_ts_is_typed_and_deterministic` at `:576-599` pins needles. Add (all from `IndexRow`): `equivalents: string[]`, `tier: string|null`, `status: string|null`, `sideEffect: string|null` (from `side_effect_class`), `lane: string|null` (`product_lane`), `catalogForm: boolean` (`gui.catalog_form`), `source: string|null` (`source_path`). Keep `docs` as first path (card also needs the origin? `vox explain` prints every doc with origin; first doc is enough for "Open docs"). Related rows are best computed client-side by mirroring `card.rs:184-215` (same domain first, then same non-surface owner crate, sort `(!same_domain, id)`, limit 5) so the TS stays small. Size impact: current gzip of the module is 54,295 bytes; expect roughly +5-8 KB gz. Regenerate with `vox ci capability-index --write` (needs a built `vox`; `target/debug/vox` exists but predates the change).

### F-3 `execute_command` gate: callers, lookup, zero-edge design (Q5)

| `App.tsx:1504` `/audit` (`['check']`) | fixed | none |
| `CommandCardsView.tsx:58` | `card.path` | none |
| `RepositoryView.tsx:23` (`status`, `check workspace`, `check`, `diff`) | fixed | none |
| `PublicationsView.tsx:126,140` (`scientia claims`, `publication-venue-recommend`) | fixed | none |
| `ClaimsView.tsx:66` | caller-supplied `path` | none |
| e2e mocks `tauriMock.ts:442`, `operatorShellMock.ts:194`, `tauriMockVariants.ts:51` | ignore args | add a `confirmation_required` case for the new spec |
Tauri deserialization: a missing `Option<T>` key becomes `None` [VERIFIED: ~/.cargo/registry/src/*/tauri-2.12.1/src/ipc/command.rs:146-157, `None => visitor.visit_none()`], so adding `confirmed: Option<bool>` is source- and wire-compatible with every existing caller. Tauri expects camelCase keys (`confirmed` is single-word).

**Lookup without a new edge.** `vox-gui` → `vox-cli` exists; `vox-cli/src/command_catalog.rs:133,146` already calls `vox_capability_registry::load_document` / `implicit_cli_capability_id`; `bundled_index()` is `include_str!`'d at compile time (`index.rs:12-13,148-156`), unlike `action_manifest.rs::read_operation_catalog`, which reads `contracts/operations/catalog.v1.yaml` from `resolve_repo_root_for_ci()` **at runtime** (fails or empties in a packaged app without the repo). ## Common Pitfalls

### Pitfall 1: Shipping the lazy chunk but failing the `ui` lane on TS2590
**What goes wrong:** vitest, vite build and Playwright all pass; hosted `pnpm typecheck` fails. **Avoid:** chunk the array in `generate_ts` (F-1) and run `pnpm typecheck` locally after regenerating. **Warning sign:** any TS2590 on the generated file.

### Pitfall 2: A second static importer silently undoes D-06
**Avoid:** one loader module; add a vitest guard that greps `src/**` (excluding the loader, generated file, tests) for `capabilityIndex.generated` and fails on a non-`import type` / non-dynamic import. Model it on `guards/ipcBoundaries.test.ts`.

### Pitfall 3: Gate bypass through `__argv`
`execute_command(['plugin'], {__argv:['remove','x']})` runs a destructive subcommand with a harmless `path`. The gate must evaluate the effective command (path plus leading non-flag argv tokens). Mutation-prove it.

### Pitfall 4: Gate not covered by PR CI
`vox-gui` is excluded from hosted `cargo check`/test (`ci.yml:87-95`); a compile error in `execute.rs` surfaces only in nightly. Keep `execute.rs` edits tiny, and compile it once locally in the background. Local compile needs the sidecar and `ui/dist` (build.rs panics otherwise, `build.rs:92-126`): stub files at `target/release/vox-<triple>`, `target/release/vox-ml-cli-<triple>` plus `ui/dist/index.html` with `VOX_GUI_SKIP_SIDECAR_AUTOBUILD=1` should satisfy `check_sidecar_binaries` + tauri-build [ASSUMED: not compiled this session]; the alternative is `vox run scripts/gui-build.vox` (builds a release vox, heavy). Both stub paths are gitignored (`git check-ignore` confirmed for the sidecar path and `ui/dist`).

### Pitfall 5: Prefilled form that drops its values
The `__argv`-wins bug (F-3). Fix before relying on prefill, or the "prefilled Catalog form" runs with no args.

### Pitfall 6: Stale chords in the sheet
Settings and App hold separate keybind state (F-11). Use one store.

### Pitfall 7: Replacing doc/skill sources wholesale
Loses 600+ doc pages and the skill-deploy action (C-4, F-5).

### Pitfall 8: Existing specs break on Best match

```rust
impl CapabilityIndex {
    /// First `cli.*` row on the path `argv` walks that is classified `destructive`.
    pub fn confirmation_required(&self, argv: &[String]) -> Option<&IndexRow> {
        let mut path: Vec<&str> = Vec::new();
        for tok in argv.iter().take_while(|t| !t.starts_with('-')) {
            path.push(tok);
            let id = format!("cli.{}", path.join("."));
            if let Some(r) = self.row(&id) {
                if r.side_effect_class.as_deref() == Some("destructive") { return Some(r); }
            }
        }
        None
    }
}
```

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Accidental destructive run via Enter | Tampering | D-01 default-to-form, backend gate, confirm dialog |
| Gate bypass: destructive subcommand smuggled in `__argv` | Elevation / Tampering | evaluate effective command (path ++ leading argv tokens), mutation-tested |
| Gate is advisory against a compromised webview (`confirmed` is client-supplied) | Spoofing | Document honestly: protects against accidents and agent mis-clicks, not a malicious renderer. | MCP destructive tools (`snapshot.restore`) not gated | Tampering | out of scope (palette does not run MCP tools); note for 06.4 |
