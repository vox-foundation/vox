## Independent safety probes

**(a) `decideCliActivation` never runs null / unclassified / writes / destructive / group-node verbs.** HELD. Code (`lib/capabilityRun.ts`): returns `explain` if absent from the live catalog or not `compiled_in`; returns `run` only if `isReadOnlyClass(sideEffect)` (exactly `read_only` or `none`) AND `!has_subcommands` AND no required argument; everything else is `form`. Tests cover null, `writes_files`, `spawns_process`, `destructive`, `network_write`, `bogus`, group node, required arg, absent, not-compiled. Cross-checked the data: the only classes reaching `run` are 49 `read_only` + 10 `none` CLI rows; `none` rows are `auth whoami, bundle list, commands, completions, graph (group, so form), graph query/status, model cas ls, plan status, workflow ls`. `secrets get` is read_only but has a required `<CANONICAL_ENV>` arg (redacted output) so it opens the form.

**(b) Backend gate.** HELD for the tested spellings. `CapabilityIndex::confirmation_required_with(argv, &CliAliases)` takes non-flag tokens and requires each path segment (or a clap alias registered at that canonical prefix) as an ordered subsequence. `vox-cli::command_catalog::gate_execution` fails closed (`cli.unresolved`) if the alias table cannot be built. `execute_command` binds its argv only from `prepare_execution(path, &args, confirmed)?` before `.sidecar(`; the source tripwire `gui_execute_command_takes_its_argv_from_prepare_execution` asserts the call, ordering, `.args(shell_args)` and absence of `form_argv(`. Tests that pass on this tree: `every_alias_spelling_of_every_destructive_row_is_gated` (all 14 destructive CLI rows x every alias spelling, incl. `models ...`, `orchestrator ...`), `gate_refuses_alias_spellings_of_destructive_rows`, `prepare_execution_refuses_ungated_destructive_argv` (argv split across `path` and `__argv`, and alias `models` + `__argv`), registry `confirmation_required_skips_flags` (flag-interleaved), `handler_verified_destructive_verbs_are_gated` (WR-01 additions). No `clap` `infer_subcommands` / external subcommands anywhere in vox-cli, so prefix abbreviations cannot slip past. Other `execute_command` callers (`CommandCardsView`, `RepositoryView`, `App.tsx:1538`) invoke Tauri directly without `confirmed`, so the same gate applies. I did not re-run the fixer's mutation proofs (read-only mandate); I read the tests and confirmed they assert the right behaviour.

**(c) `confirmed: true` only from confirm callbacks.** HELD. `grep` of non-test source: the only senders are `App.tsx` `ConfirmRunDialog.onConfirm` -> `runCli(p.path, true)` and `CommandCatalogForm` confirm callback -> `run(p.path, p.args, true)`. Direct palette run passes `confirmed` undefined; `transport.executeCommand` omits it so Rust sees `None`.

**(d) `?` guard.** HELD (`isShortcutHelpKey` + `isEditableTarget`, unit-tested; e2e "`?` in a field types" passes).

## Residual risks (honest list)

1. `confirmed` is client-supplied. Any code running in the webview could call `execute_command` with `confirmed: true`. The gate is a consent step against accidental runs from the palette/form, not an authorization boundary.
2. MCP: 3 MCP rows are classified `destructive` (plus 16 `writes_files`) but no gate applies to MCP tool invocation; the palette only opens the explain card for MCP rows, so there is no palette path to run them, but the invoke path itself is ungated.
3. 901 of ~1000 CLI verbs are unclassified (null). Failing open here means "opens the form, never runs on Enter" (verified), but the form's Run button executes an unclassified destructive verb with a single click and no confirm. Gate coverage is exactly the 14 rows classified destructive.
4. `execute_command` buffers whole output with no cap or timeout (documented on the function); the UI bounds only what it renders (64,000 chars/stream).
5. Alias coverage for feature-gated clap variants relies on a hand-maintained supplement plus a source-scan test limited to `#[command(` lines in `lib.rs` and `commands/ext.rs`; an alias declared elsewhere would be missed. Fixer marked this for human confirmation when new gated variants appear.
6. WR-02 tripwire runs only when vox-cli is in the affected set on hosted CI; a PR touching only `vox-gui/src/commands/execute.rs` may skip it.
7. WR-10 (keybind store): persist failure is swallowed; a "reset to defaults" issued before the first successful load is not persisted. The fixer flagged it for human verification; store unit tests (incl. retry/delta merge) pass here.
8. Review INFO findings IN-01..IN-08 were out of scope and unfixed (stale Catalog prefill on remount, `?` IME edge, query whitespace collapse, graph lane stale append in `#` mode, free-form class strings, naming, no listbox ARIA semantics). IN-02 incidentally fixed by WR-09.
9. TS card parity (`capabilityCard.ts` vs Rust `vox explain`) is covered by unit tests but was not independently diffed against the Rust renderer here; catalog titles remain boilerplate (explicitly out of scope per CONTEXT).
10. Playwright/Vite print unhandled `unregisterListener` rejections from mock teardown (ChatSurface/layout unlisten); tests pass, noise is pre-existing mock-harness behaviour, not phase code.
