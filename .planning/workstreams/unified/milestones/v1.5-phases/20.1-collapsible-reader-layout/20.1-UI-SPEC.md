## Layout Contract

### Breakpoints (Starlight's own — do not add new ones)

| Tier | Width | Left nav | Right "On this page" |
|------|-------|----------|----------------------|
| Phone | < 50rem (800px) | Starlight menu drawer via `MobileMenuToggle` — **unchanged**; no rail | `MobileTableOfContents` dropdown — unchanged; no hide control |
| Tablet | 50rem – 71.99rem (800–1151px) | Pinned sidebar or rail (this phase) | `MobileTableOfContents` dropdown — unchanged; no hide control; saved TOC state is kept for desktop |
| Desktop | ≥ 72rem (1152px) | Pinned sidebar or rail (this phase) | Panel shown or hidden (this phase) |

### Layout tokens

| Token | Value | Notes |
|-------|-------|-------|
| `--sl-sidebar-width` | 18.75rem (300px) | Starlight default; pinned sidebar and flyout width |
| `--vox-rail-width` | 3.5rem (56px) | Collapsed rail width `[CONFIRMED]` (A2) |
| `--vox-control-size` | 2.75rem (44px) | Hit area of every new button (WCAG 2.5.5 target, touch tablets reach ≥72rem in landscape) |
| `--vox-content-max` | 67.5rem (1080px) | Article column cap when space is freed; equals Starlight's own no-sidebar `--sl-content-width` |
| `--vox-prose-max` | 50rem (800px) | Cap for prose blocks inside a widened column `[CONFIRMED]` (A3) |
| `--sl-content-width` | 45rem (720px) | Starlight default; unchanged when both sidebars are open |

### Persisted state

| State | Storage key (`localStorage`) | Values | Default (no/invalid value) | `<html>` attribute set before first paint |
|-------|------------------------------|--------|-----------------------------|-------------------------------------------|
| Left nav | `vox-docs:left-sidebar` | `pinned` \| `collapsed` | `pinned` `[CONFIRMED]` (A1) | `data-vox-left="pinned|collapsed"` |
| Right TOC | `vox-docs:toc` | `shown` \| `hidden` | `shown` (A1) | `data-vox-toc="shown|hidden"` |

- One site-wide value per key (not per page). Survives navigation and reload.
- The head script runs synchronously in `<head>` (same mechanism as `ThemeProvider`), wraps storage
  access in `try/catch`, and writes only the two attributes. Any other value, a throw, or blocked
  storage → defaults; no error UI.
- CSS reads only the attributes, and only inside `@media (min-width: 50rem)` (left) and
  `@media (min-width: 72rem)` (TOC), so phone layout cannot be affected by saved state.
- Transitions are disabled until the client script sets `html[data-vox-layout-ready]` after the first
  animation frame. The saved state must never animate in on load.
- Starlight's own `sessionStorage` `sl-sidebar-state` (group open/scroll restore) is left untouched.

### Article width (SITE-03)

| Desktop state (≥72rem) | Article column | Prose blocks | Wide blocks |
|------------------------|----------------|--------------|-------------|
| Left pinned + TOC shown | 45rem (Starlight default, unchanged) | column | column |
| Left collapsed + TOC shown | grows into the freed 15.25rem, capped at `--vox-content-max` | ≤ `--vox-prose-max` | full column |
| Left pinned + TOC hidden | grows into the freed TOC column, capped at `--vox-content-max`; centered in the space right of the sidebar | ≤ `--vox-prose-max` | full column |
| Both collapsed/hidden | up to `--vox-content-max`, centered right of the rail | ≤ `--vox-prose-max` | full column |

- Prose blocks = direct `.sl-markdown-content` children that are `p, ul, ol, dl, blockquote, h2–h6`, plus `.starlight-aside`.
- Wide blocks = `table`, `.expressive-code`, `pre`, `figure`, `img`, `svg`/mermaid output, `.vox-playground`,
  and the landing page's inline `display:grid` card grid. They take the full column width.
- Invariants (testable): the TOC column is never narrower than `--sl-sidebar-width`; at ≥72rem the
  article column is never narrower than 45rem; the column width is computed from the space actually
  free (`100vw − --sl-content-inline-start − TOC column − 2×--sl-content-pad-x`). It is not a fixed
  value, so 72rem viewports do not squeeze the TOC.
- With the TOC hidden, the inline-end term of that formula is the 52px restore gutter (see Right "On this page" → No occlusion), not `--sl-content-pad-x`.
- Tablet: left collapsed sets `--sl-content-inline-start: var(--vox-rail-width)` and the column grows
  the same way. The tablet has no TOC column.
- The header's site-title column follows `--sl-content-inline-start` (Starlight grid), so the search box
  re-aligns with the article when the rail is active. This is expected; it must not overlap or wrap.

### Left navigation — states and behaviour (SITE-01)

| State | Visual | Article moves? |
|-------|--------|----------------|
| Pinned (default) | Starlight sidebar, 18.75rem, `--sl-color-bg-sidebar`, `border-inline-end: 1px solid var(--sl-color-hairline-shade)`. Pin toggle at the inline-end of the first sidebar row. | — |
| Collapsed (rail) | 3.5rem rail, same background and border. Contains only the rail opener (`bars` icon) centered horizontally, 16px from the top of the pane. Sidebar links are `visibility: hidden` (not focusable). | Yes, once, when the user pins/collapses (200ms, see Motion) |
| Flyout (temporary, from rail) | Full sidebar (18.75rem) drawn **over** the article. It is anchored at the rail's inline-end edge (`inset-inline-start: var(--vox-rail-width)`) below the header, so the rail and its opener stay visible and clickable while it is open. `--sl-shadow-lg`, `z-index: var(--sl-z-index-menu)`, no backdrop or dimming. Pin toggle visible in the first row, unpressed. | **No.** The article does not reflow or shift. |

Flyout state model (single source in `reader-layout.ts`) has two booleans:
- `open`, mirrored by the rail opener's `aria-expanded`.
- `sticky`, which tells the two open states apart. Transient (`open && !sticky`) means opened by hover or keyboard focus. Sticky (`open && sticky`) means opened by an explicit opener activation.

Triggers:
- **Rail opener activation** (click, tap, `Enter`, `Space`): exactly one state change per activation.
  - closed → sticky open
  - transient open → sticky open (`aria-expanded` stays `true`; the flyout stops closing on pointer leave)
  - sticky open → closed

  The flyout never covers the opener, so closing by the opener is always reachable.
- **Mouse hover (`@media (hover: hover) and (pointer: fine)`):**
  - With the flyout closed, the pointer entering the rail opens it as transient after a 150ms dwell.
  - Leaving both rail and flyout closes a transient flyout after a 300ms grace period `[CONFIRMED]` (A4). A sticky flyout ignores pointer leave.
  - After any close by the opener or `Escape`, hover-open is suppressed until the pointer has left the rail and the flyout.
- **Keyboard focus:** a `focusin` on the rail or flyout opens it as transient only when both conditions hold:
  - the focus is keyboard focus (the target matches `:focus-visible`, i.e. the last input was a key);
  - `relatedTarget` is outside `<nav class="sidebar">`.

  So pointer or tap focus never opens it; a click or tap goes through the activation rule alone. Programmatic focus return after `Escape` starts inside the nav and does not reopen. Tab order: rail opener → pin toggle → sidebar links. Focus leaving the nav closes a transient or sticky flyout.
- **`Escape`** (focus in rail or flyout): closes it, returns focus to the rail opener, and it stays closed.
- **Outside pointer-down** (outside rail and flyout), or activating a sidebar link: closes it.
- **Touch / no hover (`(hover: none)` or `(pointer: coarse)`):** no hover behaviour. Only the activation, outside-tap, link and `Escape` rules apply, so one tap is one state change.
- **Pin toggle:** pressing it while pinned → collapsed (rail). Pressing it in the flyout → pinned (the flyout becomes the pinned sidebar, the article reflows once, `open`/`sticky` reset). Writes `vox-docs:left-sidebar`.
- Following a link from the flyout navigates normally. The next page renders in the saved state (rail), not with the flyout open.

### Right "On this page" — states and behaviour (SITE-02, desktop ≥72rem only)

| State | Visual |
|-------|--------|
| Shown (default) | Starlight panel unchanged. The "Hide table of contents" button (`right-caret`) sits at the inline-end of the "On this page" heading row, vertically centered on it. |
| Hidden | The panel and its column are removed (`display: none`). A restore control is fixed at the viewport's inline-end edge, `top: calc(var(--sl-nav-height) + 1rem)`. It is a 44×44px button, `list-format` icon, `--sl-color-bg-nav` fill, `1px solid var(--sl-color-hairline-light)` border with the inline-end side flush to the edge, `border-radius: 0.5rem 0 0 0.5rem`, `--sl-shadow-sm`. Icon colour `--sl-color-gray-3`; on hover/focus `--sl-color-white`. `z-index: var(--sl-z-index-toc)`. `[CONFIRMED]` placement (A5). |

- Pages without a TOC (`starlightRoute.toc` falsy) render neither control.
- Hiding moves focus to the restore control. Restoring moves focus to the hide button.
- **No occlusion:** whenever the restore control renders (TOC hidden, ≥72rem), `.main-pane` reserves an inline-end gutter of `max(var(--sl-content-pad-x), calc(var(--vox-control-size) + 0.5rem))`, which is 52px. The article-width formula subtracts this gutter in place of the inline-end `--sl-content-pad-x`. The control sits in that gutter (44px wide, flush to the edge), so it never overlaps the page title, banner or body at any width ≥72rem, with the left sidebar pinned or collapsed, at any scroll position.
- Writes `vox-docs:toc`. Below 72rem neither control renders, and Starlight's mobile dropdown is unaffected by the saved value.

### Phone & landing page (SITE-04)

- Phone (<50rem): Starlight drawer and mobile TOC behave exactly as today. The rail, flyout, pin toggle and TOC controls are not rendered (CSS `display: none` below their breakpoints).
- No page may scroll horizontally at any tier. Wide blocks scroll inside themselves: tables already have `display:block; overflow:auto` in Starlight, and `.expressive-code` and `.demo-code` scroll internally.
- Landing page (`docs/src/index.mdx`): the hero button row keeps `flex-wrap: wrap`. The pillar grid (`minmax(190px, 1fr)`) collapses to one column at 390px. The two markdown tables scroll inside themselves. The centered image is `max-width: 100%`. No new controls overlap the hero CTA or the header at any tier.
- No new keyboard shortcuts (avoids clashing with Starlight search `/` and `Ctrl/⌘ K`).

### Motion

- Pin/collapse: `inline-size` and `padding-inline-start` transition, 200ms `ease-out`. Flyout open: `transform: translateX` from −100% of the overlap, 150ms `ease-out`. Close: 100ms. The rail is stacked one level above the flyout and the flyout is clipped at the rail's inline-end edge (`clip-path: inset(0)` on its wrapper), so the opener stays the topmost element at its own centre throughout the open and close animation.
- `@media (prefers-reduced-motion: reduce)`: all of the above become `transition: none` (instant).
- Before `data-vox-layout-ready` is set: `transition: none` regardless of preference.

## Spacing Scale

Declared values (must be multiples of 4). Expressed in rem in CSS (1rem = 16px):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inset between a 16px icon glyph and its 24px visual box. This is derived from centring, (24 − 16) / 2, not chosen. |
| sm | 8px | Gap between the pin toggle and the sidebar's first row content |
| md | 16px | Rail opener top inset; restore control offset below header (`--sl-nav-height` + 16px); Starlight `--sl-sidebar-pad-x` |
| lg | 24px | Starlight `--sl-content-pad-x` at ≥72rem and `.sl-container` child gap (unchanged) |
| xl | 32px | Not part of the width formula (the article↔TOC gap is `lg` / `--sl-content-pad-x`); reserved for block spacing inside the flyout and panels where Starlight already uses 2rem |
| 2xl | 48px | not used by new elements |
| 3xl | 64px | `--sl-nav-height` at ≥50rem (Starlight, unchanged) |

Exceptions: the 56px rail width and the 44px control hit area are layout dimensions, not spacing steps.

The pin toggle and the TOC hide button have a 24×24px visual box. The 16px icon is centred in it, and the hover background and focus ring are drawn on it. Their 44×44px hit area is an absolutely positioned `::before` that extends 10px on each inline side, 14px at block-start and 6px at block-end. The layout box stays 24px, so neither the sidebar's first row nor the "On this page" heading row grows. The 6px block-end extension stays inside Starlight's 8px heading margin, so the hit area never covers the first TOC link. The 14px block-start extension stays inside the panels' 16px top padding.

The rail opener (in the 56px rail) and the restore tab are laid out at the full 44×44px. Content caps are 720 / 800 / 1080px. The restore gutter is 52px (44 + 8).

## Color

All values come from Starlight theme variables and switch with `data-theme`. Hex values are the resolved Starlight defaults.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--sl-color-bg` — dark `#17181C`, light `#FFFFFF` | Article surface |
| Secondary (30%) | `--sl-color-bg-sidebar` / `--sl-color-bg-nav` — dark `#23262F`, light `#FFFFFF` / `#F6F7F9` | Pinned sidebar, rail, flyout, header, TOC restore control |
| Accent (10%) | `--sl-color-accent` — dark `#3369FF`, light `#3D50F5` (text variant `--sl-color-text-accent`) | See reserved list |
| Destructive | not used | No destructive actions in this phase |

Accent reserved for: (1) the `:focus-visible` outline on the new buttons
(`2px solid var(--sl-color-text-accent)`, `outline-offset: 2px`); (2) Starlight's existing current-page
highlight in the sidebar; (3) the landing page's existing "Get Started →" button. New controls are
never accent-filled. Their idle icon colour is `--sl-color-gray-3`, and on hover/focus it is
`--sl-color-white`. Borders use `--sl-color-hairline-shade` (rail/sidebar edge) and
`--sl-color-hairline-light` (restore control). Overlay shadow is `--sl-shadow-lg`.

**Focal point:** the article (page title and body) is the only focal point in every state. New controls are deliberately muted: 16px `--sl-color-gray-3` glyphs, no accent fill, no badges, and no motion beyond the state transitions in Motion. The restore tab's only fill is `--sl-color-bg-nav`, and it sits in its own gutter outside the article. The single exception is the open flyout. While the reader is navigating, it sits above the article with `--sl-shadow-lg`, and when it closes the article is the focal point again.

### Verification contract (SITE-05)

- Spec file: `docs-astro/tests/layout/reader-layout.spec.ts`, run in a new Playwright project `layout`
  whose `webServer` serves the built `dist/` (`pnpm preview`, `baseURL` `http://localhost:4321`). The
  existing `chromium` project keeps defaulting to the live site.
- Viewports: phone 390×844, tablet 820×1180 (touch), desktop 1440×900 `[CONFIRMED]` (A6). Themes: set `localStorage['starlight-theme']` to `light` / `dark` before navigation.
- Pages: the landing page `/`, plus one docs page that has a TOC, a markdown table and a code block. The planner picks it and the spec asserts those three exist, so a content change cannot silently weaken the test.
- State matrix (screenshot each × light/dark): desktop {pinned, collapsed, collapsed+flyout} × {TOC shown, hidden}; tablet {pinned, collapsed, collapsed+flyout}; phone {drawer closed, drawer open}; search dialog open at desktop (left collapsed); landing page at each tier in the default state. That is 28 captures.
- Functional assertions that gate: ARIA state per control, persistence across navigation and reload, first-paint attributes, no horizontal overflow, no article shift during the flyout, touch no-hover, `Escape` focus return, reduced motion, plus the two groups below.
- Gated flyout-gesture assertions (desktop 1440×900 with a mouse, tablet 820×1180 with touch, keyboard). "Stays" means re-read after 400ms, which is longer than the 300ms hover grace:
