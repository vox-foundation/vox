## Shared Patterns

### Storage values are lookup keys, never data
**Source:** `docs-astro/src/utils/page-status.mjs` lines 7-8, 38-42; tested by `tests/unit/page-status.test.mjs` lines 45-46.
**Apply to:** `reader-layout-head.js`, `reader-layout.ts`, `reader-layout.test.mjs`. Compare against a constant allow-list and write the constant. Never interpolate the stored string into HTML, `style` or selectors. Unit-test hostile strings.

### Wrap, don't fork, Starlight components
**Source (upstream):** `SL/components/{MobileMenuToggle,Sidebar,PageSidebar}.astro`; resolution through `virtual:starlight/components/<Name>` (`SL/components/PageFrame.astro` line 2).
**Apply to:** all three overrides. `import Default from '@astrojs/starlight/components/<Name>.astro'` and render `<Default />` unchanged. Never copy Starlight markup or its scoped CSS: scoped styles compile to `:where(.astro-xxxx)` and would not apply to copies (Pitfall 1).

### Starlight tokens only
**Source:** `VoxPlayground.astro` `<style>` lines 63-167.
**Apply to:** `reader-layout.css` and the override `<style>` blocks. Use `--sl-color-*`, `--sl-shadow-*`, `--sl-z-index-*`, `--sl-nav-height`, `--sl-sidebar-width` and `--sl-content-*`. The only new tokens are `--vox-rail-width`, `--vox-control-size`, `--vox-content-max` and `--vox-prose-max` (UI-SPEC Layout tokens).

### Review-bundle convention
**Source:** `crates/vox-gui/ui/e2e/review/capture.spec.ts` lines 23, 44, 77; `…/review/globalSetup.ts`; `crates/vox-gui/ui/.gitignore` line 3; `nightly.yml` lines 1775-1782.
**Apply to:** layout spec, global setup, `.gitignore`, `docs-quality.yml`:
- Output in `<pkg>/review-bundle/latest/`, ids joined with `--`.
- `animations: 'disabled'`, viewport clip (no `fullPage`).
- Folder wiped in `globalSetup`, gitignored, uploaded with `retention-days: 3`.

### Playwright webServer must not go through pnpm
**Source:** `crates/vox-gui/ui/playwright.config.ts` lines 32-40.
**Apply to:** `playwright.layout.config.ts`. Use `node ./node_modules/astro/bin/astro.mjs preview --port 4321`.

### Test-file conventions
**Source:** `docs-astro/tests/unit/*.test.mjs` (`node:test` + `node:assert/strict`, relative `../../src/...mjs` imports) and `docs-astro/tests/build-output/*.spec.ts` (`@playwright/test` with fs only, `../lib/dist`).
**Apply to:** both new test files. Both are auto-collected by the existing `docs-quality.yml` steps (lines 169-176), so no CI edit is needed for them.
