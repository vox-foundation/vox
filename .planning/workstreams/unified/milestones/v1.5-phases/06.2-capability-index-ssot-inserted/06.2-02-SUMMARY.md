# Phase 06.2 Plan 02: Owner, Domain and Ratchet Summary

**Every operation row in the capability index now names its owning crate (with the rule that fired and the layers.toml layer), a curated domain from a committed 17-id vocabulary, a catalog tier and a source path, and a removal-only owner ratchet fails the gate when a new command has no owner.**

## Accomplishments

- `owner.rs`: pure `resolve_owner` (override, `vox_<x>::` handler path, group table, `vox-cli-<g>`/`vox-<g>` crate-name match, `commands/<g>` module, mcp dispatch crate), `resolve_domain`, `validate_domains`, `source_path_for`. An `owner_crate` override outside layers.toml, or a domain id outside the vocabulary, fails generation naming the op id or yaml key.
- Optional catalog fields `owner_crate` / `domain` on `OperationRow` (skip-serialized when absent, copied through `apply_prev_planner_metadata`, declared in `catalog.v1.schema.json`), so the 1298-row catalog is not rewritten.
- `domains.v1.yaml`: 17 domains, 86 cli groups, 41 mcp prefixes, 41 domain crates. Index top-level `domains` lists the vocabulary in file order; `product_lane` is kept as a secondary facet.
- Generated index (1336 rows): owner rules fired cli_module 355, crate_name_match 447, group_table 192, handler_path 2, mcp_dispatch 340; 0 rows without an owner, 0 with a null domain; 20 rows carry domain `secrets` (all 9 `cli.secrets.*` rows included).
- `ratchet.rs` + `vox ci capability-index --tighten`: the check runs in both modes before the artifact write/verify. Missing baseline is an error. `run()` never writes the baseline.
