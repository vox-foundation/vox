## Summary

The site uses stock Starlight 0.38.3 on Astro 6.1.9 with no `components`, `customCss` or `head` entries in `docs-astro/astro.config.mjs`. Everything this phase needs is available through Starlight's documented extension points: component overrides, `customCss`, and `head` entries. No new dependencies are required. The flyout can be built entirely on the existing `#starlight__sidebar` pane (a `position: fixed` element), the article width on Starlight's own `--sl-content-inline-start` / `--sl-content-width` variables, and the icons already exist in Starlight's icon set (`bars`, `left-caret`, `right-caret`, `list-format`).

Three findings change how the UI-SPEC's file list should be implemented:

1. **A PageFrame wrapper cannot put the rail opener where the spec needs it.** A wrapping override can only add markup around the default `.page`, not between `MobileMenuToggle` and `#starlight__sidebar`. The spec requires the opener inside `<nav class="sidebar">` (for the `relatedTarget` rule and Escape focus return) and before the pane (for the Tab order opener → pin toggle → links). Wrapping `MobileMenuToggle` instead puts the opener exactly there with no copied Starlight code. Re-implementing PageFrame is the alternative.
2. **The TOC restore control lives inside the TOC column.** `PageSidebar` content renders inside `.right-sidebar` inside `.right-sidebar-container`, so `display: none` on the column would also hide the restore control. Collapse the column to zero width and hide `.right-sidebar-panel`. The `position: fixed` restore control escapes both.
3. **The Playwright `webServer` is config-wide, not per project.** Adding a `layout` project with a `pnpm preview` webServer to the existing config would make the docs-deploy smoke job (which has no `dist/`) try to start a preview server. Use a separate `playwright.layout.config.ts` that defines the `layout` project, and ignore `layout/**` in the existing config.

Further, the `docs-quality` job already takes 16.7–22.5 min of its 30-min cap, so the layout run should be a second job in the same workflow (`needs: docs-quality`) that downloads the built `dist/` as an artifact.

**Primary recommendation:** Wrap `MobileMenuToggle`, `Sidebar` and `PageSidebar`. Put all layout rules in one unlayered `customCss` file keyed on `html` attributes, and inline a tiny allow-list head script. Keep the flyout state machine in a pure `.mjs` module that `node --test` can exercise. Verify with a separate Playwright config against `pnpm preview`, run in a new `docs-layout` job.

### Pattern 1: Wrapper overrides (re-render the default inside your component)

Starlight resolves overrides through `virtual:starlight/components/<Name>`. Default `PageFrame` imports the toggle that way:

```astro
// SL/components/PageFrame.astro:1-18 [VERIFIED]
import MobileMenuToggle from 'virtual:starlight/components/MobileMenuToggle';
...
<nav class="sidebar print:hidden" aria-label={Astro.locals.t('sidebarNav.accessibleLabel')}>
  <MobileMenuToggle />
  <div id="starlight__sidebar" class="sidebar-pane">
    <div class="sidebar-content sl-flex">
      <slot name="sidebar" />
```

So an override of `MobileMenuToggle` renders inside the nav, directly before the pane:

```astro
---
// src/components/overrides/MobileMenuToggle.astro
import Default from '@astrojs/starlight/components/MobileMenuToggle.astro';
import { Icon } from '@astrojs/starlight/components';
---
<Default />
<div class="vox-rail">
  <button type="button" class="vox-rail-opener" aria-expanded="false"
          aria-controls="starlight__sidebar" aria-label="Show navigation">
    <Icon name="bars" />
  </button>
</div>
<script>import '../../scripts/reader-layout';</script>
```

Two details matter here:
- The `aria-expanded` attribute belongs on the button, not on `.vox-rail`. Starlight shows the pane through `:global([aria-expanded='true']) ~ .sidebar-pane` (`SL/components/PageFrame.astro:61`), and any preceding *sibling* with `aria-expanded="true"` would match. The button is a child of `.vox-rail`, so it does not.
- `MobileMenuToggle` is only rendered when `hasSidebar` (it sits inside the `hasSidebar &&` branch), so pages without a sidebar get no rail for free.

`Sidebar` and `PageSidebar` follow the same pattern: `import Default from '@astrojs/starlight/components/Sidebar.astro'` and render `<Default />` after or around the new control. Register them in `astro.config.mjs`:

```js
starlight({
  components: {
    MobileMenuToggle: './src/components/overrides/MobileMenuToggle.astro',
    Sidebar: './src/components/overrides/Sidebar.astro',
    PageSidebar: './src/components/overrides/PageSidebar.astro',
  },
  customCss: ['./src/styles/reader-layout.css'],
  head: [{ tag: 'script', content: readFileSync(fileURLToPath(new URL('./src/scripts/reader-layout-head.js', import.meta.url)), 'utf8') }],
})
```

[VERIFIED: `SL/components/Head.astro` renders entries as `<Tag {...attrs} set:html={content} />`; the `head` schema accepts `tag: 'script'`. `ThemeProvider.astro` already ships an inline `<script is:inline>` in `<head>`, so inline scripts are an established pattern on this site.]

### Pattern 2: First-paint head script (allow-list, no DOM writes beyond two attributes)

```js
// src/scripts/reader-layout-head.js — inlined verbatim; must stay an IIFE (no import/export)
(() => {
  const read = (key, allowed, fallback) => {
    try {
      const v = window.localStorage.getItem(key);
      return allowed.includes(v) ? v : fallback;
    } catch {
      return fallback;
    }
  };
  const root = document.documentElement;
  root.setAttribute('data-vox-left', read('vox-docs:left-sidebar', ['pinned', 'collapsed'], 'pinned'));
  root.setAttribute('data-vox-toc', read('vox-docs:toc', ['shown', 'hidden'], 'shown'));
})();
```

- Access `window.localStorage` *inside* the `try`. With storage blocked, the property getter itself throws `SecurityError`, not only `getItem`.
- Attribute presence doubles as "JS ran". CSS shows the new controls only under `html[data-vox-left]`, so no-JS readers get stock Starlight (spec UI-considerations row).
- Unit-test with `node:vm` (`vm.runInNewContext(src, { window: { localStorage }, document })`) for valid values, garbage, `null`, and a throwing getter.

### Pattern 3: Flyout on the existing pane

`#starlight__sidebar` is already `position: fixed; inset-block: var(--sl-nav-height) 0; z-index: var(--sl-z-index-menu); overflow-y: auto;`, and its visibility is `var(--sl-sidebar-visibility, hidden)` (`SL/components/PageFrame.astro:50-59, 89-94`). For `html[data-has-sidebar][data-vox-left='collapsed']` at ≥50rem:

- **Pane (closed):** `inset-inline-start: var(--vox-rail-width)`, `--sl-sidebar-visibility: hidden`, `transform: translateX(-100%)`. Visibility (not `display: none`) keeps the box laid out, so Starlight's `SidebarPersistState` scroll restore (`pane.scrollTop = …`) still works. It also takes the links out of the Tab order, as the spec requires.
- **Pane (open):** `html[data-vox-flyout='open']` → `--sl-sidebar-visibility: visible; transform: none; box-shadow: var(--sl-shadow-lg)`.
- **Rail:** `.vox-rail { position: fixed; inset-block: var(--sl-nav-height) 0; inset-inline-start: 0; width: var(--vox-rail-width); z-index: calc(var(--sl-z-index-menu) + 1); background: var(--sl-color-bg-sidebar); border-inline-end: 1px solid var(--sl-color-hairline-shade); }`. Its z-index is 6, still below the navbar (10).
- **Topmost opener:** the rail is opaque and stacked above the pane, so the part of the sliding pane that is behind the rail is hidden. This meets the spec's "opener always topmost" goal without `clip-path`. If a literal clip is wanted, keep the pane static at `inset-inline-start: var(--vox-rail-width)` and animate `.sidebar-content` inside it. The pane's `overflow-y: auto` forces `overflow-x` non-visible, which clips the content's negative-direction overflow. [VERIFIED by spike, Chromium 1243: an ancestor's `clip-path: inset(0)` **does** clip a viewport-fixed descendant (the opener stopped being hit-testable), and an ancestor `transform` re-anchors it (the opener moved from (6,80) to (62,144)). The pane's own `overflow-x` clipping does not affect a fixed descendant. Rule: never put `clip-path`, `transform`, `filter` or `will-change: transform` on any ancestor of the rail. The sibling-rail structure above satisfies this. Moving the rail inside `.sidebar-pane` would break it as soon as the pane is transformed.]
- **Article:** `.main-frame` gets `padding-inline-start: var(--sl-content-inline-start)` from Starlight (`PageFrame.astro:80-83`). Setting `--sl-content-inline-start: var(--vox-rail-width)` in collapsed state moves the article once; opening the flyout changes no variable, so the article cannot shift.

### Pattern 4: TOC hide/restore

`PageSidebar` renders (`SL/components/PageSidebar.astro:9-13`) `<div class="lg:sl-hidden"><MobileTableOfContents/></div><div class="right-sidebar-panel sl-hidden lg:sl-block"><div class="sl-container"><TableOfContents/></div></div>`. The wrapper renders `<Default />` plus a restore `<button>`. The hide button has to sit on the "On this page" heading row, which is inside `TableOfContents`, so either:
- (a) position the hide button absolutely at the top inline-end of `.right-sidebar-panel` (it shares the heading's row because the panel padding is `1rem var(--sl-sidebar-pad-x)` and the `h2` is the first child). This needs no deeper override and is the recommended option. Reserve inline-end padding on `.right-sidebar-panel h2` so long localized headings do not run under it.
- (b) override `TableOfContents`. This is not needed.

Hidden state at ≥72rem (`html[data-has-toc][data-vox-toc='hidden']`):
```css
.right-sidebar-container { width: 0; }
.right-sidebar { width: 0; border-inline-start: 0; }   /* fixed panel; restore button is fixed too */
.right-sidebar-panel { display: none; }
[data-has-sidebar][data-has-toc] .main-pane { width: 100%; --sl-content-margin-inline: auto; }
.vox-toc-restore { display: grid; position: fixed; inset-inline-end: 0; top: calc(var(--sl-nav-height) + 1rem); z-index: var(--sl-z-index-toc); }
```
TwoColumnContent's rules are in `@layer starlight.core` (`SL/components/TwoColumnContent.astro:15`), so these unlayered rules win regardless of specificity.

### Pattern 5: Pure state reducer + thin DOM glue

Keep the spec's state model (`open`, `sticky`, plus `suppressHover`) in `reader-layout-state.mjs`:

```js
// pure; no DOM. Events: 'opener', 'hoverEnter', 'hoverLeaveElapsed', 'focusKeyboardFromOutside',
// 'escape', 'outsidePointer', 'linkActivate', 'focusLeftNav', 'pointerLeftAll', 'pin', 'reset'
export function next(state, event) { /* table from UI-SPEC §Flyout state model */ }
```

`reader-layout.ts` maps DOM events to reducer events. It handles the 150ms dwell and 300ms grace with timers, applies the state (`aria-expanded`, `html[data-vox-flyout]`) and persists. `.mjs` matches the existing `src/utils/*.mjs` convention and `node --test` imports it without type-stripping.

Rules for the DOM glue:
- Gate hover on **both** `matchMedia('(hover: hover) and (pointer: fine)').matches` and `event.pointerType === 'mouse'`. With the per-event check, the touch behaviour is correct even if device emulation does not flip the media query.
- Escape: listen on `keydown` on the nav. Starlight's own handler is a `keyup` listener on the parent nav that calls `this.btn.focus()` on the mobile button. That button is `display: none` at ≥50rem, so its focus call is a no-op and does not steal focus back. [VERIFIED: `SL/components/MobileMenuToggle.astro`]
- Search: Starlight opens search with `dialog.showModal()` (top layer, above any z-index) and sets `body[data-search-modal-open]`. Close a transient flyout when that attribute appears (a `MutationObserver` on `body` attributes), or on the search button's `pointerdown`.
- Scroll the current link into view inside the pane with `pane.scrollTop = link.offsetTop - …`. `scrollIntoView()` can also scroll the document.
- Reset `open`/`sticky` on `matchMedia('(min-width: 50rem)')` change.
- Set `data-vox-layout-ready` after two `requestAnimationFrame`s (one frame can land before the first style resolution with the attributes).

### Pattern 6: Width math via Starlight's own variables

Starlight's content box is `.sl-container { max-width: var(--sl-content-width) }` inside `.content-panel { padding: 1.5rem var(--sl-content-pad-x) }`. At ≥72rem the TOC column is `S + (W − X − S)/2`, with `W` = main-frame content width, `X` = `--sl-content-width` and `S` = `--sl-sidebar-width` (`TwoColumnContent.astro:21-51`). Override `--sl-content-width` on `html` per state:

```css
@media (min-width: 72rem) {
  html[data-has-sidebar][data-has-toc][data-vox-left='collapsed'][data-vox-toc='shown'] {
    --sl-content-inline-start: var(--vox-rail-width);
    --sl-content-width: min(var(--vox-content-max),
      calc(100vw - var(--vox-rail-width) - var(--sl-sidebar-width) - 2 * var(--sl-content-pad-x)));
  }
}
```

- **Specificity:** Page.astro's inline `<style>` is extracted **unlayered** and emitted after customCss. Live CSS: `@media(min-width:50em){:where(.astro-5dacf6zr)[data-has-sidebar]{--sl-content-inline-start: var(--sl-sidebar-width)}}`. Its specificity is (0,1,0) because of `[data-has-sidebar]`. Selectors with two or more attribute selectors on `html` beat it. [VERIFIED: deployed CSS and `SL/components/Page.astro:52-79`]
- **Check at 1440×900:** collapsed+shown gives X = min(1080, 1440−56−300−48 = 1036) = 1036 and TOC column = 300 + (1384−1036−300)/2 = 324 ≥ 300 ✓. At 72rem (1152): X = 748 ≥ 720 ✓, TOC column 324 ✓.
- **Rendered vs variable:** the rendered prose box is `min(X, mainPane − 2·pad)`, which is about one `pad` (24px) less than X while the formula is in force. Tests must measure the rendered element (`.sl-markdown-content` width), not the variable. Subtracting `4 * pad` instead of `2 * pad` makes them equal; both satisfy the spec invariants.
- **Stock squeeze:** stock pinned+shown at exactly 72rem already squeezes the TOC column below `S` (W−X−S = −168px). That state is "unchanged" in the spec, so assert the TOC-column invariant only for the three non-default states, or at 1440.
- Using `100vw` here is safe. Under classic (non-overlay) scrollbars it overshoots by the scrollbar width, but these are `max-width` caps and the `2·pad` slack absorbs ≤17px. Never set `width: 100vw` on a box.
- **Tablet (50–71.99rem):** only `--sl-content-inline-start` changes. Starlight has no TOC column there, and `MobileTableOfContents` already uses `inset-inline-start: var(--sl-content-inline-start, 0)`, so it follows the rail automatically.

### Pattern 7: Review-bundle capture (mirror the GUI)

The GUI already uses this naming and upload shape (`.github/workflows/nightly.yml:1765-1782`: `pnpm exec playwright install …`, then `actions/upload-artifact@v7` with `path: crates/vox-gui/ui/review-bundle/latest/`, `retention-days: 3`). `crates/vox-gui/ui/.gitignore:3` has `review-bundle/`. ### Anti-Patterns to Avoid
- **`display: none` on `#starlight__sidebar` or `.right-sidebar-container`.** The first breaks Starlight's scroll restore; the second hides the restore control.
- **Transitioning custom properties.** `--sl-content-inline-start` and `--sl-content-width` are unregistered, so they jump. Transition the consuming properties instead (`padding-inline-start` on `.main-frame`, `inline-size` on the pane/rail, `max-width` on `.sl-container` if desired).
- **`@layer` in customCss.** Unlayered rules beat every `starlight.*` layer. Wrapping our rules in a layer would make them lose to Starlight.
- **Reading storage in CSS-free paths.** The head script is the only reader at load. `reader-layout.ts` reads the attributes, not storage, so the two cannot disagree.
- **New `.sh`/`.py` helpers.** Use pnpm scripts and Playwright only (AGENTS.md VoxScript-first).

## Common Pitfalls

### Pitfall 1: PageFrame "wrap default" can't place the opener
**What goes wrong:** markup added around `<Default>` lands outside `<nav class="sidebar">`. Then `relatedTarget` checks, Escape focus return and Tab order (opener → pin toggle → links) all break.
**How to avoid:** wrap `MobileMenuToggle` (recommended) or re-implement PageFrame. If re-implementing, the default PageFrame's scoped styles compile to `:where(.astro-tu4vtngh)` and will **not** apply to new markup, so all of `PageFrame.astro:24-97` must be ported. Add a unit tripwire that hashes `node_modules/@astrojs/starlight/components/PageFrame.astro`, so that a `^0.38.3` bump fails loudly.

### Pitfall 2: Starlight's pane-visibility sibling selector
`[aria-expanded='true'] ~ .sidebar-pane` matches any earlier sibling. Never put `aria-expanded` on a direct sibling of the pane (the rail wrapper); only on the button inside it.

### Pitfall 3: Specificity vs Page.astro's unlayered inline style
`[data-has-sidebar] { --sl-content-inline-start: … }` and `html:not([data-has-sidebar]) { --sl-content-width: 67.5rem }` are unlayered and come later in source order. Our overrides need higher specificity (e.g. `html[data-has-sidebar][data-vox-left='collapsed']`, which is (0,2,1)).

### Pitfall 4: Touch emulation and hover media queries
Headless Chromium launches with `--blink-settings=primaryHoverType=2,availableHoverTypes=2,primaryPointerType=4,availablePointerTypes=4` (hover + fine pointer) [VERIFIED: `playwright-core/lib/coreBundle.js` ~43341]. With `hasTouch`, Playwright sends `Emulation.setTouchEmulationEnabled` [VERIFIED: same file, 37647]. [VERIFIED by spike: in a `{ isMobile: true, hasTouch: true }` 820×1180 context, `matchMedia('(hover: hover) and (pointer: fine)').matches === false`; in a default 1440×900 context it is `true`.] **However**, Playwright's `locator.hover()` dispatches `pointerType: 'mouse'` events even in the touch context. The `pointerType` check alone would therefore let the "no hover on touch" assertion fail. The media query is the gate that matters there.
**How to avoid:** gate hover in JS on the media query (primary) **and** `event.pointerType === 'mouse'`. Make the tablet spec assert `matchMedia('(hover: hover) and (pointer: fine)').matches === false` as a precondition, so a silent emulation gap fails visibly instead of passing for the wrong reason. Use `locator.tap()` for touch gestures.

### Pitfall 5: Focus-driven open vs mouse click
A mouse click focuses the button but does not match `:focus-visible`, so it must not trigger the focus-open rule. Otherwise the click would go closed → transient (focus) → sticky (click), two state changes. Check `event.target.matches(':focus-visible')` in `focusin`.

### Pitfall 6: Escape focus return re-opening
Focus moves programmatically to the opener with `relatedTarget` inside the nav, which by the spec's rule must not reopen. Verify the `relatedTarget` check actually runs. Gated assertion 4 covers it.

### Pitfall 7: Restore control trapped in the hidden column
The restore control is rendered inside `.right-sidebar` (fixed, `overflow-y: auto`) inside `.right-sidebar-container`. Use zero width plus `display: none` on `.right-sidebar-panel` only. A `position: fixed` descendant escapes `overflow` clipping as long as no ancestor has `transform`/`filter`/`contain`/`will-change` (`.main-pane`'s `isolation: isolate` is fine; it is also not an ancestor). Do not add transforms to the TOC column.

### Pitfall 8: `.right-sidebar` is viewport-wide
`.right-sidebar { position: fixed; width: 100% }` resolves against the viewport, so the TOC panel box extends off-screen to the right of its static position (`TwoColumnContent.astro:29-38`). Measure the TOC column with `.right-sidebar-container`'s rect, not `.right-sidebar`'s.

### Pitfall 9: Headings are wrapped
`markdown.headingLinks` defaults to `true` (`SL/utils/user-config.ts:250`), and the site does not disable it. Rendered headings are therefore `div.sl-heading-wrapper.level-h2 > h2` (`SL/integrations/heading-links.ts:45`). A prose cap on direct-child `h2–h6` misses them; include `.sl-heading-wrapper`.

### Pitfall 10: Landing page specifics
`docs/src/index.mdx` uses inline styles: a hero `h1` at 2.25rem, flex-wrap buttons, and a pillar grid `repeat(auto-fit, minmax(190px, 1fr))` with two markdown tables. At 390px the content width is 390 − 2×16 = 358. That fits one 190px column, so the grid already collapses; tables are `display: block; overflow: auto` (`SL/style/markdown.css`). Expect the phone landing overflow check to pass without content edits. Fix any failure in CSS rather than by editing the MDX inline styles if possible. The landing page uses the doc template, so it has a sidebar and TOC and gets the rail and TOC controls.

### Pitfall 11: First-paint check must defeat the module script
To prove the head script, not the deferred module, sets state: seed storage with `addInitScript`, then `page.route` the **HTML document** and strip every `<script type="module"…>…</script>` (both `src=` and inline) before fulfilling. Aborting `**/_astro/*.js` alone is not enough [VERIFIED: the built `/reference/ref-decorators/` contains 4 inline `<script type="module">` blocks because Astro inlines small bundles, and `reader-layout.ts` may be inlined the same way; module scripts also run before `DOMContentLoaded`]. Then assert `html[data-vox-left='collapsed'][data-vox-toc='hidden']` at `domcontentloaded`. Also check that the rail is visible and `data-vox-layout-ready` is absent. For no-JS, use a context with `javaScriptEnabled: false` and assert no new controls are visible.

### Pitfall 12: Playwright `webServer` is config-level
`TestConfig.webServer` exists, but `TestProject` has no `webServer` (`@playwright/test` types, test.d.ts ~1049). If a `layout` project with a preview server is added to `playwright.config.ts`, every run starts `pnpm preview`. That includes docs-deploy's `npx playwright test tests/smoke.spec.ts` job, which has no `dist/`, so it would fail. Use `playwright.layout.config.ts` with `testDir: './tests/layout'` and `projects: [{ name: 'layout' }]`. Add `'layout/**'` to `playwright.config.ts`'s `testIgnore`, so a bare `playwright test` does not run layout specs against the live site.

### Pitfall 13: The findings route could pull Rust into `pnpm build` (it currently does not)
`src/pages/findings/[uri].astro` renders through `bash scripts/vox-dev.sh scientia publication-finding-page-render` → `cargo run -q -p vox-cli`. **Observed in this worktree:** `pnpm build` finished in ~50 s (698 pages), emitted **no** `/findings/` routes and invoked no cargo, even though `contracts/scientia/fixtures/findings/` holds a fixture. Likely cause [UNVERIFIED]: `getStaticPaths` resolves the fixtures directory from `import.meta.url`, which points into the bundled prerender chunk, so `existsSync` fails and it returns `[]`. This is a pre-existing latent bug outside 20.1's scope; do not fix it here. Do not budget executor time for a Rust compile either. If someone fixes that route later, any job that builds `dist/` (including a layout job) will need cargo.

### Pitfall 14: UI-SPEC example `/retired/` has a sidebar
`StarlightPage` defaults `hasSidebar: props.hasSidebar ?? entry.data.template !== 'splash'` (`SL/utils/starlight-page.ts:157`), and `src/pages/retired.astro:8-13` passes no template. `/retired/` therefore **has** a sidebar. For the no-sidebar case use the 404 page (`/404.html` or any unknown path under `astro preview`); Starlight's 404 uses the splash template.

### Pitfall 15: Capture count
The spec's matrix gives desktop 6×2 + tablet 3×2 + phone 2×2 + landing 3×2 = 28 captures, plus two search-dialog captures, for 30 PNGs in total. Assert the count from a manifest in the spec so a skipped capture fails. Use 30, or 28 plus 2 named search files, and do not leave it ambiguous.

## Open Questions (RESOLVED)

1. **Rail host: `MobileMenuToggle` wrapper vs re-implemented `PageFrame`.**
   - What we know: a PageFrame *wrapper* cannot meet the spec's focus/Tab requirements (Pitfall 1). Re-implementing needs ~70 lines of ported Starlight CSS plus a drift tripwire.
   - Recommendation: wrap `MobileMenuToggle`, and record in the plan that the UI-SPEC's "PageFrame override" row is implemented as a MobileMenuToggle wrapper with the same observable behaviour. The spec marks MobileMenuToggle "Unchanged". That still holds for its behaviour: `<Default />` renders untouched and the phone drawer is identical.
2. **TOC "removed (`display: none`)" wording.** Implement as zero-width column + hidden panel (Pattern 4/Pitfall 7). The observable result matches the spec. Tests should assert the panel is not visible and the column's width is 0, not the literal `display` value of the container.
3. **Hide-button placement.** Recommend an absolutely positioned button in `.right-sidebar-panel` aligned with the `h2` row (no `TableOfContents` override).
4. **Pin-toggle placement ("first row" / "inline-end of the first sidebar row").** Recommend `position: absolute` at the top inline-end of `.sidebar-content` with matching inline-end padding on the first sidebar row. The toggle stays on the first row's line and adds no height. Hide it below 50rem: `Sidebar` also renders inside the phone drawer.
5. **Header `--__toc-width`.** Header.astro uses a private variable that is `0` only for `:root:not([data-has-toc])` (`Header.astro:67-68`). With the TOC hidden, the search box aligns as if the TOC were present. The spec only requires no overlap and no wrap. Optionally set `--__toc-width: 0rem` for `html[data-vox-toc='hidden']` at ≥72rem, accepting that it couples to a private variable.
6. **Invariant scope.** Stock pinned+shown at exactly 72rem already violates "TOC column ≥ sidebar width". Assert the invariants for the non-default states, and at 1440 for all states.

### Verified Baselines and Test Mechanics (second research pass)
Measured on the **stock** build (no 20.1 changes) with playwright-core 1.63.0 / Chromium 1243 against `pnpm preview`:
- **No horizontal overflow** at 390, 820 (touch) and 1440 on `/`, `/reference/ref-decorators/`, `/reference/stability/`, `/tutorials/tut-getting-started/` and the 404 page. Any overflow failure in the layout spec is therefore a 20.1 regression, not pre-existing debt.
- **Before-values at 1440×900, pinned + shown (stock):** `.main-frame` `padding-inline-start` 300px, `.right-sidebar-container` 360px, article column (`.sl-container`) 720px. The 404 column is 1080px (no sidebars). Use these as the reference for the "no article shift" and width assertions.
- **Sample-page candidates (built HTML):** `/reference/ref-syntax/` has 1 table, 18 code blocks and a 12-entry TOC. `/reference/ref-decorators/` has 1 table, 10 code blocks and 22 TOC links. `/reference/stability/` has 1 wide table, no code and a one-heading TOC, which makes it a good extra edge case for the hide control on a minimal TOC.
- **Persistence-test seeding:** seed with `browser.newContext({ storageState: { cookies: [], origins: [{ origin, localStorage: [...] }] } })`. `addInitScript` re-runs on every navigation and would overwrite the value the test just toggled. A "persists across navigation" check would then pass or fail for the wrong reason. Keep `addInitScript` for the first-paint check only.
- **Escape ordering:** Starlight's `<starlight-menu-button>` registers a `keyup` Escape listener on its parent `<nav>`. That listener calls `setExpanded(false)` and focuses the menu button. At ≥50rem the button is `display: none`, so that `focus()` is a no-op. Because the rail lives in the same `<nav>`, handle Escape on `keydown`. Assert `document.activeElement` after `keyboard.press('Escape')` returns, which covers both keydown and keyup.
- **CI timing:** the two most recent `docs-quality` runs took 22.5 and 23.5 min (≈12.5 min of that is building `vox-cli` for doc lint/doctest; the Starlight build is ≈1m45s). That leaves ≈6.5 min of the 30-min cap, which confirms the layout run must be its own job. Pattern 8's `needs: docs-quality` + `dist` artifact works, but serialises it: PR wall time ≈ 23 + layout. **Alternative:** an independent parallel `docs-layout` job that runs `pnpm build` itself. That build needs no Rust (Pitfall 13), and `git-dates.mjs` degrades to an empty map on a shallow clone (last-updated dates do not affect layout). It costs a duplicate ~2-min build, but the wall time drops to ≈ max(23, layout) and the cross-job artifact goes away. Both options satisfy "stays in `docs-quality.yml` and runs after `pnpm build`". This is the planner's call.

### Known Threat Patterns
| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Tampered localStorage value reaching DOM/CSS | Tampering | Equality check against constant arrays, then `setAttribute` with the constant. Never interpolate storage into HTML, `innerHTML`, `style`, or selectors. Unit-tested with hostile strings |
| Storage access throwing (blocked cookies/private mode) breaking page | DoS | `try/catch` around `window.localStorage` access and `setItem` writes; defaults on failure |
| Inline script injection via config | Tampering | `head` content is `readFileSync` of a committed file. No user/content data is concatenated in. The content is static per build |
| CSP | — | Live site sends no CSP header and has no `public/_headers` or Astro `security.csp` [VERIFIED: live response headers]. If a CSP is added later, this inline script (like Starlight's ThemeProvider script) needs a hash. Note it in the plan's follow-ups, not as a blocker |
