<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub scheduler -> ubuntu-latest | The lane relies on an ephemeral hosted image plus an explicitly installed CUDA toolkit. |
| CUDA toolkit -> Rust/Candle compilation | nvcc and compile/link success validate the CUDA feature graph without asserting device runtime. |
| CI result -> ADR acceptance | A skipped or fail-open job must never count as CUDA-toolchain evidence. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-07 | Spoofing | compile lane presented as runtime GPU proof | high | mitigate | Job/docs explicitly describe CUDA-toolchain compile validation and disclaim device-runtime coverage. |
| T-06-08 | Tampering | workflow failure masking | high | mitigate | Contract test forbids continue-on-error, skip env, fallback backend, and shell success masking in the job. |
| T-06-09 | Denial of service | toolkit install or CUDA compile hang | medium | mitigate | GitHub-hosted runner plus literal slow-lane timeout; every command fails normally. |
| T-06-10 | Repudiation | unauditable CUDA sign-off | high | mitigate | Summary records immutable run URL and head SHA; 06-04 consumes that evidence. |
| T-06-SC | Tampering | package installs | medium | mitigate | Reuse the repository's existing pinned CUDA setup action/version; no new Rust dependency is added. |
</threat_model>
