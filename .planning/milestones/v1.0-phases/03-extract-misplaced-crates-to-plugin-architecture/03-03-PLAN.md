<objective>
Give the host a way to receive webhook events from vox-plugin-webhook without any crate edge
(D-10), and make the plugin's network surface fail closed (D-14).

Purpose: REQ-dead-crate-extract-to-plugin, webhook half (SC#2), plugin side. Today the plugin
auto-starts an HTTP listener on `0.0.0.0:9080` in `init()` with an optional token ("degraded" no-auth
mode), and nothing can get its events out: its bridge types are private, VoxHost has no callback,
and Loader hardcodes the host. D-10 picked a poll extension with a JSON boundary. The orchestrator
side (config + poller) is 03-04.

ABI approval record: the `VOX_PLUGIN_ABI_VERSION` 12 -> 13 bump that a new extension point requires
was accepted by the user as part of D-10 (CONTEXT.md, "ABI" bullet, 2026-09-25). It is additive:
`VOX_PLUGIN_ABI_MIN_SUPPORTED` stays 12. No further approval is needed; no checkpoint is inserted.

Output: two feature commits (Task 1 ABI + inbox, Task 2 fail-closed listener) and an audit task.
</objective>
