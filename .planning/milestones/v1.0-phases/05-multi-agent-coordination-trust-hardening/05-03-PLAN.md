<objective>
Make resource-lock state observable per chat session and render it in the chat execution rail (D-10,
D-11, D-13) — the MESH-01 visibility slice.

Purpose: lock events already flow bulletin -> event bus -> activity_log, but their activity rows
carry no session, `activity_query` cannot filter by session, and the chat surface shows none of it
(05-RESEARCH Pattern 6). This plan closes that path end to end. The real caller that acquires locks
for hopper tasks arrives in 05-05; here the events are produced through the existing Orchestrator
wrappers, which is exactly what 05-05's gate will emit.

Output: three commits (event shape + projection, GUI data path, rail chip + Playwright).
</objective>
