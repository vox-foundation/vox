(c) Record the one documented deliberate exemption. `crates/vox-gui/src/commands/coderabbit.rs`'s
    `sidecar_path_tests` module validates against `contracts/operations/catalog.v1.yaml`
    rather than `build_catalog()`, because `coderabbit` is not a default `vox-cli` feature and
    `vox-gui` links `vox-cli` with default features, so the compiled clap catalog would never
    contain those paths. That is a test-only assertion about a sidecar subprocess surface, not
    a UI-side command declaration, so it does not violate ADR-045 rule 1. Its own doc comment
    already states this rationale and its residual gap (asserts the root command only, not a
    leaf rename). Record it as a known exemption so a later audit does not re-litigate it.

(d) Record why `navigation.ts`'s `PARENT_CHILD_MAP` is NOT a violation: it groups GUI-native
    view keys — several of which (chat, dashboard, memory, browser) have no CLI command at all
    — into sidebar IA sections, and `CommandCatalogEntry` carries no section, parent, or group
    field, so this data could not be catalog-derived even in principle. ADR-045 rule 1's actual
    scope is narrower: no `.tsx` may independently declare a command's *existence* (its name,
    args, or about text) outside what `get_command_catalog()` returns.

(e) Do NOT present `vox ci gui-catalog-parity` as satisfying GUI-02. It compares
    `contracts/operations/catalog.v1.yaml` against `crates/vox-gui/ui/src/types/catalog.ts` —
    a different SSOT pair covering a different surface (RESEARCH.md, Anti-Patterns).
