<objective>
Build the single capture chokepoint that turns web text into pending Untrusted findings, and reroute the two live web sinks (R1 in `execute_search_plan`, the Tavily CRAG mirror) into it.

Purpose: TRUST-02 (web hits never enter the searchable corpus), TRUST-04 (provenance plus a gitignored snapshot), TRUST-05 at the ingest boundary. vox-search has no vox-crypto edge, so hashing, redaction and snapshots run in vox-orchestrator-mcp and reach vox-search through an injected trait, mirroring the existing `LexicalMemoryFallback` injection.
Output: `vox_search::capture::{WebFindingCapture, CapturedWebHit}`, `SearchRuntimeContext::web_capture`, the `vox_orchestrator_mcp::kb_tools::findings` capture pipeline, and deletion of the corpus mirror helper.
</objective>

## Decisions applied

- **D-04:** `persist_web_hits` stays default-on and now means "capture into the `kb_findings` inbox (Untrusted, pending, deduped) when a sink is injected; never into the searchable corpus". Field, default and `SecretId::VoxSearchPersistWebHitsDisabled` unchanged.
- **D-05:** surfaces with no sink capture nothing; this interim regression (GUI/CLI web hits unpersisted) is accepted.
- **D-06:** taint rule (every captured web finding is Untrusted), quote/summary/snapshot caps, snapshot location under the repo root's `.vox/cache/kb-findings/` with `snapshot_relpath` relative to the repo root even when the DB is the user-global one.
- Dedupe key: hex BLAKE3 over origin db-string, a 0x00 separator, `dedupe_scope` else the URL else empty, 0x00, and the content hash. A nullable URL is never a raw UNIQUE column (SQLite treats NULLs as distinct).

| Boundary | Description |
|----------|-------------|
| web providers (SearXNG, DDG, Tavily) → vox-search | attacker-controlled page text and titles |
| vox-search → capture sink → kb_findings | the only path web text may take into storage |
| capture → local filesystem | snapshot writes under the repo root |
