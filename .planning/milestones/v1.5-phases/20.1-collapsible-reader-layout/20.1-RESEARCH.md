# Phase 20.1 Research: Collapsible Reader Layout

## Executive Summary

Phase 20.1 delivers an uncluttered, article-first reading experience across voxlang.org by allowing readers to fold the left navigation into a compact rail and hide the right "On this page" sidebar. When folded, the article widens into the freed space up to a readable maximum width, with code blocks, tables, and playgrounds making full use of the extra room.

The site runs Astro 6.0 with Starlight 0.38.3. Starlight's default layout relies on rigid CSS variables (`--sl-sidebar-width: 18.75rem`, `--sl-content-inline-start`, `--sl-content-width: 45rem`) and hardcoded media queries (`50rem` for sidebar, `72rem` for two-column TOC). 

Our research confirms that the cleanest, most maintainable, and upgrade-safe implementation is a **hybrid architecture**:
1. **Early Head Script (`starlight.head` in `astro.config.mjs`)**: Reads layout preferences synchronously from `localStorage` (`'vox-sidebar-state'` and `'vox-toc-state'`) and sets `data-sidebar-state` and `data-toc-state` attributes on `document.documentElement` before the browser parses the `<body>`. This guarantees **zero Flash of Unstyled Content (FOUC)** and **zero Cumulative Layout Shift (CLS = 0)**.
2. **Selective Starlight Component Overrides**:
   - `Sidebar.astro`: Wraps the default sidebar, injecting a pin/collapse toggle button at the top of the navigation dock and supporting the narrow 3.5rem rail mode with hover/focus overlay expansion.
   - `TableOfContents.astro`: Wraps the TOC navigation, injecting a subtle "Hide" button next to `<h2>On this page</h2>`.
   - `PageSidebar.astro` (or `TwoColumnContent.astro`): Hosts the unobtrusive edge restore tab (`.vox-toc-restore-btn`), fixed at the top-right edge when the TOC is hidden.
3. **Dedicated Reader Stylesheet (`src/styles/reader-layout.css`)**: Injected via `starlight.customCss`. Re-binds Starlight CSS variables based on `[data-sidebar-state]` and `[data-toc-state]`, handles `@media (hover: hover)` overlay expansion without moving the article, widens the main pane fluidly, and honors `@media (prefers-reduced-motion: reduce)`.
4. **Playwright Visual-Stepper Suite (`docs-astro/tests/reader-layout.spec.ts`)**: Systematically tests all 5 states × {phone, tablet, desktop} × {light, dark} across both documentation pages and the voxlang.org landing page, writing screenshots to `docs-astro/test-results/review-bundle/` and hooked into `docs-quality.yml`.

### 1.2 Layout Geometry & CSS Variables
Starlight coordinates layout dimensions using the following variables defined in `@astrojs/starlight/style/props.css`:
- `--sl-sidebar-width`: default `18.75rem` (300px).
- `--sl-content-width`: default `45rem` (720px) — causes severe crowding for tables and wide code blocks.
- `--sl-content-inline-start`: on viewports `>= 50rem`, set in `Page.astro` to `var(--sl-sidebar-width)`.
- `--sl-nav-height`: `3.5rem` (< 50rem) / `4rem` (>= 50rem).
- `--sl-z-index-navbar`: `10`
- `--sl-z-index-menu`: `5`
- `--sl-z-index-toc`: `4`

In `PageFrame.astro`:
```css
.main-frame {
  padding-top: calc(var(--sl-nav-height) + var(--sl-mobile-toc-height));
  padding-inline-start: var(--sl-content-inline-start);
}
@media (min-width: 50rem) {
  .sidebar-pane {
    --sl-sidebar-visibility: visible;
    width: var(--sl-sidebar-width);
    background-color: var(--sl-color-bg-sidebar);
```

In `TwoColumnContent.astro`:

## 2. Architecture: Component Overrides vs Custom CSS & Scripts

### 2.1 Why Pure CSS Is Insufficient
Pure CSS can re-bind `--sl-sidebar-width` and `--sl-content-width`, but interactive collapsible controls (pin toggle, hide TOC button, restore tab) require semantic HTML buttons with accessible ARIA attributes (`aria-label`, `aria-expanded`, `aria-controls`), keyboard focusability, and event handlers. Injecting these buttons purely via client-side DOM scripting causes late pop-in and hydration delay.

### 2.2 Why Component Overrides + CSS Is the Ideal Architecture
Starlight 0.38 provides native component overrides via `starlight({ components: { ... } })` in `astro.config.mjs`.
Overriding specific leaf components allows:
1. **SSR Semantics**: Buttons are rendered directly into HTML on the server.
2. **Clean Separation**:
   - `Sidebar.astro` override renders the left rail pin toggle button.
   - `TableOfContents.astro` override renders the TOC hide button.
   - `PageSidebar.astro` override renders the floating restore button.
   - `src/styles/reader-layout.css` handles geometry, animations, and typography expansion.
   - `astro.config.mjs` `head` injects the early blocking FOUC script.

## 3. Left Sidebar Collapsible Rail & Hover Expansion (SITE-01)

### 3.1 States
- **Pinned (Expanded)**: Default on desktop. Full width `18.75rem`, `--sl-content-inline-start: 18.75rem`.
- **Collapsed (Rail)**: Narrow rail width `3.5rem` (56px). `--sl-content-inline-start: 3.5rem`. Main content shifts left by `15.25rem` (~244px), reclaiming space.
- **Hover/Focus Overlay**: When collapsed, hovering over the rail (`@media (hover: hover)`) or keyboard-focusing inside it (`:focus-within`) temporarily expands `.sidebar-pane` to `18.75rem`. Crucially, `--sl-content-inline-start` remains `3.5rem`, so `.main-frame` **does not shift** — it behaves as a floating modal drawer with `box-shadow: var(--sl-shadow-lg)`.

### 3.2 Rail Specification & CSS
```css
:root {
  --vox-sidebar-rail-width: 3.5rem;
  --vox-sidebar-full-width: 18.75rem;
}

@media (min-width: 50rem) {
  /* When Collapsed to Rail */
  html[data-sidebar-state="collapsed"] {
    --sl-sidebar-width: var(--vox-sidebar-rail-width);
    --sl-content-inline-start: var(--vox-sidebar-rail-width);
  }

  /* Rail Base State */
  html[data-sidebar-state="collapsed"] .sidebar-pane {
    width: var(--vox-sidebar-rail-width);
    overflow-x: hidden;
    overflow-y: hidden;
    transition: width 0.22s cubic-bezier(0.16, 1, 0.3, 1),
                box-shadow 0.22s ease;
  }

  /* Hover Expansion (Overlay without moving article) */
  @media (hover: hover) {
    html[data-sidebar-state="collapsed"] .sidebar-pane:hover {
      width: var(--vox-sidebar-full-width);
      overflow-y: auto;
      box-shadow: 4px 0 24px rgba(0, 0, 0, 0.4);
      z-index: calc(var(--sl-z-index-menu) + 5);
    }
  }

  /* Keyboard Focus-Within Expansion */
  html[data-sidebar-state="collapsed"] .sidebar-pane:focus-within {
    width: var(--vox-sidebar-full-width);
    overflow-y: auto;
    box-shadow: 4px 0 24px rgba(0, 0, 0, 0.4);
    z-index: calc(var(--sl-z-index-menu) + 5);
  }
}
```

### 3.3 Pin/Collapse Toggle Button & ARIA
The toggle button is placed at the top of the sidebar in `src/components/overrides/Sidebar.astro`:
```html
<div class="sidebar-rail-toolbar">
  <button
    id="vox-sidebar-pin-toggle"
    class="sidebar-pin-btn"
    type="button"
    aria-label="Collapse sidebar to rail"
    aria-pressed="false"
    title="Collapse sidebar to rail (Ctrl+[)"
  >
    <svg class="icon-pin" ...></svg>
  </button>
</div>
```
When clicked:
- Toggles `document.documentElement.dataset.sidebarState` between `'collapsed'` and `'pinned'`.
- Updates `aria-label` ("Collapse sidebar to rail" vs "Pin sidebar expanded") and `aria-pressed`.
- Saves state: `localStorage.setItem('vox-sidebar-state', state)`.

## 5. Article Width Expansion (SITE-03)

### 5.1 Dynamic Width Allocation
When sidebars collapse or hide, `--sl-content-width` dynamically scales up from the default `45rem` (~720px):

```css
@media (min-width: 72rem) {
  /* Default: Left Pinned (18.75rem), Right Visible */
  :root {
    --sl-content-width: 48rem;
  }

  /* One Sidebar Folded: Left Rail OR Right Hidden */
  html[data-sidebar-state="collapsed"]:not([data-toc-state="hidden"]),
  html:not([data-sidebar-state="collapsed"])[data-toc-state="hidden"] {
    --sl-content-width: 60rem; /* ~960px */
  }

  /* Both Sidebars Folded: Full Reading Mode */
  html[data-sidebar-state="collapsed"][data-toc-state="hidden"] {
    --sl-content-width: 74rem; /* ~1184px */
  }

  /* When TOC is hidden, main-pane takes full available width and centers */
  html[data-toc-state="hidden"] :global([data-has-sidebar][data-has-toc]) .main-pane {
    width: 100% !important;
    --sl-content-margin-inline: auto !important;
  }
}
```

### 5.2 Wide Content Breakouts
Wide content (code blocks, tables, diagrams, playgrounds) expands to take advantage of the widened container without awkward scrolling:
```css
/* Tables expand cleanly */
.sl-markdown-content table {
  width: 100%;
  display: table;
  max-width: 100%;
}

/* Expressive Code & Playgrounds expand */
.sl-markdown-content .expressive-code,
.sl-markdown-content .vox-playground {
  width: 100%;
}

/* Text readability line length cap */
.sl-markdown-content > p,
.sl-markdown-content > ul,
.sl-markdown-content > ol {
  max-width: 75ch;
}
```

## 6. Responsive & Touch Device Handling (SITE-04)

### 6.1 Viewport Breakpoints
- **Mobile (< 50rem / 800px)**:
  - Stock Starlight mobile drawer (`<starlight-menu-button>`) is preserved.
  - Rail toggle and right restore buttons are disabled/hidden (`display: none`).
  - Mobile TOC remains the native Starlight dropdown accordion (`<details id="starlight__mobile-toc">`).
  - Zero horizontal overflow (`overflow-x: clip` on `.page`).
- **Tablet (50rem <= width < 72rem)**:
  - Starlight already hides the desktop TOC (`lg:sl-hidden`).
  - Left rail collapse is fully supported! Collapsing the left navigation gives tablet readers massive screen space.
- **Desktop (>= 72rem / 1152px)**:
  - Both left rail collapse and right TOC hide are available and operate independently.

### 6.2 Touch vs Hover Differentiation
```css
/* Touch devices (hover: none) DO NOT expand on hover */
@media (hover: none) {
  html[data-sidebar-state="collapsed"] .sidebar-pane:hover {
    width: var(--vox-sidebar-rail-width) !important;
    box-shadow: none !important;
  }
}
```
On touch devices, tapping the pin toggle button expands or collapses the sidebar deterministically without erratic hover states.

### 6.3 Accessibility & Reduced Motion
- All interactive controls have visible focus rings (`:focus-visible`).
- Pressing `Escape` closes temporary overlay expansions and returns focus to the toggle button.
- `@media (prefers-reduced-motion: reduce)`:
```css
@media (prefers-reduced-motion: reduce) {
  .sidebar-pane,
  .vox-toc-restore-btn,
  .main-pane,
  .content-panel {
    transition: none !important;
    animation: none !important;
  }
}
```

## 7. Flash Prevention (FOUC) & localStorage Synchronization

To satisfy SITE-04's requirement for first-paint stability with zero flash:

In `docs-astro/astro.config.mjs`:
```javascript
starlight({
  // ...
  head: [
    {
      tag: 'script',
      content: `(() => {
        try {
          const s = localStorage.getItem('vox-sidebar-state');
          if (s === 'collapsed') document.documentElement.dataset.sidebarState = 'collapsed';
          const t = localStorage.getItem('vox-toc-state');
          if (t === 'hidden') document.documentElement.dataset.tocState = 'hidden';
        } catch (_) {}
      })();`,
    },
  ],
})
```
Because Starlight injects `head` items synchronously into `<head>` before the browser constructs the DOM tree or renders the first paint:
1. `document.documentElement` receives `data-sidebar-state="collapsed"` and `data-toc-state="hidden"` synchronously.
2. The CSS selectors matching `html[data-sidebar-state="collapsed"]` are evaluated during initial style calculation.
3. The page renders directly in the saved configuration on paint 1. There is no flicker, pop-in, or CLS.

## 8. Playwright Visual-Stepper Specification (SITE-05)

### 8.1 Test Suite: `docs-astro/tests/reader-layout.spec.ts`
The test suite covers the full Cartesian product required by SITE-05:
- **Viewports**:
  - Desktop: 1440 × 900
  - Tablet: 820 × 1180
  - Phone: 390 × 844
- **Themes**: Dark (`data-theme="dark"`), Light (`data-theme="light"`)
- **Pages**:
  - Docs Article with TOC: `/tutorials/tut-getting-started/`
  - Landing Page: `/`
- **States**:
  1. Default (Left Pinned, Right Visible)
  2. Left Collapsed to Rail, Right Visible
  3. Left Rail Hover Overlay Expanded (Desktop)
  4. Left Pinned, Right Hidden
  5. Both Left Rail Collapsed & Right Hidden

### 8.2 Test Implementation Outline
```typescript
import { test, expect } from '@playwright/test';
import { mkdirSync, writeFileSync } from 'node:fs';
import { join } from 'node:path';

const VIEWPORTS = {
  desktop: { width: 1440, height: 900 },
  tablet: { width: 820, height: 1180 },
  phone: { width: 390, height: 844 },
};

const THEMES = ['dark', 'light'] as const;
const PAGES = [
  { name: 'docs', path: '/tutorials/tut-getting-started/' },
  { name: 'landing', path: '/' },
];

test.describe('SITE-01..05 Reader Layout Matrix', () => {
  for (const [vpName, vpSize] of Object.entries(VIEWPORTS)) {
    for (const theme of THEMES) {
      for (const pageInfo of PAGES) {
        test(`${pageInfo.name} - ${vpName} - ${theme} states`, async ({ page }) => {
          await page.setViewportSize(vpSize);
          await page.goto(pageInfo.path, { waitUntil: 'domcontentloaded' });
          await page.evaluate((t) => document.documentElement.dataset.theme = t, theme);

          const bundleDir = join(process.cwd(), 'test-results/review-bundle');
          mkdirSync(bundleDir, { recursive: true });

          // 1. Initial State Screenshot & Checks
          await expect(page.locator('body')).not.toHaveCSS('overflow-x', 'scroll');
          await page.screenshot({ path: join(bundleDir, `${pageInfo.name}-${vpName}-${theme}-01-default.png`) });

          if (vpName === 'desktop') {
            // 2. Collapse Left Sidebar
            const pinBtn = page.locator('#vox-sidebar-pin-toggle');
            await pinBtn.click();
            await expect(page.locator('html')).toHaveAttribute('data-sidebar-state', 'collapsed');
            await page.screenshot({ path: join(bundleDir, `${pageInfo.name}-${vpName}-${theme}-02-left-collapsed.png`) });

            // 3. Hover Rail Expansion
            await page.locator('.sidebar-pane').hover();
            await page.screenshot({ path: join(bundleDir, `${pageInfo.name}-${vpName}-${theme}-03-left-hover-overlay.png`) });
            await page.mouse.move(500, 500); // unhover

            // 4. Hide Right Sidebar (if TOC present)
            const hideBtn = page.locator('#vox-toc-hide-btn');
            if (await hideBtn.isVisible()) {
              await hideBtn.click();
              await expect(page.locator('html')).toHaveAttribute('data-toc-state', 'hidden');
              await expect(page.locator('#vox-toc-restore-btn')).toBeVisible();
              await page.screenshot({ path: join(bundleDir, `${pageInfo.name}-${vpName}-${theme}-04-both-collapsed.png`) });

              // 5. Restore Right Sidebar
              await page.locator('#vox-toc-restore-btn').click();
              await expect(page.locator('html')).toHaveAttribute('data-toc-state', 'visible');
            }
          }
        });
      }
    }
  }
});
```

## RESEARCH COMPLETE

### Key Findings Summary:
1. **Layout Variables**: Starlight 0.38 controls sidebar width via `--sl-sidebar-width` and content offset via `--sl-content-inline-start`. Collapsing the sidebar dock to a `3.5rem` rail while keeping hover expansion fixed as an overlay cleanly avoids content shift.
2. **Component Overrides**: Overriding `Sidebar.astro`, `TableOfContents.astro`, and `PageSidebar.astro` in `astro.config.mjs` allows SSR rendering of all buttons with complete ARIA attributes without brittle DOM hacks.
3. **FOUC Elimination**: Injecting a small synchronous script into Starlight's `head` config directly modifies `document.documentElement.dataset` from `localStorage` before HTML body parse, ensuring 0ms layout shift.
4. **Landing Page Equivalence**: `docs-astro/src/content/docs/index.mdx` has `data-has-sidebar` and `data-has-toc` matching doc pages, so reader layout controls work identically on the homepage and article pages.
5. **Testing & CI**: Playwright can run against `pnpm preview` or built dist, screenshotting each state across phone, tablet, and desktop, archiving artifacts in `docs-quality.yml`.
