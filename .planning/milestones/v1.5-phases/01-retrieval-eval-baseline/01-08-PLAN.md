Propose relevance labels for the first half of the user's seed questions, and generate paraphrase-style expansion candidates for them. Use a multi-method candidate pool, so later dense or hybrid retrievers are not penalised for relevant docs that BM25 missed (pooling bias, pitfall P5).

Purpose: EVAL-02 needs qrels the user approves and an LLM expansion the user prunes. This plan runs in parallel with 01-09 (second half), which splits the reading-heavy pooling across two executor contexts.
Output: `golden-draft/qrels-proposal-a.md`, `golden-draft/expansion-proposal-a.md` (GUID-free, under the phase dir per AP-13).
</objective>

- AP-02: the agent proposes qrels and expansion only; the user approves and prunes.
- AP-06: chunk id = `doc_path#heading_path`, heading_path = title › H2 › H3.
- AP-11: every query needs ≥1 doc row > 0 and ≥1 chunk row = 2.
- AP-13: drafts live in golden-draft/, are GUID-free, and are deleted in 01-10.

Half assignment (shared with 01-09):
- Number the draft's query lines matching `^- \[(where|how-to|concept|policy|why|troubleshoot|multi-hop)\] ` in file order as q001..qNNN (n = count).
- This plan owns q001..q(ceil(n/2)). 01-09 owns the rest.
- Expansion handles here are A01, A02, ….

Tools (build once with `cargo build -p vox-cli`, then use `./target/debug/vox`):
- `vox kb eval --query "TEXT" --top 20`: BM25 pool over the snapshot.
- `vox kb eval --headings DOC_ID`: valid heading_paths.
- `rg -n -i` / `git ls-files docs/src`: path/title grep, always excluding `docs/src/archive`.
- `vox graph query "TERMS"`: only if `vox graph status` shows the corpus fresh; otherwise write "graph: unavailable" in the pool line.

Never read docs/src/archive/ (AGENTS §Archival Protocol). Never paste query text into any file outside golden-draft/. Never put the canary GUID in any draft.

Proposal block format (Markdown; one block per query; the user edits it in 01-10):
- First line of the file: `approved_by:` (left blank for the user).
- Block heading: `## qNNN [intent] question text` (verbatim from the draft).
- `pool:` line naming the methods used and the BM25 rank of each proposed doc.
- `answer:` line with an excerpt of at most 200 chars and its chunk id.
- Rows `- [x] doc S DOC_ID` and `- [x] chunk S DOC_ID#HEADING_PATH` for proposed labels (S = 2 answers / 1 relevant). Top pool items you considered and rejected get rows as `- [ ] …` so the user can flip them.

Expansion block format:
- Heading: `## Aii [intent] (paraphrase of qNNN) question text`.
- A `- [ ] keep` line (unchecked; the user decides).
- The proposed qrel rows, copied from the source query and adjusted if the paraphrase shifts intent.
