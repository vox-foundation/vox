## Mutation protocol (apply to every row)

1. Precondition: `git status --porcelain -- <file>` prints nothing. Plans 12-01..05, 12-07 and 12-08 are committed, so restoring by checkout cannot discard work. If anything prints, stop and report.
2. Presence before: run the row's presence check (`grep -cF '<guard text>' <file>`) and confirm it prints `1`. Insertion rows instead check that `grep -c 'MUTATION-12-06' <file>` prints `0`.
3. Apply the mutation with the Edit tool. Insertion rows add a statement ending in the comment `// MUTATION-12-06`.
4. Presence after: the guard check now prints `0`, or for insertion rows the marker check prints `1`. Any other result means the mutation did not land: stop and investigate rather than trusting the test.
5. Run the mapped test and confirm it FAILS. Record the first failing assertion or panic line.
6. Restore with `git checkout -- <file>`, re-run the presence check (back to `1`, or marker `0`), and confirm `git diff --quiet -- <file>` exits 0.
7. Re-run the mapped test and confirm it PASSES.

Do at most one mutation per file at a time, and never run `cargo fmt` while a mutation is applied. Test fixtures are mutation-safe by construction (12-04 rule): nonexistent remotes, `{}` args, writes under `target/`, isolated DB. An un-parked call therefore errors harmlessly.
