<objective>
Route `vox model eval-corpus` through the model registry and the LLM facade, including local `mens/*` checkpoints, with seeded, fully drawn sampling and correct infra-error accounting (BENCH-01, BENCH-02; D-02, D-03, D-12).

Purpose: `generate_candidate` hardcodes an OpenRouter config, so MENS (the model the program exists to measure) is unroutable; the facade's own rate-limit prefixes are scored as model failures; and there is no seed. This plan resolves the model once per run through the existing `resolve_target` + `llm_config_for_spec` pair (the same pair `vox models bench` and `vox chat --model auto` use), adds `--seed` / `--top-p`, extracts the sample loop into a testable `draw_samples` that records one `SampleRecord` per sample, and fixes infra classification. The typed report that consumes these records is wired in 12-07; until then `run()` keeps writing today's report from the same outcomes.
Output: routing, seeding and sample-recording in eval_corpus.rs; an assertion-failure bit on `VerifyOutcome`.
</objective>

## Flagged assumption (spec-less edge probe)

BENCH-01's edge probe came back `unclassified`, so per protocol it stays unresolved and is flagged here rather than auto-resolved. Manual review found these routing edges; the truths above cover the first three, the fourth is a backstop truth, and the fifth is left to the reviewer:
1. unknown `mens/*` id → hard error (truth 2);
2. `provider:model` ids for known prefixes → `resolve_target` synthesis (unchanged behavior, covered by the bench tests);
3. `mens/foo/checkpoint-N` ids → resolved by `ModelRegistry::get` to the parent spec, so they route to voxlocal like the parent; the label check in 12-07 then refuses them because sub-checkpoints carry no card;
4. `VOX_LOCAL_ENDPOINT` unset (port 11434 vs 11435) → warning (backstop truth);
5. a voxlocal endpoint that is up but serving Ollama rather than `vox mens serve` → no automatic detection; the provider-reported model string recorded per sample (12-07 provenance) is the evidence. Reviewer: confirm this is acceptable.
