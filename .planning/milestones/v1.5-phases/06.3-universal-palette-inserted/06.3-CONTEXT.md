# Phase 06.3: Universal Palette (INSERTED) - Context

**Gathered:** 2026-10-10
**Status:** Ready for planning

<domain>
## Phase Boundary

Make the existing ⌘K Omnibar (`crates/vox-gui/ui/src/components/layout/Omnibar.tsx`) the one place to find and act on anything in Vox, driven by the Phase 06.2 capability index:

- **Find:** searching any CLI verb, MCP tool, skill, crate, doc, setting or keybind returns it (DISC-05).
- **Act:**
  - selecting a surface navigates to it
  - selecting a CLI verb runs it (only when safe) or opens a prefilled Catalog form
  - selecting anything else opens an explain card (DISC-06)
- **Shortcuts:** `?` opens a generated shortcut sheet, and every keybind is also a palette action (DISC-07).
- **Tests:** a Playwright spec with mock IPC covers search and run, with review-bundle screenshots.

Out of scope here:
- Capability Explorer and the coverage gate (06.4)
- Architecture Atlas (06.5)
- time-to-find journeys (06.6)
- semantic search (DISC-v2-02)
- per-panel contextual help and a tour (DISC-v2-01)

</domain>

<decisions>
## Implementation Decisions

### Run vs open safety
- **D-01:** Selecting a CLI verb **opens the Catalog form, prefilled, with an explicit Run button, by default**. It runs directly from the palette only when the op is declared read-only (`side_effect_class: read_only`) AND has no required arguments.
  - **Reversibility:** costly — users learn the Enter behavior.
- **D-02:** **Backfill `side_effect_class: read_only`** in `contracts/operations/catalog.v1.yaml` for verbs we can verify are read-only (status, list, show, explain, features, doctor, and similar). Apply each by checking the handler, never by name alone.
  - Anything unclassified (null) is **treated as side-effecting**.
  - Add the classification to the 06.2 capability index row.
  - Ratchet it: the count of null side-effect classes on CLI ops may only fall, following the 06.2 owner-ratchet pattern.
- **D-03 (REVISED 2026-10-10 after research):** **Gate scope is `side_effect_class: destructive` only.** The D-02 backfill reviews the ~22 destructive-looking verbs (`db reset`, `rollback`, `remove`, …) and marks the real ones. `reversible: false` is NOT a gate trigger, because it appears on read-only ops too. Add an enum to `catalog.v1.schema.json` for `side_effect_class`.
- **D-03 (original wording):** **The backend enforces a confirmation token for destructive ops.**
  - `execute_command` (`crates/vox-gui/src/commands/execute.rs`) must refuse an op whose catalog `side_effect_class` is destructive or irreversible unless the call carries an explicit `confirmed: true`.
  - The UI sets that flag only after a confirm dialog.
  - Unknown or unclassified ops are not blocked by the backend. The UI default from D-01 covers them.
  - The backend reads classification from the bundled capability index (`vox-capability-registry`, already a dependency path), not from the UI.
  - **Reversibility:** costly — changes an IPC contract other callers use.
- **D-04 (REVISED 2026-10-10 after research):** **Run output** is a short toast with the exit status and an excerpt, plus a **"View full output" button that opens a dialog** with the complete stdout and stderr. The Console is a live xterm PTY with no API to append foreign output, so the original "full output in Console" plan isn't possible. Do not stream output inside the palette.

### Index wiring & load
- **D-05 (REVISED 2026-10-10 after research):** **The index replaces surface and command rows. For docs and skills it only fills gaps.** The existing docs source (669 pages) and skill source (whose rows also deploy the skill) stay. The index adds only docs and skills those sources lack, deduped by id or normalized relative path. The bullets below apply to surface and command rows; for docs and skills, read "replaces" as "fills gaps".
- **D-05 (original wording):** **The capability index replaces the overlapping federated sources.**
  - The `surface`, `command`, `skill` and `doc` rows come from `capabilityIndex.generated.ts`.
  - `setting`, `policy`, `action`, agents, on-screen hits, graph and backend hits stay as their own sources.
  - Update `contracts/gui/omnisearch-index.v1.yaml` to record the new source per kind.
  - No row may appear twice from two sources.
- **D-06:** **Load the index lazily on the first ⌘K**, via dynamic `import()`, cached in memory afterwards. The startup bundle must not grow by the 514 KB artifact. Show a brief loading state on the first open.
  - **Reversibility:** reversible.
- **D-07:** **Rows with no direct GUI action** (MCP tools, crates, and capabilities without a surface) open an **explain card in a drawer**.
  - The card shows the same groups as `vox explain`: equivalents, location, status, related, docs.
  - It offers "Open form" for CLI ops, "Copy MCP name" for MCP tools, and "Open docs" when a docs link exists.
  - Render it from the index data in TS. Do not shell out to `vox explain`.

### Ranking & layout
- **D-08:** **Keep the existing capped facet groups** (Surfaces, Commands, Docs, On screen, Graph; `FACET_CAP`), fed from the index per D-05. Add one **top "Best match" row**: the single best hit across all facets.
- **D-08a (2026-10-10):** **Add a capped "Tools & crates" facet** for MCP tool and crate rows. Commands stay capped at `FACET_CAP`, with a "show more" hint pointing at the 06.4 Explorer.
- **D-09:** **Each result row shows a kind icon plus chips** for the interfaces it's reachable through (CLI · GUI · MCP), the domain, and its keybind chord if it has one.
- **D-10:** **Add a `#` prefix mode** for crate and layer rows, alongside the existing `>` commands, `@` agents and `/` skills (`parsePaletteQuery` in `components/layout/paletteSources.ts`).

### Shortcut sheet & keybind actions
- **D-11:** A bare **`?` opens the shortcut sheet only when focus is not in** an input, textarea or contenteditable. It is also available as a palette action and through a new registry binding (`Mod+/`).
- **D-12:** The sheet lists **all keybinds from the registry** (`lib/keybinds.ts`, `ACTION_REGISTRY` + `DEFAULT_BINDINGS`), showing the user's current rebinds as they're set. It is generated from the registry, not hand-written.
- **D-13:** **Every registry action is a palette row** labelled with its current chord (for example "Toggle sidebar ⌘B"). Selecting the row runs the action. Use the existing `action` federated kind. A new registry entry appears automatically.

### Research-driven decisions (2026-10-10, from 06.3-RESEARCH.md)
- **D-14:** **Fix the 06.2 TS artifact first.** `capabilityIndex.generated.ts` currently fails `pnpm typecheck` with TS2590 (union too complex).
  - Change `emit.rs::generate_ts` to emit the rows in chunks; 250–800 rows per chunk pass.
  - Extend the TS row with the fields the palette needs and the Rust `IndexRow` already has: equivalents, tier, status/coverage, `side_effect_class`, `catalog_form`, source/docs.
  - Regenerate through the generator only. This is a 06.2 regression, so it is the first task.
- **D-15:** **The confirm gate adds no new crate edge.**
  - Put the check in `vox-capability-registry`, as `CapabilityIndex::confirmation_required` or similar.
  - Expose a thin wrapper in `vox-cli::command_catalog`.
  - Call it from `crates/vox-gui/src/commands/execute.rs`. `vox-gui` already depends on `vox-cli`, which already depends on the registry.
  - Keep the logic outside `execute.rs` as far as possible: hosted PR CI excludes `vox-gui` from check/test (`ci.yml:87-95`), so tests must live in the registry and vox-cli.
  - The gate must evaluate **`path` plus the leading `__argv` tokens**, because `path=['plugin'] + __argv=['remove', …]` would otherwise bypass it. Back this with a mutation proof.
  - `confirmed: Option<bool>` is wire-compatible with every existing Tauri caller.
- **D-16:** **Fix the existing `execute.rs` `__argv` bug** in the same change. When `__argv` is present the structured args are dropped, so every typed Catalog form flag is silently discarded (`execute.rs:22-31`). Without this fix a prefilled form is useless.
- **D-17:** **Keybinds come from one shared store.** Rebinds persist in the backend DB (`gui.keybinds`), but App and Settings each load their own copy once, so a rebind doesn't reach App handlers or the sheet until restart. Give the sheet, action rows and App one shared live store. `dispatch-intent` has no App handler: give it one, or exclude it from runnable action rows with a reason.
- **D-18:** **Read-only semantics.** `side_effect_class` `none` counts as read-only. Classification is strict across all flag combinations: an op is read-only only if no flag makes it write.
- **D-19:** **Matching.** Order is exact alias/id/CLI path/MCP name, then prefix, then token containment, with Jaro-Winkler used only as a typo fallback. JW alone is noisy: `vox fabrica fmt` hits 755 rows at 0.75. Budget about 2–4 ms per keystroke over 1544 rows.
- **D-20:** **Update existing e2e.** `palette-search-navigate.spec.ts` will change behavior because `fmt` becomes an exact CLI hit and Best match. Update the spec to the new contract rather than weakening it.

### Claude's Discretion
- **Ranking tie-breaks** (the user said "use best judgement"). Default:
  1. Exact id, CLI path or MCP-name match beats fuzzy, reusing the 06.2 resolver semantics.
  2. Then fuzzy score.
  3. Close or tied scores: a row with a dedicated surface wins.
  4. Then catalog tier (Recommended > Advanced > FeatureGated).
  5. Then local recent use.
  - Keep it deterministic, with id as the final tie-break.
- **Further prefixes** beyond `#` (the user said "use best judgement" plus `#`). Add more only if they clearly earn their keep. `:` for MCP tools is the candidate; `?` alone is reserved for the sheet (D-11).
- Fuzzy matching algorithm in TS. It may mirror the 06.2 Rust scorer (`max(jaro-winkler, 0.9 × token containment)`, threshold 0.75) for consistency.
- Exact drawer and component reuse for the explain card, and the loading-state UI.
- How the Catalog form gets prefilled from a palette selection (the arg shape of the existing `CommandCatalogForm`).

</decisions>

## Existing Code Insights

### Reusable Assets
- The Omnibar facet engine (`omnibarFacets.ts`): capped and fail-independent, so swap its sources rather than rewriting it.
- The `activateRow` switch already handles navigate, command, doc, skill, setting, policy and agent. Add `explain` and `action` arms.
- The Catalog generic form (`CommandCatalogForm.tsx`) already renders clap-derived forms for every CLI command; it is the "Open form" target.
- The keybind registry and `chordFromEvent` are the source for the shortcut sheet and for action rows.
- The 06.2 index already carries equivalents, domain, tier and coverage per row. The palette chips (D-09) need no new data except `side_effect_class` (D-02).

### Established Patterns
- Generated GUI data lives in `src/generated/*.generated.ts`, produced by `vox ci …` generators and drift-gated.
- Toast plus Console for command output (`/audit` in `App.tsx`).
- Prefix modes are parsed in one place (`parsePaletteQuery`).

### Integration Points
- `Omnibar.tsx` sources and `activateRow`.
- `App.tsx` `onRunCommand` and the Console surface.
- `execute.rs` (Tauri IPC) confirm gate.
- `catalog.v1.yaml` → operations-sync → capability-index generator (the `side_effect_class` field).
- `omnisearch-index.v1.yaml`.

## Specific Ideas

- Roadmap success criterion 1 lists keybinds and settings among the things search must return. Settings stay on their existing source (D-05); keybinds come in as action rows (D-13).

- Watch item from 06.2: many index titles are boilerplate (e.g. "Fabrica Fmt", "CLI operation `vox add`"). Searching by CLI path (`vox fabrica fmt`) must work even when the title is poor.
