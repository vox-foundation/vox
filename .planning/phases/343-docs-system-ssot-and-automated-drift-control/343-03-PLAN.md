<objective>
Add a strict prose-vs-CLI gate: every prescriptive `vox <cmd> [--flag]` mention in agent files must name a real command and real flags, and no "(planned per …)" claim may sit next to a command that already exists. Measure the same check on reader-facing docs pages so the user can decide how to handle those findings.

Purpose: DOCS-DRIFT-03 (detect). The existing resolver in `vox-doc-pipeline` accepts any mention whose first token is known (`claims/resolver.rs:505-508`) and the registry omits 14 real `vox ci` subcommands and all flags (RESEARCH F3), so ground truth is the in-process clap tree (`build_catalog()`) unioned with the registry for feature-gated groups. The check is local to the new stage; the ledger's registry-level CLI resolution in `vox-doc-pipeline` is left unchanged because that crate cannot see the clap tree, and the stage is the gate. First fixes named by the roadmap: AGENTS.md `vox audit retirement` / `vox audit effort`.
Output: `docs_cli_claims.rs` + stage, agent-file fixes, a measured reader-facing count, and the fix-or-baseline decision for 343-04.
</objective>
