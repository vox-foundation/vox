<objective>
Make `vox mens serve` refuse an adapter unless its on-disk collateral report re-validates: present, status pass, the slice block complete and labelled, every slice's accuracy and think-initiation within 5% when recomputed from the stored numbers, and every per-slice `reasoning_report.json` scored with n 32.

Purpose: the serve half of GATE-01, and the serve check that the GATE-02 label is present. Today serve reads only `status`; a hand-edited or old-format `pass` binds.
Output: `vox_eval::reasoning_slice::verify_reasoning_slices` and `assert_collateral_gate` in `dispatch.rs`, called from the serve arm.

A green test is not a model score. No model weights are needed or used.
</objective>

**Locked decisions this plan implements.**
- D-01: accuracy and think-initiation compared separately per slice at 0.05; a drop on either refuses.
- D-02: serve requires all three slices and both metrics; a missing slice report, a `not_scored` report, or `n` other than 32 refuses. Old-format passing reports are refused (none exist under `mens/runs`, which holds only `logs`).
- D-03: non-finite values or a zero reasoning pre-score refuse; the generic `eval_collateral_damage` stays untouched.
- D-04: serve requires the slice label (`scope_note`, `slice_size`, per-slice `n`) to be present.
- D-05: serve only reads reports on disk. No model run, no before/after numbers.
- D-07: serve recomputes from stored numbers and does not trust `status` alone (second line of defense behind the writer's stale-report removal).
- D-10: numeric equality between the collateral report's post values and `reasoning_report.json` is not required; serve checks `status == "scored"` and `n == 32` only.
- D-08/D-09: no `VOX_*` env var, no crate dependency, no numeric baseline; the research doc stays unedited and unstaged.

**Claude's discretion (recorded).** Serve requires the stored `threshold` to equal `CollateralDamageConfig::default().max_degradation_rate` and always recomputes with the default config, so an edited threshold cannot widen the bar. Serve requires `scope_note` to equal `REASONING_SLICE_SCOPE_NOTE` exactly. Every new refusal message starts with `eval_collateral_damage` so existing greps keep matching.
