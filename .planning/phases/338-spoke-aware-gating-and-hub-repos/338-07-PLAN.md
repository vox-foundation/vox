<objective>
Gate the vox-lang spoke on hidden-test compile-and-test pass rate and wire the rust bench into the
rust gate (D-09, D-22, SPOKE-07). No model runs in this plan; plan 338-08 runs the 0.6B adapter and base
controls after a human approves the wall-clock.

**Ordering (D-15):** start only after phases 335 and 337 have landed and plans 338-04, 338-05 and
338-06 are done. `eval_gate/{policy,check_run,run_gate}.rs`, `reasoning_eval.rs` and
`item_checkpoint.rs` are shared with 335/337; the executor re-reads them at execution time.

**Pre-registration:** floors are fixed in the YAML before any model result exists: humaneval_vox
min_pass_rate 0.25 (same bar as the ladder's pass_at_k min_at_1) and rust_bench 0.50 (provisional per
D-22, no rust adapter exists). Changing a floor later is a policy change: it changes policy_blake3 and
re-gates every receipt. Floors are never tuned to observed results.

D-14: reuse `vox model eval-corpus`, `EvalCorpusReport`, `verify_program`, `with_backend`,
`ItemCheckpoint`, plan 338-05's SuiteReport and suite_verdict, and plan 338-04's rust bench. vox-ml-cli is
over its LoC budget, so eval_spoke.rs is thin glue (argument parsing, backend wiring, file IO); logic
lives in vox-eval and vox-corpus. No new crate edge.

Expected wall-clock (D-16): no GPU here. The ignored HumanEval-Vox oracle test runs `vox check` and
`vox run --mode interp` on about 30 held-out references: about 1-3 min. Unit tests: seconds.

Purpose: a vox-lang adapter must pass tests it never saw, and must beat the base, to be promoted.
Output: suite rows in check_run, two suite entries in gate YAMLs, `vox mens eval-spoke`.
</objective>
