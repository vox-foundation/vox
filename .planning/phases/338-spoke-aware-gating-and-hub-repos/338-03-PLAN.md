<objective>
Turn the wired-vs-paper inventory (338-RESEARCH.md "Wired vs paper inventory") into code: each paper
key in the four gate files is wired with a producer test or deleted (D-03, SPOKE-02). Leave no paper.

**Ordering (D-15):** start only after phase 335 has landed and plan 338-01 is done. `check_run.rs` and
`policy.rs` are shared with 335 and with plan 338-01's collateral change; the executor re-reads both at
execution time and re-confirms each verdict below against the landed code before deleting anything
(a key 335 wired since research is kept and given its producer test instead).

Decisions per key (from research, re-confirmed at execution):
- WIRE: `supervised_ratio` (producer exists: training telemetry; only the reader is wrong).
- KEEP (already wired): `pass_at_k`, `anti_stub`, `collateral_damage` (including `require_report`).
- DELETE: `truncation` (no writer), `throughput` (training speed is not adapter quality, and the
  device key falls back to `cpu`), `eval_local` (scores the training corpus, not the adapter),
  `per_context` (empty), `modal_mix` (no run-dir producer shown; keep only if
  `rg -n "modal_breakdown|mix_report.json" crates` finds a writer into the run dir path check_run reads,
  then give it a producer test), `mcp_tool_schema` (no writer), `review_recurrence` (no producer),
  `rust_compile_rate` and `clippy_clean_rate` (score corpus reference answers; replaced by the rust
  bench suite in plan 338-07), `tool_call_valid_json_rate` and `tool_name_exists_rate` (score corpus
  rows; replaced by the agent episode suite in plan 338-08), `bfcl_accuracy` and
  `eval-gates-bfcl.yaml` (no adapter run writes `bfcl_results.json`), dead struct fields
  `version` and `perplexity`.
- The `eval_gate:` key in domain-profiles.yaml stops being paper in plan 338-06 (spoke routing reads it).

D-14: deletion over new code; test-first for the wired key; no new crate edge.

Purpose: a gate file states only what is actually measured on the adapter.
Output: smaller gate files, a strict policy loader, an inventory test.
</objective>
