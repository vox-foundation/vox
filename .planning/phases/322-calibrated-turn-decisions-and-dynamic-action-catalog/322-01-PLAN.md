## Decision: how "unset" is represented (L-13)

Explicit fields, not sentinel-equals-Default. Add to `McpChatModelResolution`:
`pub task_unset: bool` and `pub complexity_unset: bool`, both `false` in `Default`.

Why not the sentinel: on this branch three live call sites set the Default values *explicitly*, so a sentinel would let the pack override deliberate choices:
- `models_tools.rs:61-77` (`vox_suggest_model`): `"codegen"` maps to `task_category: CodeGen`; Testing/Debugging/General/ToolOrchestration map to `complexity: 5`.
- `chat_tools/chat/message.rs:977-981` (cognitive profile): `"fast"` and unknown profiles set `complexity: 5`.
Default `false` is fail-safe: a call site that never sets the field keeps today's value, so a forgotten site can lose the pack but can never be overridden by it. Only the default chat agent turn (`try_run_agent_turn`, message.rs:270-280) sets both to `true`; `resolution_for_tier(Some("cloud"))` (message.rs:158-170) sets `complexity_unset: false` because it raises complexity. `prefer_local` has no caller field: `resolve.rs:385-386` derives it from the caller's task, so it counts as unset exactly when `task_unset` is true. `allow_free_in_performance_mode` is "unset" when `res.clutch.is_none()` at the decide() site, which is after the source-policy block (resolve.rs:278-311) has written any policy-derived clutch into `res.clutch`.
