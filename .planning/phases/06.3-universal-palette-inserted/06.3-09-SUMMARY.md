# Phase 06.3 Plan 09: Palette run path Summary

**Enter on a read-only compiled-in leaf CLI row now runs it straight from the palette with a toast and a full-output dialog; every other verb opens the prefilled form or the explain card, destructive runs need an explicit 'Run anyway', and the Catalog form sends positionals through the gated `execute_command`.**

## Accomplishments

- `decideCliActivation` is the single D-01 decision: `run` only for read_only/none, compiled-in, leaf, no required arg; `explain` when the live catalog lacks the path or it is not compiled in; otherwise `form`. The same decision drives the trailing row hint (`↵ runs`, `↵ opens form`, `↵ explains`) and Enter.
- `voxTransport.executeCommand(path, args, { confirmed })` goes straight to `execute_command`. The Catalog form no longer uses `callTool` (no MCP detour around the gate).
- Positional arguments (no long, no short) go out as `__positionals` in declaration order; options keep their long name; button reads `Run`.
- A `confirmation_required: <id>` rejection opens `ConfirmRunDialog` (Cancel focused); `confirmed: true` is sent only from its confirm callback, in both the form and the palette run handler in App.
- Toasts gained an optional action button; palette runs show title `vox <path> — exit N`, a body of at most 400 characters, and `View full output` (RunOutputDialog, text-only `<pre>` blocks).
