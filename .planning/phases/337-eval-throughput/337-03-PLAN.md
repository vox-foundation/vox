<objective>
Pre-register the sequential McNemar rule in the ladder policy and make the policy loader refuse an
invalid one (THRU-10 policy part; D-10, D-11, D-13, D-22, D-23). The rule ships inactive:
`rule: fixed_n` stays the active rule until the user decides to flip it (a deferred, one-way decision
for receipts; not part of this plan).

**Ordering (D-14, D-15, D-26):** start only after phase 335 has landed; `eval-gates-ladder.yaml` and the
gate policy loader are 335's files, so the executor re-reads both at execution time. This block must land
before 338-02, because 338-02's `policy_blake3` hashes the whole parsed YAML: adding the block after
receipts exist would make every receipt stale on arrival (research Pitfall 7).

**Why the exact check runs only for an active rule:** the exhaustive size computation takes seconds, and
the policy is loaded by eval-gate, serve and collateral runs. Structural checks run on every load; the
exact `check_size` runs whenever `rule` selects the sequential rule (the only state in which the schedule
can judge anything) and in a test over the committed file. An edited schedule therefore cannot gate a
run without passing the exact check.

Purpose: the stopping rule is fixed in the repo before any adapter is judged by it.
Output: YAML block, typed loader with guards, tests, a mutation proof.
</objective>
