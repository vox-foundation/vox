   `first_diagnostic` helper in vox-corpus or a user-approved vox-compiler edge (decision 1).

   carries fixes and breaks. Should a regression (a break) take priority as the loss? (decision 2)
3. The duplicate-sentence rule as written on the docs page (decision 3).
4. 0.6B under its old report reads `failed` and quotes the refusal, because the 338-01 check order
   returns Failed for any non-pass report even under a retired rule (decision 4).
5. Card-only push writes the local inspection label into the remote manifest; until 338-01 lands
   that label can still read `passed` for a stale size while its card says needs re-gate (339-04
   T-339-12). Accept until 338-01, or hold the push for those sizes.
6. Where per-spoke gate detail from 338-02 goes: the index grid cell, a collapsed block, or nowhere
   (decision 8).
7. The spoke shown for every trained size is `vox-lang`, declared in hub-cards.yaml with its
   provenance on the docs page, until 338-06 derives it (decision 9).
8. Re-gate time estimates come from phase 337's projections (low confidence), labelled as estimates
   (decision 10).
9. The index's held-out comparison lists sizes whose reports pass the current prompt-protocol check,
   read as the spec's "current-rule results only".
10. Whether a gated-current size (if 0.6B's 128-item re-gate passed) should get a new weights
    version `v<N>` now, or card-only like the rest.
11. The reduced "Use it" block on non-passed cards (checker W8). Those cards show the pull command
    with ` --allow-ungated` and one sentence about what `vox mens serve` does with an ungated
    adapter, and no serve command, request or recorded output (339-07). Keep it, or drop "Use it"
    from non-passed cards entirely.
12. Gate and collateral evidence from before phase 335's serving change. Collateral reports and gate
    receipts recorded before it also ran the adapter through the old serving path. This phase
    gates only held-out outputs and scores on `adapter_serving` (checker B1) and keeps the gate
    state as `gate_of` computes it, since 338 owns gating. Should 338-01 also require the serving
    identity on collateral evidence, so those sizes read needs re-gate for that reason too?
