<objective>
The two data inputs every card needs besides the gate fact: the per-size wording file (CARD-05) and
the D2 before/after examples from stored eval checkpoints (CARD-03). Both are pure and data-driven;
neither writes card prose (that is 339-05 and 339-07).

Orchestrator decisions applied here: compiler verdicts come from stored fields only (no new helper,
no new edge); the loss is the literal spec rule and the totals carry fixes AND breaks; the spoke fact
until 338-06 lands is `default_spoke: vox-lang` declared in hub-cards.yaml with its provenance;
eval-time estimates come from hub-cards.yaml, labelled as estimates, never from Rust.

Serving-path gate (checker B1): phase 335 changed how adapters are served (NF4(W) plus the
full-precision LoRA arm, instead of NF4(W+ΔW)) and stamps `adapter_serving` into every new adapter
checkpoint header. Every adapter output and score recorded before that is from the old path. This
plan adds the one gate every later card plan uses: `facts::adapter_evidence`. It does not change
what `RunRecords::load` returns for the legacy model card, so the legacy goldens do not move.

Verdict phrases (checker W2): the six phrases are the list 339-02 wrote on the docs page; this plan
puts them in code verbatim, and 339-07 tests that the two stay equal.

Purpose: real base-vs-adapter Vox output on every trained card, chosen by a rule nobody can tune.
Output: `mens/config/hub-cards.yaml`, `hub_card::config`, `hub_card::examples`, checkpoint loading in
`facts.rs`, a committed real-schema evidence sample.
</objective>
