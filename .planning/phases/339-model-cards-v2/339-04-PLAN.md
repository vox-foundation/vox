<objective>
Build the card-only Hub push the user's brief requires (CARD-12): "card-only for every size except
one whose weights are gated-current". Research §Q10 found it does not exist: the README is inside the
hashed bundle manifest, so a card change makes a published size `Diverged`, and today's `--push`
either re-publishes the whole bundle with a new version tag or refuses.

**Why this matters before 338-01 lands:** until 338-01 replaces `verify_publish_gates`, that check
still accepts the 32-item-era passes of 1.7B/4B/8B. Once 339-05 changes the card bytes, those sizes
read `Diverged`, and a plain `vox mens hub sync --push` would re-publish their weights as `passed`
under a new tag. The card-only path closes that window: after it runs, those sizes are `InSync` again,
so a plain `--push` is a no-op for them, and after 338-01 their label changes and the new check
refuses them. 339-10's push step never runs a plain `--push` without `--size <gated-current size>`.

All code is in a NEW file (`hub_cards_push.rs`) plus one CLI flag, so nothing text-conflicts with
338-01/02/06's edits to hub_sync.rs; hub_sync.rs is not edited. Per D3 the upload commit message
and the CLI row table are not card prose: they stay short and in the existing style, and no card
wording lives in this file.

This plan also holds the parity test for the serving identity (checker B1). 339-03 declares
`CURRENT_ADAPTER_SERVING` in vox-populi. The eval writer's `ADAPTER_SERVING` is `pub(crate)` in
vox-ml-cli and belongs to phase 335, so the only place both are visible is a vox-ml-cli test. hub.rs
is the vox-ml-cli file this plan already edits.

Purpose: the v2 cards can reach every published repo without touching weights or tags.
Output: `vox_populi::mens::hub_cards_push`, `vox mens hub sync --cards-only`, the serving parity test.
</objective>
