**Duplicate-sentence rule (written on the page under "How the cards are made"; 339-09 implements it).**
The set is every card rendered for one ladder: one model card per size, and the index. From each card, drop the YAML
frontmatter, every fenced code block, and the footer line (the one exception the spec allows). Each
heading, list item and table row is its own unit; consecutive plain lines of one paragraph join into
one unit. Split each unit after `.`, `?` or `!` when a space or the end of the unit follows. Normalize
each sentence: keep link text and drop the URL, remove inline-code backticks and emphasis markers,
turn table pipes into spaces, lowercase, collapse whitespace, drop trailing punctuation. A word is a
whitespace-separated token holding at least one letter or digit. Any sentence of four or more words
that occurs twice in the set (on two cards, or twice on one card) fails the build. So every sentence
a template repeats for each size names that size (record numbers alone can coincide), and the
per-size blurbs in `mens/config/hub-cards.yaml` differ sentence by sentence. Section headings on
model cards are at most three words, so they never count; the title names the size.

**Verdict list (written on the page under "Examples on the cards"; the contract for 339-03's
`Verdict` enum and 339-07's examples template, which must use exactly these six phrases).**

| `Verdict` variant (339-03) | Phrase on a card | Meaning (from stored check fields only) |
|---|---|---|
| `Passes` | `passes` | `pass` is true: it parses, type-checks and is not a stub |
| `Empty` | `no code` | the output held no code to check |
| `ParseErrors(n)` | `does not parse` | `parse_ok` is false; the stored error count follows when recorded |
| `TypeErrors(n)` | `type errors` | it parses but `typecheck_ok` is false; the `diag_errors` count follows when recorded |
| `Stub` | `stub` | it compiles but the anti-stub check failed |
| `Rejected(check)` | `rejected by` | it compiles, is not a stub, and the named stored check is false |

**Serving-path rule (written on the page under "Held-out pass rate" and "Examples on the cards").**
Adapter outputs and the adapter's held-out score count as card evidence only when the adapter
checkpoint header's `inputs.model.adapter_serving` names the current serving path (the
`ADAPTER_SERVING` constant in crates/vox-ml-cli/src/commands/mens/item_checkpoint.rs; cite the
constant, do not copy its value onto the page). Earlier generations served NF4(W+ΔW), folding the
adapter delta in before quantizing and losing most of it, so their outputs are not shown and the card
says why in one sentence. Base outputs are unaffected.
