<objective>
One pure selector, built on pick_base, chooses the largest measured qwen3_code QLoRA size that fits an injected free-memory reading, and a second reading either keeps that size or steps down. Explicit size names are refused instead of shrunk.

Purpose: SIZE-02 core. Later plans only call this API from training, chat, and the GUI host. This plan does not probe a GPU, download weights, train, or touch mesh routing.
Output: The picker, the pre-load revision, the explicit-size check, and the free-memory adapter in spoke_base_resolver.rs.

Locked decisions (318-CONTEXT.md, do not reopen):
- D-01: 1.7B and 4B cannot win. floor_measured false stays ineligible. Do not invent a floor_mb.
- D-02: CUDA free memory is memory.free from query_nvidia_smi_vram. Metal free memory is monitor_metal memory_free_mb (recommended working set minus current allocated size). Do not use the wired-limit sysctl, the helper that copies the Metal budget into both total and free, or the vm_stat estimate.
- D-03: Eligible rows are measured qwen3_code QLoRA rows. The largest floor_mb that fits wins.
- D-04: Nothing fits, or an unreadable reading, fails closed. No fallthrough to a smaller unmeasured rung and no retired 8B directory fallback.
- D-05: Extend pick_base. Do not write a second max-by-floor loop.
- D-10: Automatic picks step down on the second reading to the next smaller measured qwen3_code QLoRA row that fits. The result names the original size, the loaded size, and the free-memory reading. If the smallest measured row no longer fits, return an error.
- D-11: Explicit spellings already accepted by resolve_qwen3_size are not stepped down. Unmeasured, or a floor above the reading, is an error on the first check and on the second reading.
- D-12: Tests inject readings. No GPU probe, no Hugging Face, no weight download, no training run, no mesh heartbeat.
</objective>
