- `is_oom` (`vox-plugin-mens-candle-core/src/candle_qlora_train/oom.rs:27-31`) treats an error as memory when its lowercase text contains `out of memory`, `greater than the maximum allowed buffer size` or `mtlcommandbuffererror(8)`; the training loop then writes `oom_step_<n>.safetensors`, an `oom` telemetry row with `observed_bytes` (Plan 02 fills it from the peak sampler) and bails with `out of memory at step ...`. The Plan 03 writer records that as `not_trained` with the error text and the telemetry peak.
- The run cap (Plan 02) stops only at an optimizer boundary after at least one optimizer step, so a probe always measures at least one full step. Time spent downloading and loading the base is outside the cap.
- Base sizes on disk (bf16 safetensors, approximate GB): 1.7B 4, 4B 9, 8B 17, 14B 30, 32B 66. 0.6B and (after S2) 1.7B are cached.
- macOS may kill a process under memory pressure (exit 137, no record written); GNU `timeout --signal=INT` lets the trainer pause cleanly first.

**Probe procedure P(S)** (S is one of 1.7B 4B 8B 14B 32B; run from `$R`):
1. Skip S when `$E/ladder.json` already has an entry for it (resuming after an interruption).
2. Live reading: `$ML mens train $COMMON --model Qwen3-$S --output-dir mens/runs/320-probe-$S --plan-only --json > $E/s3-plan-$S.json 2> $E/s3-plan-$S.err`. When it refuses with `refusing rather than shrinking`, set `FORCE=1` and re-run the same command with `VOX_MENS_FORCE_TRAIN=1` in its environment (D-06: the measurement decides). Any other refusal stops the plan with that message.
3. Disk: when `.base_cached` is false, `df -g "$HOME" | awk 'NR==2{print $4}'` must be at least the size's GB plus 20; otherwise stop the plan and report the shortfall (P-320-12).
4. Probe, in the background: `env ${FORCE:+VOX_MENS_FORCE_TRAIN=1} timeout --signal=INT --kill-after=600s 10800s $ML mens train $COMMON --model Qwen3-$S --output-dir mens/runs/320-probe-$S --max-runtime-secs 120 --force-restart > /tmp/320-06-probe-$S.log 2>&1; echo $? > $E/s3-probe-$S.exit`. Read the log when notified; the timeout is a safety net for download and load, not the run cap.
5. Evidence: `tail -200` of the log to `$E/s3-probe-$S-log.txt`; copy `mens/runs/320-probe-$S/train-record.json` to `$E/s3-record-$S.json`. When the process ended without a record (killed), write `$E/s3-record-$S.json` with `jq -n` in the same schema: `schema` `vox_mens_train_record_v1`, `status` `not_trained`, `reason` `process ended without a record (exit <code>)`, `size`, `pin`, `peak_mb` as the ceiling in MiB of the largest `payload.peak_metal_allocated_bytes` or `payload.observed_bytes` in this run's `telemetry.jsonl` (null when there is none), `peak_source` `telemetry` or null, `recorded_at`.
6. Verdict: `fits` when the record's status is `trained` or `capped`, `peak_mb > 0` and `peak_mb <= free_mb` from step 2. `does_not_fit` when the status is `not_trained` and the reason matches one of the three `is_oom` phrases or the no-record text from step 5, or when a trained or capped run's `peak_mb` exceeds `free_mb`. Anything else (download failure, a code error) stops the plan as `Stage S3: FAIL — <reason>`: fix the code first (D-05). For a size that failed before its first step with no peak, set `lower_bound_mb` to `free_mb` (it needed more than the live budget).
7. Projection (fits only): from this run's last `step` row, `planned = optimizer_step / progress_fraction` and `projected_full_secs = planned / steps_per_sec_ema`; when the EMA is null use `train_wall_secs / optimizer_steps` for the rate. Null when neither exists.
8. Append to `$E/ladder.json` `sizes`: `{size, pin, preset, verdict, forced, free_mb, free_source, peak_mb, peak_source, lower_bound_mb, record_status, optimizer_steps, planned_optimizer_steps, projected_full_secs, probe_dir, reason}`.
9. On `does_not_fit`: append every larger size with `verdict` `not_attempted` and `reason` `above non-fitting <S> (D-06)` (pin and preset from S1's plan JSON, the rest null), and stop climbing.
