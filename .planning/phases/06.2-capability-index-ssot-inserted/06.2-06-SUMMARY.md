# Phase 06.2 Plan 06: Frontmatter Capability Claims Summary

**Docs pages claim capabilities with a `capabilities:` frontmatter key; the generator validates the ids, appends claim doc links, and emits opt-in `doc.<path>` rows, while the lint, Starlight schema and governance doc accept and explain the key.**

## Accomplishments

- `docs_claims.rs`: `split_frontmatter` (closes only on a line that is exactly `---`, CRLF-safe), `PageMeta`, `parse_meta` (invalid YAML or a non-list `capabilities` gives `None`, the page is skipped; the doc lint owns that error). Carries the `vox:defactored-from vox-doc-pipeline` marker.
- `inputs.rs`: `load_doc_pages` walks `docs/src` in file-name order, pruning `docs/src/archive/` via `filter_entry` before any read, with capped reads; keeps only claiming pages and the five pinned targets.
- `nodes.rs`: `apply_doc_claims` validates every claimed id against row ids (error names the page and the id), appends `DocLink{path, origin: claim}` after the default, and emits `doc.<path>` rows (domain `docs`, refs = claimed ids sorted, owner/coverage/gui null, origin `claim` or `pinned`). Ids are only compared with row ids, never used as paths.
- `secrets-ssot.md` claims `cli.secrets` and `crate.vox-secrets`. Regenerated index has 6 doc rows (5 pinned plus secrets-ssot, 3 `claim` origins, 5 `pinned`). `vox explain secrets` shows `Docs: docs/src/reference/secrets-ssot.md (claim)`.
- Lint: two regression tests (flow and block list) pinning that `capabilities:` raises no error; only the `#[cfg(test)]` module changed. Starlight: `capabilities: z.array(z.string()).optional()`. Governance: "Capability claims" section plus a commented template line.
