# Phase 06.2 Plan 04: vox explain / vox features Summary

**`vox explain <thing>` and `vox features [--domain d]` plus the MCP tools `vox_capability_explain` / `vox_capability_features`, all answering from the embedded capability index through thin wrappers over vox-capability-registry, with the registries produced by operations-sync.**

## Accomplishments

- Catalog ops `capability.explain` and `capability.features` (cli paths `[explain]`, `[features]`; mcp names `vox_capability_*`, `http_read_role_eligible: false`, read_only). `owner_crate: vox-capability-registry` makes their index rows read `crate vox-capability-registry, layer 2, rule override`; `owner-ratchet.v1.json` is byte-unchanged.
- `Cli::Explain { query: Vec<String> }` (so `vox explain secrets get` needs no quoting) and `Cli::Features { domain }`; both are in the no-reward meta arm.
- `capability_cmds::{explain_output, features_output}` (CLI) and `capability_tools::{explain, features}` (MCP) share `resolve`, `explain_rows`, `rows_in_domain`, `render_*` and the new `domain_counts_json`, so CLI `--json` and MCP `data` are the same value.
- MCP schemas: `query` 1-256, `domain` 1-64 chars, `additionalProperties:false`; args structs use `deny_unknown_fields`.
- Real output: `vox features --domain secrets` lists `vox secrets get` etc. with owner/layer/docs; `vox features` lists 17 domains with counts; `vox explain secrets` prints Equivalents/Location/Status/Related.

## Deviations from Plan

**1. [Rule 1 - Bug] Per-command `--json` would collide with the global `--json`.**
- **Found during:** Task 1 (before first build).
- **Issue:** `GlobalOpts.json` is `#[arg(long, global = true)]`; adding `json: bool` to `Explain`/`Features` makes clap's duplicate-argument debug assertion fire at startup.
- **Fix:** dropped the local field; dispatch passes `global.json`. `vox explain x --json` and `vox --json explain x` both work (verified).
- **Files:** crates/vox-cli/src/lib.rs, cli_dispatch/mod.rs. **Commit:** 0e983f9dd.
