**Core Invariants:**
1. **100% Offline/Standalone Sovereignty:** `vox`, `vox-gui`, `voxlang.org`, and `vox-orchestrator-d` must never require connectivity to `vox-ops`; all community intelligence and leaderboard snapshots degrade gracefully offline.

3. **End-to-End Strong Typing & Database Shape Auditing:** Every telemetry event, local `VoxDb` row (`TypedResearchMetricRow` / `VoxDb::audit_research_metric_shapes`), and PostgreSQL table/view in `vox_ops` enforces strongly-typed enums/newtypes (`DurationBucket`, `TokenBucket`, `SaltedHashHex`, PostgreSQL `CHECK` constraints, `sqlx::FromRow`) with zero untyped JSON drift.
4. **Multi-Surface Model Router Parity, 3-Way Ludus SoC & Zero-Cheating Leaderboard (`D29`, `D31`):** `vox-orchestrator::models` is verified across CLI, daemon (`vox-orchestrator-d`), MCP (`vox-orchestrator-mcp`), and GUI (`vox-gui`), while `vox-gamify` is split into: (1) core `agent_telemetry` in `vox-db`, (2) multi-user competitive Ludus (`collegium`, `arena`, `leaderboards`, `disputes`, GitHub sync) + `ludus_community.verified_contributions` (`BLAKE3` hash chain + `Ed25519`-signed `VerifiedLeaderboardSnapshotV1`) in `vox-ops` Postgres, and (3) solo offline quests/companions/FSRS in local `vox-gamify`, rendered via v0 / Claude Design surfaces on `voxlang.org` (`VoxLeaderboardArena.astro`) and `vox-gui` (`LeaderboardArenaPanel.tsx`).
