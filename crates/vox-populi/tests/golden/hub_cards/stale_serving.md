1.7B is [trained](https://voxlang.org/reference/mens-models/#state-legend), its spoke is [vox-lang](https://voxlang.org/reference/mens-models/#hub-and-spoke) and its gate is [needs re-gate](https://voxlang.org/reference/mens-models/#state-legend): it passed the retired 32-item collateral rule and the 128-item paired re-run for 1.7B has not been done.

## Why this size

A small rung for ordinary laptops and desktop GPUs with a modest memory budget. It handles single-file generation and one-pass fixes for compiler diagnostics. Drop to the smallest size when latency is the limit, or climb to the middle size when an answer needs reasoning across functions. The measured training peak for 1.7B is 27007 MiB (`peak_source`: run_summary), and no serving memory figure has been measured for it.

## Use it

The 1.7B adapter sits on the base pin `Qwen/Qwen3-1.7B@70d244cc86ccca08cf5af4e1e306ecf908b1ad5e`, and this command downloads it after checking the BLAKE3 hash of every file in `hf_sync_manifest.json`.

```bash
vox mens hub pull --size 1.7B --namespace ns --allow-ungated
```

`vox mens serve` loads the 1.7B adapter only from a run directory that holds a passing collateral report and a passing `gate_receipt.json`, so the pull needs `--allow-ungated` and no serving example is given.

The docs page explains [why the 1.7B adapter cannot be loaded with transformers or PEFT](https://voxlang.org/reference/mens-models/#why-peft-cannot-load-the-adapters).
